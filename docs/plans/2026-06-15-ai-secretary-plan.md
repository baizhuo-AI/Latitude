> 已纳入 4 个 agent 对照真实代码的评审:(1) 改为**竖切验证**排法,先用单引擎跑通最小闭环验证"秘书味",再横向铺开;(2)「懂你的状态」**纳入本次改造**(置于 Phase 3,带冷启动护栏);(3) 纳入一批代码层硬约束(适配器无状态、调度基建抽成地基、纯函数可测、i18n、双实现 schema 对齐等)。

**Goal:** 把 Daybreak 内置助手升级为有人设、有跨对话记忆、会主动的 AI 秘书,且大脑可在 Claude Code / Codex / 纯 API 间切换;先单引擎验证效果,再多引擎发布。

**Architecture:** 秘书核心(人设 / 记忆 / 调度)由 app 自持;大脑是无状态的可换推理引擎,每轮由 app 注入〔人设 + 记忆 + 历史〕;工具与数据走现有 MCP server(纯 API 路径由 app 自派发)。

**Tech Stack:** Tauri 2(Rust)+ React 18 + Zustand + Tailwind + SQLite(`@tauri-apps/plugin-sql`)+ i18next + 现有 MCP server(:42800)。

## 横切约束(贯穿所有 Task,只写一次)

- **C1 适配器无状态**:任何大脑调用都不依赖引擎自身的 session 记忆,**放弃 CLI 的 `--resume`**;每轮由 app 把〔人设 + 记忆 + 压缩历史〕完整注入。会话归属于 app 的 `messages` 表。(评审最高风险项)
- **C2 时间/状态注入的纯函数**:闸门、心跳、冷却、预算、负荷判断、记忆过期/冲突,全部实现为 `f(输入, now)` 的纯函数,**函数体内不读 `Date.now()`**;调度器只负责 tick 取时间后调纯函数。范式照搬现有 `src/lib/reminder.ts` 的 `shouldFireReminder`。
- **C3 裸调用入口**:提供 `generateOnce(systemPrompt, messages)`——不绑会话、不写库、不记 usage,供"试一句"和主动消息合成使用(现有 LLM 调用都耦合了落库,必须新开口子)。
- **C4 单一 owner + 真相源**:主动调度与记忆写入只在单一 owner 窗口跑;owner 用 localStorage 抢锁(owner id + 心跳时间戳,过期可抢占),发送前 compare-and-set;所有判断读 DB/localStorage,**不读 Zustand 内存态**。
- **C5 i18n**:所有新 UI 文案走 i18next;**主动消息 / 简报 / 人设注入按当前 `lang` 设置生成**(简报话术要跟随语言)。
- **C6 错误降级**:大脑调用失败(超时/限流/key 失效)→ 静默重试 N 次,仍失败则不打扰用户、仅写日志;主动场景宁可不发,不报错弹窗。
- **C7 设置默认值**:每个新设置项的出厂默认值必须进 `src/lib/settings.ts` 的 `defaults()`;主动姿态默认"温和"。
- **C8 测试就近放置**:测试文件与源码同目录(项目现有约定,如 `reminder.test.ts`),不另起 `tests/` 目录。

## Phase 0 — 最小地基(只够支撑竖切)

**目标:** 把"无状态调用 + 调度基建 + 测试夹具"这三块地基铺好,刚好够 Phase 1 用,不预先造多引擎抽象。

### Task 0.1 调度基建(抽成地基,记忆与主动共用)
- **建:** `src/lib/secretary/scheduler.ts`(单一 owner 的 tick 循环,扩自 `reminder.ts` 模式)
- **做什么:** 一个 owner 窗口跑 tick;对外提供"注册定时任务/事件回调"的入口;owner 抢锁(C4),**接管判定做成纯函数 `shouldTakeOver(lockState, now)`(C2)**。**记忆的日终扫描和主动的心跳都挂在它上面**(修复评审发现的倒序依赖)。
- **依赖:** 无
- **验收:** 多窗口同开时 tick 只在一个 owner 跑;关掉非 owner 窗口不影响;owner 退出后另一窗口能在超时后接管(确定性测试,时间注入)。

### Task 0.2 无状态单引擎 + 裸调用
- **改:** `src/lib/llm/index.ts`、`src/lib/llm/deepseek.ts`、`src/lib/chatStore.ts`
- **做什么:** (a) 先选**单个强的、支持工具的模型**接入(建议 API 路径,如 DeepSeek V4 / Anthropic API;CLI 留到 Phase 4)——顺手解决 chat 写死 `reasoner`、工具/推理互斥的存量硬伤;(b) 改成无状态:每轮注入完整上下文,不 resume(C1);(c) 加 `generateOnce`(C3)。
- **依赖:** 无
- **验收:** 多轮对话里人设/上下文不丢(对比首轮,**断言第二轮 system prompt 仍在、不走 resume 分支**);`generateOnce` 能不写库地返回一段输出;目标模型能在单次调用里同时用工具 + 合理推理;**Phase 1–3 所有大脑调用只经此处暴露的两个入口(`generateOnce` 裸调 + 带会话的 turn 调用),不直接调 provider**(把 Phase 4 抽接口的重构面钉成单点)。

### Task 0.3 假引擎测试夹具
- **建:** `src/lib/engine/fakeEngine.ts`(可按脚本返回指定文本/工具调用序列,可断言收到的 system prompt 与工具集)
- **做什么:** 一个可编程的 fake 大脑,作为后续所有确定性测试的取数源(项目现在零 LLM mock)。
- **依赖:** 0.2
- **验收:** 能用它给 `chatAgentCall` 写特征化测试(断言工具调用轮次上限、收到 tool 结果后回灌再请求等控制流),锁住"行为不变"基线。

## Phase 1 — 竖切 MVP 闭环(验证"秘书味")★ 关键里程碑

**目标:** 单引擎下,早上收到一条**有人设、续接昨天**的简报。**一周内验证"这玩意儿到底像不像个人"。**
**依赖:** Phase 0

### Task 1.1 人设模块 + 注入
- **建:** `src/lib/persona/personaSpec.ts` **改:** buildChatSystemPrompt
- **做什么:** 结构化人设字段(名字/基调/称呼/关系/习惯雷区/自由补充)+ 锁死的"反机械"核心段;合成系统提示词,每轮 + 每条主动消息注入。**核心段永远拼在用户人设段之后**(后注入权重更高,天然压制冲突,不做语义检测)。内置 3 预设(资深幕僚/机灵搭档/温和陪伴),默认资深幕僚。
- **依赖:** 0.2、C5
- **验收:** 改人设字段,输出腔调随之变;故意填"高冷别主动",它仍会简报、仍会主动(断言核心段恒在合成 prompt 里、用户字段覆盖不掉它——纯字符串测试)。

### Task 1.2 人设框 + 试一句
- **建:** `src/components/persona/PersonaPanel.tsx`
- **做什么:** 脚手架框(预设 chips + 字段 + 习惯雷区 + 自由补充);"试一句"用人设草稿经 `generateOnce` 生成样例简报+催办,就地展示,不写库;加轻量节流;未配 key/模型时给引导而非空结果。
- **依赖:** 1.1、0.2(generateOnce)
- **验收:** 能填写保存;试一句腔调随字段变;连点不会无限调用;无 key 时有引导。

### Task 1.3 最小记忆:每日纪要(只写 + 只注入)
- **改:** `src/lib/db.ts`(新增 `daily_digest` 表:date 唯一、summary、created_at,按现有迁移模式)**建:** `src/lib/secretary/dailyScan.ts`
- **做什么:** 日终(挂 0.1 调度)让大脑读当天对话+任务变动,写一条纪要;每轮对话 + 主动扫描注入近 N 天纪要。**本阶段先不做 remember 工具、不做面板、不做卫生**(留 Phase 2)。
- **依赖:** 0.1、0.2、1.1
- **验收:** 跑一次后当天纪要存在;新对话能引用昨日纪要内容(注入层:断言 prompt 含纪要文本——确定性;行为层关键词命中只作"读到没读到"的地板,**"续接得自不自然"这类质量判断归 4.4b 的 rubric/人评,别用关键词假装确定性**)。

### Task 1.4 晨间简报 + 投递(聊天框)
- **建:** `src/lib/secretary/composeProactive.ts`(独立文件,不混进 dailyScan)**改:** `chatStore.ts`、chatbar 组件
- **做什么:** 晨间简报 = 当天第一次心跳(挂 0.1),读〔昨日纪要 + 今日任务库 + 人设〕合成一条,在对话悬浮条里以新助手消息冒出,可直接回复接成对话。
- **依赖:** 0.1、1.1、1.3、C6
- **验收:** 早上出现一条续接昨天的简报且可回复续聊;大脑失败时静默不打扰。

### Task 1.5 冷启动 + 补发(评审新增,影响第一印象/信任)
- **改:** `composeProactive.ts`、启动入口
- **做什么:** (a) 首日无"昨天":用人设自我介绍 + 引导填"关于你" + 用现有日历/任务撑起第一条简报,不冷场;(b) 启动时若发现今天该发的简报漏了(app 没开过),补发并标"补";(c) 漏跑纪要的补跑策略(防续接断链)。**补发判定做成纯函数 `shouldBackfill(lastDigestDate, lastSentDate, now)`(C2),含时间窗:过了晌午 / 用户今天已开过对话,则不误补"早安简报",降级为轻提示或跳过。**
- **依赖:** 1.4
- **验收:** 全新用户首日有像样的第一条;`shouldBackfill` 的跨天/漏跑/晌午边界用确定性用例覆盖(时间注入);手动模拟"早上没开 app"启动后能补发当日简报、且过点不误补。

### Task 1.6 防骚扰底线(gate-lite,验证期也别烦人)
- **建:** `src/lib/secretary/gate.ts`(纯函数,C2)
- **做什么:** 竖切阶段先上最小闸门:静默时段 + 去重 + 默认温和频率。完整预算/冷却/优先级留 Phase 3。
- **依赖:** 0.1
- **验收:** 静默时段不发;同内容不重复发(纯函数确定性用例,时间注入)。

### Task 1.7 主动消息投递日志(给里程碑评估提供客观依据)
- **建:** 轻量表/字段,记录每条主动消息:发了什么、何时、是否被回复或忽略
- **做什么:** 纯本地留痕,**不做降频逻辑**(那是 Phase 3 的 3.5);只为下面的验证检查点提供"这几天发了 N 条、回了几条、忽略几条"的数据,别让最关键的验证靠主观回忆。
- **依赖:** 1.4
- **验收:** 主动消息发出即留痕;里程碑评估时能读出发送/回复/忽略计数。

> **★ 里程碑评估(Phase 1 结束,继续前必做):** 连用几天,**结合 Task 1.7 的投递数据**,判断**晨间简报到底像不像个人、续接昨天有没有打动你**。不够 → 先调人设/纪要质量(可能要换更强的大脑),再往下。够 → 进 Phase 2。这一步就是这套排法的意义:最贵、最不确定的"秘书味"先证伪。

## Phase 2 — 记忆做厚 + 看得见可编辑

**目标:** 从"只会写纪要"到"记得住你这个人、且你能看能改"。
**依赖:** Phase 1

### Task 2.1 记忆事实表 + 双实现工具(schema 对齐)
- **改:** `src/lib/db.ts`(新增 `memory_facts`:id、category、content、source(`told`/`inferred`)、durability(`durable`/`transient`)、pinned、created_at、expires_at)、`src/lib/chatTools.ts`(TS 侧 remember/update/forget,供 API 路径)、`src-tauri/src/mcp/`(Rust 侧同名工具,供 CC/Codex 的 MCP 路径)
- **做什么:** 两处实现 remember/update/forget,**字段与枚举逐字对齐**;确保 **TS 建表迁移先于 MCP 工具被调用**(MCP `create_if_missing(false)`,不自己建表)。
- **依赖:** Phase 0
- **验收:** API 路径与 MCP 路径写出的 `memory_facts` 字段/枚举完全一致(同一条 SQL 落库);老用户升级后新表自动建好。

### Task 2.2 全量注入(纪要 + 事实)
- **改:** personaSpec / buildChatSystemPrompt
- **做什么:** 每轮 + 每次主动扫描注入〔近 N 天纪要 + 全部有效事实〕;设注入体积上限,超量截断不报错;inferred 事实以试探语气呈现。
- **依赖:** 2.1、1.3
- **验收:** 注入内容确定性可断言(prompt 含指定纪要/事实);超量截断不抛错、**且 pinned 事实不被截断**。

### Task 2.3 「关于你」面板
- **建:** `src/components/memory/AboutYouPanel.tsx`
- **做什么:** 按 category 分组;每条可改/删/加;`told`/`inferred` 标签区分(学到=橙色提示)。pinned 字段保留,置顶 UI 可后置。
- **依赖:** 2.1、C5
- **验收:** 增删改即时落库并影响下次注入;inferred 明确标记。

### Task 2.4 记忆卫生(规则层确定性 + 语义层人评)
- **改:** dailyScan、注入逻辑
- **做什么:** **规则层(纯函数,必须硬):** `filterActiveFacts(facts, now)` 过期不注入;`resolveConflict(old, new)` 新覆旧或标 conflict。**语义层(大脑):** 日终去重归并、拿不准降级为待确认。周/月压缩留后续。
- **依赖:** 2.1、2.2
- **验收:** transient 过期后不再注入、durable 恒在;同主题冲突新覆旧(规则层确定性用例);语义归并走人评。

## Phase 3 — 主动做全 + 懂状态 + 防骚扰命门

**目标:** 从 gate-lite 升到完整主动引擎,且默认温和、能学会闭嘴。
**依赖:** Phase 1(基础)、Phase 2(记忆)

### Task 3.1 完整触发层
- **改:** `scheduler.ts`、`triggers.ts`
- **做什么:** 心跳(可配间隔)+ 事件(会议将至/ddl 临近/任务卡很久/刚完成),产出候选不直接发。
- **依赖:** 0.1
- **验收:** 各类触发产生候选(纯函数,造数据可测)。

### Task 3.2 完整闸门(确定性地板)
- **改:** `gate.ts`(扩 1.6)
- **做什么:** 预算(每半天上限,跨界重置)+ 静默(工作时段外/开会/专注)+ 冷却 + 去重合并 + 优先级阈值。**纯函数 `gate(candidates, gateState, now)`,入参无任何引擎句柄**(R3 弱模型地板的可证明点)。
- **依赖:** 3.1、C2
- **验收:** 给 50 候选 + 预算 3 → 输出 ≤3;静默时段非急候选全拦;急候选 + 冷却中仍放行(确定性表格用例,边界 ±1 分钟)。

### Task 3.3 懂状态(安全版 + 冷启动护栏)★ 纳入本次改造(按你的决定)
- **建:** `src/lib/secretary/loadSignals.ts`(纯函数 `computeLoad(signals, now)`)
- **做什么:** 从日程密度/完成率/是否加班/推迟次数算负荷与节奏,只调闸门阈值 + 语气,不读心情。**冷启动护栏:信号样本不足或置信度低时,输出"未知"档 → 不据此调整、也不说带状态判断的话**(避免头几天瞎猜翻车)。
- **依赖:** DB 信号源(纯函数,**不依赖 3.2/3.4**;其负荷档输出由 3.2 闸门与 3.4 投递消费——修复 Phase 内"前依赖后")
- **验收:** 满日程→抬阈/更短;空闲→放低;**信号稀疏(新用户头几天)→ 返回"未知",不产生任何状态相关措辞**(确定性用例)。

### Task 3.4 完整投递 + 配置
- **改:** chatStore、chatbar、`plugin-notification`、reminder 弹窗;**建:** `ProactiveSettings.tsx`
- **做什么:** 聊天冒泡 + 可选通知/弹窗(按渠道配置);懒人三档(关/温和/积极)+ 高玩展开;默认温和(C7)。
- **依赖:** 3.2、C4、C5
- **验收:** 主动消息按渠道触发;切档改底层参数;默认值=温和。

### Task 3.5 「别烦我」+ dismiss 降频(R1 命门,评审强调)

- **依赖:** 3.2、3.4
- **验收:** "别烦我"后静默到期;模拟连续 dismiss → 频率自动下降(确定性用例)。

### Task 3.6 推荐档位提示(R3)
- **改:** 模型配置 UI

- **验收:** 选低于推荐档的模型出现提示。

## Phase 4 — 多引擎 + 发布打磨

**目标:** 从单引擎扩到 Claude Code / Codex / API 三选,达到可发布。
**依赖:** Phase 1–3(秘书味已验证)

### Task 4.1 引擎适配器接口(此时才抽象)
- **建:** `src/lib/engine/types.ts`、`apiAdapter.ts`
- **做什么:** 把 Phase 0 的单引擎缝重构成统一接口:输入〔系统提示词+消息+工具+流式回调〕,输出〔文本流/工具调用〕;声明能力位(支持工具?支持推理?支持流式?——抹平 API 非流式 vs CLI 流式、reasoner 互斥)。
- **依赖:** 0.2、0.3
- **验收:** API 适配器走新接口行为不变(用 0.3 夹具回归)。

### Task 4.2 Claude Code 适配器(headless 无状态)
- **改:** `claudeCodeAdapter.ts`、`cli_agent/claude.rs`
- **做什么:** headless 驱动 `claude`,**app 注入人设/上下文、不用 CC 自身项目记忆、放弃 --resume**(C1),工具走已接好的 MCP。
- **依赖:** 4.1
- **验收:** 同一消息,API 与 CC 都正确调一次 MCP 工具;CC 输出体现 app 注入的人设、无 CC 本地项目记忆痕迹。

### Task 4.3 Codex 适配器(真功夫在接 MCP)
- **建:** `codexAdapter.ts` **改:** `cli_agent/codex.rs`、安装引导
- **做什么:** Codex 适配器本身基本是存量(已能 spawn/resume),**真正的活是给 codex 注入/配置 daybreak MCP**(研究 `--config`/`-c` 或安装引导里 `codex mcp add`),否则工具调不到、静默退化成纯聊天。
- **依赖:** 4.1
- **验收:** Codex 能调到 MCP 工具;未配 MCP 时有明确引导而非静默失败。

### Task 4.4 跨引擎一致性回归(行为层进 CI,腔调层人评)
- **建:** 一致性用例(就近放置)
- **做什么:** **4.4a 行为层(进 CI):** 温度=0、固定输入,用 0.3 夹具录制回放,断言工具调用序列/消息条数一致——与措辞无关。**4.4b 腔调层(nightly/手动):** 真三引擎跑固定输入 + 评分 rubric(是否复读/是否拍板/开场是否雷同/称呼对不对/长度克制),人评门禁。
- **依赖:** 4.1、4.2、4.3
- **验收:** 4.4a 可在 CI 稳定重复跑;4.4b 有 rubric 与基线。

### Task 4.5 隐私 + 成本 + 敏感不记
- **改:** 设置、首启引导、心跳
- **做什么:** 云端大脑会看到记忆的显式披露(**提前到记忆注入上线即生效**)+ 仅本地大脑选项 + 敏感不记开关;成本优化(廉价规则预过滤、心跳频率、仅工作时段、省电模式)。
- **依赖:** Phase 2、3
- **验收:** 选云端大脑有披露;开仅本地后记忆不外发;平静日大脑调用次数在上限内。
