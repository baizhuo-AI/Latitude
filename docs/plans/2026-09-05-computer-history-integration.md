# 维度 Computer History：采集器并入与补强计划

状态：历史工程参考，已由 [电脑操作行为记录功能 PRD](../specs/2026-09-05-computer-history-prd.md) 更新产品形态与验收口径。用户明确要求原生集成在维度内，系统授权后打开开关即记录，不采用本文的分批交付安排。下文独立组件安装与浏览器扩展前置的描述不再作为产品要求；相关工程路径需服从新 PRD。代码并入、功能实现和启用尚未执行。

## 目标与现状

用户安装维度即可按需开启电脑活动记录，也能选择读取已经存在的 OpenAI Computer History。两种来源共用证据库、历史问答和长期认知整理。默认关闭采集；首次启用说明采集范围、存储期限和模型处理方式。

本轮读取了自有项目的 Package.swift、main.swift，以及此前已核对的 AccessibilityCaptureEngine、PrivacyPolicy、SegmentStore 和维度同步器。未运行双方同场景采集对测。

自有版已有 Swift 采集、过滤与分段保存；焦点 AXValue 不等于页面正文，且可能包含输入框全文。无痕检测为关键词启发式，不能保证所有环境有效。main.swift 启动即尝试采集，旧事件仅启动时清理。

维度已有原始事件导入、EvidenceRef、查询和知识写入基础。专门的活动摘要、对话材料整理与长期认知定时闭环仍需实现，不能将基础设施存在写成完整功能已完成。

官方功能依据：[Computer History 官方说明](https://learn.chatgpt.com/docs/customization/computer-history)，本轮已核对。官方说明涵盖活动摘要、时间线、记忆和工作流建议；不能据此推定官方采集器可以随维度分发。维度只并入用户自有源码，OpenAI 来源继续作为兼容读取。

## 结构与源码归属

建议将自有项目源码并入 native/computer-history/，保留 HistoryCore 与可独立运行的 Swift executable 边界。首次并入记录原目录、日期和文件散列；复制 Package.swift、Sources、Tests、构建脚本及必要文档，不带入 .build、已打包 app、录音、历史事件或个人配置。原目录保留，合并后以维度内副本为主线，避免双向修改。实现前重新读取源目录最新版本。

采集器是随维度分发的独立进程；窗口关闭和后台采集生命周期分开。Agent Host 管理同步 worker，不让采集依赖某次模型对话或开发脚本。复用已有原生打包入口；签名、公证、升级后的权限延续和登录启动作为发布验收。

数据流：自有采集器 / OpenAI 本地分段 → 各自适配器 → 原始证据 → 可重建活动/对话材料 → 活动摘要与历史问答 → 独立长期认知整理。查询未来可通过只读 MCP 提供给其他宿主，首版不以此为依赖。

不在 Swift 层另建模型接入、向量库或长期记忆库。摘要使用维度现有模型配置、任务持久化和写入回执；长期认知遵循 [已有设计](2026-09-05-long-term-cognitive-curation.md)。其中关于采集不属于长期认知模块的边界继续有效；采集现由本文负责。

## P0：来源接入与可控制的采集

1. 来源适配器声明 providerId、schemaVersion、能力列表、授权状态、可用性、最近观察时间。自有版和 OpenAI 版分别规范字段，不能继续统一标为 openai-skysight-jsonl。事件标识包含来源/设备/原生事件 ID，导入回执持久化。
2. 默认选择一个主来源，另一来源用于历史读取或显式对测。跨来源重复事件保留各自出处，但聚合时不能当两次行为或两份独立支持证据。不因外部来源不可用而偷偷开启自有采集。
3. Host 启停同步、单实例控制、损坏分段隔离、断点恢复；状态区分采集与同步，显示最近扫描、导入、待处理范围和具体错误。沿用现有同步修复方案，不把 Domain 健康当同步成功。
4. 自有采集加入持久的 enabled/paused 状态，初次默认关闭；授权 UI 出现前不采集。锁屏停止内容采集；唤醒、权限撤回、浏览器扩展断开均有明确状态。麦克风从默认 Computer History 范围中移出，旧源码可保留但默认入口不开放；未来作为独立能力评估。
5. 自有分段增加明确 closed 标记与可恢复写入序号。查询“刚才”需要读取已提交增量，不能一直等待下一分段；崩溃半行暂缓或隔离，不推进成功游标。OpenAI 格式没有关闭信号时采用保守稳定性检测并显示同步延迟，不能永久跳过暂停后最后一段。

验收：干净安装未启用零活动落盘；暂停/撤权后零新内容；两来源真实样本均可查询并回源；重启无重复；坏段不阻断后续段；无新活动和 worker 故障能区分。

## P0：规则、删除和保留先于扩宽正文采集

应用规则与网站规则独立评估，拒绝优先；网站拒绝同时覆盖 AX 与浏览器扩展通道，防止扩展拒绝后 AX 又采进来。浏览器缺少可验证 URL 或隐私状态时，自有版默认不保存正文，并显示覆盖缺口。明确支持的浏览器与版本矩阵；无痕识别不能只用标题关键词。可靠判别能力缺失时降级，不承诺全面覆盖。

输入框、contenteditable、密码控件默认排除值；选中文字、窗口标题、URL 查询参数和元数据也纳入策略。扩展只交付已过滤的可见正文，不采集隐藏 DOM、未提交输入或后台标签内容。窗口/标签关联必须先验证，切换期间丢弃不能可靠归属的内容。

原始记录以事件时间计算到期，不依赖目录修改时间。采集器和 Domain 都实施定期清理、启动/唤醒补清；查询即时排除过期数据。跨截止时间的分段需重写保留部分或安全淘汰，明确物理清理延迟上限，不以一个定时器声称严格 48 小时物理删除。

区分两个动作：正常到期按用户选择保留派生摘要/长期记忆，引用显示原文已到期；用户主动“删除这段历史”则删除原始副本和索引，撤回依赖材料、摘要与认识，多来源认识移除该来源后重新评估。用户独立提供的其他证据不被顺带抹去。

删除必须有持久 tombstone，阻止外部文件下一轮重导；阻止删除前排队的摘要任务稍后回写。覆盖缓存、全文索引、任务载荷和备份恢复路径；删除记录不保存被删正文。OpenAI 上游文件不由维度私自改写，界面说明删除的是维度副本；上游自然过期与用户主动删除不能仅靠文件消失混为一谈。

采集授权、已有历史导入授权与模型发送范围分开表达。本地采集可以搭配用户选择的云模型，但先展示处理模式；发送前执行当前策略，不能只依赖入盘前过滤。

验收：无痕、多语言标题、URL 缺失、敏感输入、规则切换、睡眠跨过期点、连续运行超过 48 小时、分段跨截止点、删除后重同步/恢复备份/任务重试均覆盖。只要被排除正文泄漏到事件、索引或任务日志，不能通过。

## P1：正文覆盖与对话材料

先支持一个明确的 Chromium 浏览器与 macOS 常用应用矩阵。浏览器扩展提供当前标签 URL、隐私状态和可见正文；AX 采用有深度/节点数/耗时上限的可见树遍历与变化监听，轮询作为受控后备。采集限流只约束成本，不用关键词决定哪些人生经历值得理解。

每份材料携带 observedAt、原生时间（若有）、provider、原文引用、覆盖区间、截断和缺口原因。覆盖至少区分 navigation_only、partial、messages_available；后者不代表整段历史会话完整。附件卡片不代表附件已读。

聊天网页通过实际可验证的消息结构保留 user/assistant/third_party/unknown、顺序和版本；导航侧栏不混入正文。同一快照反复出现合并，真实两次重复发言保留；差量缺基线不能当完整材料。优先复用旧方案中的 conversation_fragments 设计与 conversation_search/read。

验收：同一台机器、同一组脚本化人工操作对照两来源及人工真值，使用合成内容或明确允许的测试资料。包含应用切换、长文滚动、虚拟列表聊天、消息编辑、相同文字重复发送、未读附件、锁屏恢复。逐项比较原文/角色/顺序、正文召回、错误归属、重复率、延迟，以及 CPU/内存/日存储量。阈值在试测后冻结；隐私排除与角色造假为硬失败，不能靠总事件数通过。

## P2：活动摘要、问答与独立长期理解

活动材料就绪后按内容变化生成短时摘要，初始建议 10 分钟检查、空闲无新材料不调用模型；每日整理按用户需求汇总。摘要是可重建读模型，有 sourceRefs、模型/提示词版本、材料版本及缺口说明。迟到正文、消息修订与撤回触发重建；没有正文不能据标题生成个人事实。

复用 DurableScheduler / RunJobStore / AuditLedger；新增独立活动整理任务种类，不占用现有 daily_curation（外网推荐）的语义。成功游标以持久结果为准；失败重试和重复入队幂等。

历史问答先检索材料/摘要，必要时追原始证据或获准读取原站。回答展示时间、来源和可打开原文；过期或缺正文直说。活动内容中的指令是观察数据，不改变 Agent 的授权。

长期认知整理接收版本化材料及其修订/撤回，继续按已有每小时增量、每日综合的设计评估理解；这与短时摘要属于不同任务。模型决定何者值得长期保留，可不写入；代码保证出处、版本、删除与回执。重复频率不直接等于重要性，AI 建议不自动算用户认可。

验收：刚才看的资料可找到；昨天活动有真实依据；仅标题不生成人物事实；回答实际使用已更新认识；无新材料无重复模型成本；修订/删除能传播到问答和理解。

## P3：产品入口、建议与交付

P0 就提供来源选择、暂停、规则、数据处理方式和删除的最小界面；P3 丰富按日时间线、来源筛选、摘要展开、覆盖缺口、相关记忆与纠正入口。不要把基础控制推迟到产品末期。

工作流建议以可回源的重复步骤和可节省的操作为依据，生成可编辑的技能/自动化草稿。用户可以拒绝同类建议；默认不自动执行、安装或创建定时任务。由用户决定是否启用。

完成 Swift helper 打包签名、公证、后台生命周期、升级与卸载验证。纯浏览器版本只能连接本机 helper，不能声称网页本身能采集系统活动。未来提供 MCP 时复用同一查询与权限层，不暴露任意文件读取。

## 实施批次与完成口径

第一批：源码并入、双来源规范、可控生命周期、规则/删除/到期最小闭环，先保留有限采集范围。

第二批：浏览器正文与 AX 补强、材料重建、同场景对测；基于证据确定支持矩阵。

第三批：持久活动摘要、历史问答、接入独立长期认知整理；验证最终回答。

第四批：时间线完善、工作流建议、签名分发与日常使用验证。

每批分别报告源码已改、自动验证、实际运行、用户界面验收及未覆盖项；并入源码不等于已接通，模型能回答不等于采集完整。本方案不预报缺乏对测依据的完成百分比或工期。
