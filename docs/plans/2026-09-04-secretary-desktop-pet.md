# 秘书桌宠：实现与验收

## 用户操作

- 在原来的形象框中按住秘书拖动，移出后松手变成桌宠；拖回空框松手恢复立绘。轻点打开对话，移动不足 5px 按点击处理。Esc 撤销当次拖动。
- 桌宠独立于主窗口。macOS 版使用透明置顶窗口，透明区域透过点击；浏览器版提供页面内的同一套拖放交互。
- 空框保留“叫回来”；桌宠提供“回到框里”和“隐藏”。菜单栏托盘可以再次显示桌宠或打开主窗口。
- 桌宠对话、主窗口对话和底部输入栏使用同一个会话和草稿。收起窗口不会丢草稿；提交成功才清空已提交的内容。
- 文字为默认输入。语音由用户点击启动，识别后加入可编辑草稿，由用户决定发送。没有后台常开麦克风。
- 提醒先用表情和气泡，气泡可设 10 秒、30 秒、1 分钟、自定义秒数或一直保留；动作时长与气泡时长分别设置，可演一次或循环。悬停、键盘操作时暂停气泡消退。

## 素材

`src/assets/secretary/pet/` 包含 12 个独立动作：拖起、落地、招手、等待、思考、书写、递交、庆祝、困倦、惊讶、歉意、返回。沿用现有秘书的发型、服饰、笔记本和配色。原始 PNG 保留真实 alpha，浅底/深底预览用于检查缩小后辨识度与边缘。

拖动使用拖起/落地/返回；提醒按类型使用招手、等待、惊讶或庆祝；执行中使用思考。其他动作留在素材库，可按后续明确的任务状态扩充。短暂拖放动作不会改变用户设置的提醒计时。

## 文件兼容范围

| 格式 | 当前读取内容 |
| --- | --- |
| TXT / Markdown / CSV | 文字，支持 UTF-8、UTF-16 BOM、GB18030 |
| PDF | 文本层，保留页码；空页、扫描件和密码会明确提示 |
| DOCX | 正文；不宣称读取图片、修订、批注 |
| PNG / JPEG / WebP | macOS Vision 文字识别；不等同于图像语义理解 |

文件拖入后先加入草稿，不自动发送。资料以文件名、读取范围和正文作为附件资料传给原有 Agent。重新加载历史时，聊天气泡仍显示原问题和附件名。原生文件路径必须来自系统文件选择或实际拖放，不能靠前端传一个路径就任意读取本机文件。

## 状态归属

- `src-tauri/src/pet.rs` 持有唯一的原生形态、位置、拖动事务及命中区域。AppKit 记录手势，避免跨 WebView 转交指针以及快速松手的时序问题。稳定形态只在松手或显式召回时改变。
- `BrowserLiveDimensionApp` 持有唯一的会话、运行状态和提醒队列。桌宠、对话和提醒窗口消费快照，把操作交回主窗口；不创建第二个 Agent 执行器。
- `desktop_http.rs` 仅代理本机 43120 / 43121，维持现有 Agent Host / Domain 服务。`NativeDesktopApp` 与浏览器共用产品界面。
- `composer/` 管理共享草稿、附件解析和语音；`pet-notices/` 管理展示时长。气泡收起只结束本次展示，不代表任务完成。
- 旧原生 MCP、日历同步、活动调度保留源码，但新桌宠入口不重复启动这些后台流程。

## 已验证与范围

前端构建与样式检查通过。浏览器实际走通拖出、点开对话、草稿关窗恢复、拖回归位；单元与集成测试覆盖拖动取消、负坐标边界、提醒去重和计时、共享草稿、输入法、附件解析、任务提交。

macOS Speech / Vision 桥接编译通过，Vision 使用生成的测试图片实际识别成功。真人语音和麦克风权限流程仍需在正常应用内试录，不能用编译通过代替实测。

本次实现面向 macOS 桌宠与浏览器页面内模式。开发应用复用已有 Agent / Domain 服务；分发包自动携带并托管两项服务不属于本次已验证范围。
