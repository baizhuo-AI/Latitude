# 单张大桌面、线索定位与星图转场恢复方案

状态：用户已确认第四版预览，单张大桌面、线索定位、旧便签迁移、两套转场和本轮对话上下文已接入产品源码。浏览器已检查实际点击、键盘进入、返回、刷新及窄窗口；完整验证结果见第 9 节。日期：2026-09-08。

本方案依据本轮用户明确的交互方向和当前源码编写。它替代“每条线索派生一张独立桌面”的设计；其他文档中的旧桌面描述在实施时同步更新。

## 1. 已确定的产品关系

始终只有一张可扩展的桌面。桌面上自然形成不同板块，用留白、轻量标题和内容聚集来辨认；板块之间允许交叠和过渡，不增加封闭容器、固定栅格边界或强制分类。

线索板是关系视图和定位入口。点击线索后，来源视图快速离开，中间出现一段高速穿行动画，让短时间的切换产生跨过很长距离的感觉；随后桌面进入、减速稳停，进场前已对准相应板块。用户最新明确要的是中段动画本身制造距离感。穿行由方向性纹理、短拖影和不同速度的图层表现，不依赖延长等待或实际遍历整张桌面的坐标，不把整屏当作方框旋转。

常用区是大桌面上的一个默认落点，不是另一张桌面。星图保留自己的景深与星体汇聚转场，与桌面、线索板的新转场分别管理。

## 2. 核心使用路径

| 用户操作 | 期望结果 |
| --- | --- |
| 首次打开应用 | 展示桌面的常用区，沿用现有主要业务卡片和用户布局 |
| 在线索板点“客户交付” | 线索先有点击反馈；桌面视图快速滑入、减速稳停，进场前已对准客户交付板块 |
| 从桌面返回线索板 | 以反方向的滑动切换恢复线索板原来的位置，并标出刚才进入的线索 |
| 在导航中点“桌面” | 恢复桌面上次的视野；导航按钮只负责切视图 |
| 在线索板点“当前方向” | 返回同一张桌面的常用区，清除之前的板块选择；拖动纸片不触发跳转 |
| 点固定的“回常用区” | 定位到常用区，卡片位置保持原样；在其他视图中也可使用 |
| 点“返回上一位置” | 恢复上一处桌面视野，适用于从总览或线索入口跳转后回看 |
| 在当前板块新建便签 | 便签出现在当前视野中的合适空位；不自动改变原始知识关系 |
| 刷新当前页面 | 恢复当前视图、可用落点和缩放；目标失效时回常用区并说明 |

“首次打开”的默认与“刷新恢复”分开处理。首次使用采用现有桌面位置作为常用区；后续可通过“设为常用区”保存当前落点。返回上一位置只由明确的跳转产生，不为每一帧滚动记录历史。

## 3. 单张桌面怎样组织

### 空间与板块

- 卡片保留稳定身份和桌面坐标。浏览、切视图、定位以及内容刷新都不挪动卡片。
- 板块保存稳定 ID、名称、定位锚点和相关卡片引用；定位范围可由这些卡片的实际位置计算，不以刚性矩形约束卡片。
- 一张卡片可以与多条线索有关；多条线索可以定位到相同内容。板块改名不改变身份和卡片位置。
- 拖动卡片只调整桌面摆放，不凭位置自动认定目标归属或写入认知关系。
- 第一次建立某个板块时，把所需内容放到现有布局附近的空白区域。之后按用户摆放使用，不因重新打开线索而自动重排。
- 没有关联内容的线索可以落到一个轻量标题和空态入口；不补造待办、趋势图或进度。

画布范围同时覆盖卡片与空板块锚点，确保还没有卡片的板块也能定位。视野保存为桌面坐标中的中心点与缩放值，窗口尺寸变化时重新计算可见范围。

### 卡片内容

同一事项保持同一业务身份。常用区的汇总清单与其他板块中的相关清单可以引用同一事项，完成、改名等操作写回同一条记录；不会因为换板块创建另一份待办。

复用现有卡片类型，只在板块确有内容时添加对应卡片。取消每点一条线索就生成“相关线索 / 行动 / 进度 / 节奏 / 提醒”整套派生桌面的做法。视觉上的软分区不要求修改现有数据库分工。

### 导航和手势

固定保留“桌面 / 线索板 / 星图”视图导航、“回常用区”和桌面总览。总览复用现有卡片总览并增加板块入口，首版不增加一套常驻复杂小地图。

桌面空白处拖动、触控板双指移动用于平移；捏合用于缩放；卡片正文的滚动优先留在正文，卡片拖动继续使用现有手柄或明确拖动区域。鼠标用户可用空格加拖动平移，输入框聚焦时空格照常输入。

桌面内的滚动、捏合和边缘惯性不触发换视图。切视图采用显式导航；快捷键仅在没有输入框、弹窗或卡片控件接管时生效。窄窗口仍保留回常用区与总览两个直接入口，不靠不断缩小文字适配。

“整理桌面”默认整理当前板块或当前选中卡片；全桌整理作为单独操作并可撤销，避免一次整理打散所有板块。

## 4. 两套转场

### 线索板 ↔ 桌面：高速穿行、减速稳停

1. 所点线索立即轻微强调。
2. 进入桌面前完成目标定位。桌面进场的第一帧就呈现正确板块，不能先闪出常用区再滚过去。
3. 来源内容快速移出，中间纹理沿同一方向高速掠过，再由目标内容滑入、明显减速至停稳。第四版候选保留总长 820ms：来源在前 24% 约 197ms 内淡出、模糊移走；目标从 36% 约 295ms 起，以 0.84 屏位移、透明和模糊状态进入，一边减速一边清晰，约 72% 时完全显现，最后停稳。不回弹、不晃动、不旋转。
4. 落定后，对应标题或关联卡片柔和强调约 500ms，帮助辨认落点，不给软板块补上围墙。密集文字随各自视图移动，避免长时间叠在一起。

中段沿用纸面与橄榄色风格，通过纸张边缘、短拖影和不同速度的图层制造距离感；近、中、远层速度比例为 1 / 0.57 / 0.26，柔光层为 0.09。纹理动画累计跨过约 6 个虚拟屏高；该距离是视觉参数，不是桌面实际移动的坐标。中段直接衔接两端画面，不增加独立加载遮罩。

第四版候选重点修正两端衔接：移除随场景平移的整块背景，两个常驻背景分别沿用线索板的 7px 点纹理和桌面的 27px 网格，由全局进度换色并保持纹理相位连续。透明 canvas 覆在内容上方，拖影在 4%–24% 渐入、39%–78% 渐隐；真实纸张边缘接上一层短拖影，使界面内容与穿行纹理有重叠衔接。途中改向时保留当前位移、模糊、透明度与背景进度，避免取消动画后闪回。

首版 420ms、1 屏位移呈现相邻两屏切换；第二版 600ms、1.8 屏位移增加了间隔、渐变纹理与光影，但两版都未满足用户所说的中段长距离穿行感。第三版的高速穿行中段已获用户认可，用户进一步指出动画与两端界面的衔接不自然。第四版按上述方式优化后已获用户确认，现已接入产品；星图另按仓库旧版编排恢复。

秘书和导航在切换中保持稳定。返回线索板采用反方向、相同速度节奏的滑动切换，恢复原位置。重复切换不重播整套纸片落下、散开的装饰动画。转场不阻塞后续选择；途中改向时平滑响应，并最终停在用户最后选择的视图。

桌面内部的近距离定位可以短平移；远距离定位使用短过渡直接到达，避免长途滑行。相机动画可被用户拖动或新的定位请求立即打断。

### 进出星图：恢复旧编排

本次找到的可恢复源码基线为 Git `6b8a156ef5aefb9e04d93732c453a1f3da2a2ba7` 中的相关文件。它能证明仓库旧版的效果，尚未经过与用户记忆版本的视觉对照。

恢复的内容：

- 进入时，来源视图缩远，星图夜空背景淡入。
- 北极星先亮，由大到小收成稳定锚点。
- 群星和星尘从视野外错峰汇聚，单向减速落定；按用户后续反馈取消过冲和回弹。北极星持续缩至正常大小，退出星图时目标视图也直接停在正常比例。
- 星标文字与星云随后显现。
- 退出时，群星和星尘向外退散，目标视图通过景深过渡出现。

以旧版约 900ms 的主切换、约 2.8s 的完整星体编排为还原基线；装饰编排不锁住操作，新的视图选择可以随时打断。恢复只针对星图转场，不整文件回滚、不重新带回桌面与线索板的旋转，也不自动恢复旧星尘数量和高成本常驻闪烁。

源码上需一起恢复星体的外推位移变量、错峰参数、进入/退散关键帧和各自持续时间；只复制旧 CSS 会因位移变量缺失、现有 560ms 相位过早结束而失效。继续采用当前绝对叠放的视图结构，直接桌面 ↔ 星图时不让线索板从中间扫过。

隐藏星图停止持续动画；正在退散的星图仍完成离场。系统开启“减少动态效果”时，两套转场都使用简短淡切或直接切换。

## 5. 内容关联与秘书上下文

板块归属使用已有目标 ID、明确关系、用户选择及业务记录的来源引用建立；不依赖“标题刚好与标签相同”。去掉进入目标后按标题二次判断并变淡的旧逻辑。

业务待办的 `sourceNodeIds` 可用来找关联知识，但来源并不天然等于唯一归属。关系明确时复用；跨多个目标时允许多处引用；无法明确归属时保留在常用区并允许用户选择。日程当前返回类型缺少同等来源字段，实施时补齐读取或采用明确的 UI 关联，不能凭标题猜测。

待办完成与真实结果反馈继续是不同状态。板块可以同时展示“已完成待办”和“待回看行动”，不会把一个勾选自动变成目标已被验证。

对话提交时带上当前视图、当前明确选中的板块/线索和必要的卡片或实体引用；这属于本轮界面上下文，不写入用户长期记忆。点击、输入或明确定位优先决定上下文；用户自由平移后不能一直沿用旧板块冒充“这里”，跨区时可使用当前选中内容与可见范围作为参考。界面中的新建、记录和秘书操作要与这个范围一致。

## 7. 旧布局和便签迁移

保留当前根 `layout.id`，现有主桌面原位成为常用区；保留拖动位置、尺寸、隐藏状态与用户内容。

过去派生桌面里的用户便签和呈现改动迁入共同画布的相关板块。不能只复制本机缓存：部分便签的远端记录也绑定旧 `layoutId`。迁移需要保留来源身份及已同步记录 ID，或验证后更新归属；不得重新创建同一条远端记录来“搬家”。

用一次性的旧桌面 ID 与卡片 ID 到新卡片 ID 的映射处理重名。首次迁入板块可整体平移到空白区域，保留板块内部的相对位置和用户尺寸；后续打开不再次迁移或摆放。

同一业务记录复用原实体引用。不同区域里用户单独编辑的便签按独立便签保留，不能因为标题相同而合并。旧标题哈希映射一次后改用稳定板块 ID，改名不会重新生成空间。

迁移可重复执行，旧数据在新状态读回和验证完成前保留。UI profile 的导出、恢复和清空流程同时认识新增的空间状态，避免恢复后出现便签还在、位置和板块丢失。

## 8. 实施顺序与验收

独立交互预览已经过四轮调整并获得用户确认。实现按该效果接入共享的 DimensionPresetApp / DimensionApp / DimensionDeck，浏览器和原生主窗都使用这套视图代码。

已完成三部分：固定根桌面身份与板块相机；旧便签、业务引用及本轮上下文；穿行与星图编排。以下为验收场景，自动化与浏览器证据分开记录，不用单元测试代表原生视觉验收。

必须实际通过的场景：

1. 鼠标单击与键盘都能从线索进入正确板块；拖动线索后不会误打开。
2. 卡片拖到远处后，线索定位、总览定位和回常用区都不改变任何卡片坐标。
3. 连续跨板块、跨视图、刷新和改名后，位置、缩放、内容及关联仍正确。
4. 桌面上的滚动和捏合不会意外切视图；卡片正文仍可正常滚动、编辑。
5. 已完成或隐藏的记录不会因切视图复活；待办勾选不会自动生成结果证据。
6. 从某板块问“整理这里”时，请求有正确的界面范围；返回常用区后不会继续指向旧线索。
7. 桌面 ↔ 线索板快速离场，中间通过纸面纹理、边缘拖影和视差形成高速穿行的距离感，目标出现后明显减速稳停；往返方向对应，不回弹、不旋转，无初始落点闪跳或文字重影；秘书与固定导航保持稳定。桌面进场前已定位到目标板块，中段只表达视图间的距离，不遍历大桌面的真实内容；途中改向最终停在用户最后选择的视图。
8. 星图的北极星、汇聚、星尘、标签、星云和退散可见；动画途中改向最终停在用户最后选择的视图。
9. 旧用户布局与本机/已同步便签迁移后可读，备份恢复后空间关系一致。

自动化重点覆盖坐标不变、对象身份、迁移幂等、上下文与动画中断等真实状态约束；点击、手势、落点、星体编排和可读性通过实际浏览器及原生窗口检查。构建或单元测试通过不代替视觉验收。

## 9. 本次实现与验证记录

- 根 layout.id 和 React 桌面节点始终保持；线索只选择稳定 area.id 和相机落点。自由移动离开板块、总览定位其他卡片或返回常用区会更新当前界面范围。
- 相机保存中心、缩放、常用区及上一位置；定位包含空板块锚点、负坐标和卡片实际尺寸，景深外层缩放也参与换算。滚动/捏合不切视图，正文滚动优先。
- 新板块首次分配避让现有卡片拖动/缩放后的范围，并为宽旧便签组留空间；已有板块不重排。新便签优先寻找当前视野空位，满时在附近放置并定位。新建时的 cardAreaIds 仅为界面引用。
