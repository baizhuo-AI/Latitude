# 长期认知整理：独立核心功能

状态：产品与实现设计，尚未实现或启用。用户于 2026-09-05 明确提出：屏幕事件预处理由另一个 Computer History 复刻窗口负责；长期理解与整理应该是重要、核心、独立的长期定时任务。

2026-09-05 更新：已按用户要求先审计实际知识结构和内容，再形成[知识库治理方案](2026-09-05-knowledge-governance.md)。本文件保留核心目的与上游边界，具体数据现状、治理操作、读写一致性和验收以本机审计记录（不随公开仓库提供）及新方案为准；仍未实施或启用。

## 功能目的

维度定期读新增材料，把它们和过去的了解放在一起，判断对用户的处境、目标、偏好和做事方式是否需要更新。这份理解在用户下次聊天时直接参与回答，使熟悉程度随真实交流与经历增长。

用户不需要每次提问后再等系统从头认识自己。持续理解既包括记住具体事实，也包括发现关系、提出有依据的解释、修正过去的误解；没有新认识时允许不写入。

## 本任务边界

- 输入由上游提供的材料：可读取的对话或活动内容、来源标识、原文位置、时间与版本、说话者及其可靠程度、覆盖缺口。具体接口适配上游实际实现，不在此处另造采集/屏幕预处理协议。
- Computer History 复刻、浏览器正文获取、屏幕去重与对话重建不在本任务实现范围。
- 已有维度直接聊天、用户补充和纠正也可作为输入。
- 来源缺正文或角色不明时记录待补材料；不接管上游补采，也不把标题写成个人事实。其他已可用材料仍继续处理。
- 本功能属于维度自身的持久任务体系，与外网阅读推荐、行动结果回收、周回顾分开；不是 Codex 应用中的提醒或自动化。

## 每轮工作的具体内容

1. 取得自上轮成功处理后新增或改变的材料。按导入/修订时间和稳定来源 ID 跟踪，不仅按发生时间截断，避免漏掉迟到导入的历史对话。
2. 阅读与新材料有关的旧认识及其原始依据。允许模型继续追读上下文、寻找反例或其他情境；不要求每轮固定查询次数或固定人格维度。
3. 由模型判断：这是什么新事实，补充了什么处境或动机，是否改变过去某项理解，是否值得长期保留。具体例子包括发展路径的取舍、用户主动给出的原因、重要纠正、少见但有解释价值的行为；这些不是关键词白名单或必须填满的表格。
4. 作出新增、补充、修订、撤回、暂存或跳过决定。保留旧版本、原始引用、简短更新理由和适用情境。直接陈述、用户转述、AI 建议、系统推测分开。
5. 持久化完成状态与真实写入回执。只有记录了实际结果才标成功；失败后可恢复，不重复增加同一知识。未读完或缺材料的范围保留为待处理/待补，不伪装成已覆盖。

## 两种节奏，属于同一核心功能

首版节奏建议，尚未启用：

- 每小时做一次增量整理，有新材料才启动模型分析。没有新材料时只更新扫描状态。
- 每天做一次综合检查，把近期新增认识与相关长期认识对照，检查重复、矛盾、情境差别以及需要降低把握的判断。综合检查不是固定生成一篇日报。
- 用户明确纠正旧认识时尽快处理，不必等待日级综合。关机错过的周期恢复后合并补处理，不能为每个错过的时段重复生成相同任务。

时间间隔作为产品配置可调整。定时只规定何时检查，不规定模型只能思考几轮或必须产出几条知识。

## 与现有实现的关系

当前 services/agent/src/scheduler/durableScheduler.ts 的 daily_curation 做的是外网阅读推送。本功能使用独立的任务类型与会话标识，例如 cognitive_review；名称在实现时统一，不复用 daily_curation 的含义。

复用 DurableScheduler、RunJobStore、AuditLedger、现有知识读取/写入/修订工具及 Change Set，不另建一套知识数据库。需要补充处理进度记录：来源/材料版本、处理状态、关联 runId、写入回执、待补原因；以及任务类型在持久存储、恢复、调度、状态展示中的完整注册。

沿用当前可追溯 standing grant：系统可以保存可撤销的推测，但必须保持 system_inferred，不能自动升级为用户确认。外部材料内容只作为证据，不作为改变任务或授权的指令。

## 用户实际会看到什么

独立的“长期理解”功能入口，显示最近一次整理、已处理到的材料范围、待补材料和当前理解。避免把普通任务监控字段全部放到日常聊天里。

每项理解能够展开查看依据、适用场景、最近变化，并允许用户纠正。更新列表例如显示“新增了一个目标背景”“修正了对重复提问的解释”，不只显示处理了多少条事件。

通常在后台工作，不每小时推送总结。值得本人核对的重要新判断、与已确认事实冲突的材料，或影响服务的持续失败，才形成适当的提醒或共创内容。用户下一次聊天能直接使用已更新的认识和引用，必要时继续读原文。

## 用本次讨论验收

- 用户说重复提问是在测试产品后，旧的“重复问人格意味着强烈自我标签需求”应被修订或降低把握；日后不能反复用旧解释。
- 如果只看到工作验收，认识应注明工作情境；不能直接推广成用户整体人格。
- 上游提供完整的多线规划讨论后，能根据用户自己的原话理解几条路径的关系、选择与理由；AI 提出的解释不自动算用户认可。
- 假设用户给助手设定沉稳的人设，记录为助手设计要求，不能写成用户本人的性格。
- 没有新证据，连续运行不会持续新增近义观察，也不会每次换一个人格标签。
- 一轮中断后重跑，既不漏材料，也不重复写知识；来源被修订/撤回后，相应旧认识能够重新评估。
- 最终回答确实使用更新后的理解及来源，而不是后台写成功、前台仍引用旧上下文。
