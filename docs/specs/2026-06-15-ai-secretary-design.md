# Daybreak「AI 秘书」改造方案

> ⚠️ **文档状态：historical（已实现，口径可能过期）**
> 本文描述的是 Latitude 早期（Daybreak 时期）的设计与实现，**不是当前产品规范**。
> 当前权威：[产品总纲](2026-08-20-dimension-master-prd.md) · [工程实施计划](../plans/2026-08-20-dimension-implementation-plan.md)。
> 保留原因：其中的实现细节与踩坑记录仍对工程有效。

- 日期:2026-06-15
- 状态:设计稿(待评审)
- 一句话:把 Daybreak 内置的"快速待办助理"升级成一个**有人设、有记忆、会主动**的 AI 秘书,且做成**能发出去给大家用**的产品。

---

## 0. 背景与目标

### 现状
内置 agent 本质是个**快速待办助理**:你开口它才动,能建任务、查日历、把进展同步回飞书表格,系统提示词写得"温和克制专业"。离"秘书"差三层:

- **没记忆**:对话之间是白纸,换个对话就忘了你是谁、上次聊过啥。
- **不主动**:全 app 只有一个默认关着的"记录活动"定时提醒(`reminder.ts`),没有简报、没有主动问候、ddl 临近也不吭声。
- **人设单薄**:有"克制专业"的设定,但没名字、没性格、没自己的说话方式 —— 这是"不够拟人"的根源。

### 目标
升级为 AI 秘书,核心三件事:**晨间简报、主动问候、跨对话记忆**。

"够拟人"拆成四个维度(全要):
1. 有个性人设
2. 会主动关心
3. 说话自然
4. 懂你的状态(**安全版**:只推断负荷,不读心情)

### 关键约束
- **要发出去给大家用**(产品,不是个人工具)→ 大脑要兼容 **Claude Code / Codex / 纯 API** 三种接入。
- **效果优先于速度**。
- 复用现有技术栈:Tauri 2(Rust)+ React + Zustand + SQLite。

## 1. 方案

### 1.1 总体架构:秘书核心 app 自持 + 大脑可插

**核心原则:让它成为秘书的东西(人设、记忆、调度)全部由 app 自己拥有;Claude Code / Codex / API 只是背后那颗可以随时换的推理引擎。**

```
Daybreak 自己拥有的「秘书核心」(换哪个大脑都不变)
  ├ 人设 / 声音          结构化人设模块,每轮注入
  ├ 记忆 +「关于你」面板    app 自存,可看可改
  ├ 主动引擎 / 调度       晨间简报 + 事件触发,app 自己的定时器
  └ 对话 UI(悬浮条)
        │  统一接口:「给你上下文 + 一组工具,你负责推理」
        ▼
  ┌──────────────┬──────────────┬────────────────────┐
  │ Claude Code  │    Codex     │       纯 API         │
  │ (headless)   │ (headless)   │  (app 自己跑 agent 循环)  │
  └──────────────┴──────────────┴────────────────────┘
        └──── MCP server(42800)────┘  ← 工具/数据,CC 和 Codex 都走这条
                  纯 API 路径由 app 自己派发工具
```

**引擎适配器(Engine Adapter)**:一个薄接口 —— "给你一段上下文 + 一组工具,你回我文本或工具调用"。三个实现:
- **API**:app 自己跑 agent 循环(复用现有 DeepSeek 直连路径,扩成可接 DeepSeek V4 / Anthropic / OpenAI)。
- **Claude Code**:headless 驱动本地 `claude`(复用现有 `src-tauri/src/cli_agent/`),通过 MCP 连数据。
- **Codex**:headless 驱动本地 `codex`,同样走 MCP。

**为什么这条架构是被需求逼出来的**:一旦要支持**纯 API**,就没有任何现成 runtime 帮你管记忆和定时 → app 必须自持这两块 → 一旦 app 自持,Claude Code / Codex 就降级成"可换引擎",不需要再挂它们的原生功能。所以"做成 Claude Code 外挂"那条更弱(它连纯 API 都覆盖不了),被这条架构吞掉。

**工具 / 数据层**:现有 MCP server(端口 42800)是唯一天然通用、不用重写的一层 —— CC 和 Codex 都说 MCP;纯 API 路径由 app 自己派发同一组工具。

**模型定位(产品分层)**:
- **默认 = 纯 API(便宜的 DeepSeek V4 key)**:填个 key 就能用,门槛最低 —— 给大众用的地板。
- **Claude Code / Codex = 高玩自带大脑**:已有订阅的人接进来,顶配效果、零边际成本 —— 天花板。
- 设一个"推荐档位"提示,避免用户挂个太弱的模型导致体验崩。

### 1.2 人设与声音

"够不够拟人"九成在**声音**上,不在功能上。

**人设 = 用户自己填的「脚手架框」(不是空白框)。** 空白框对大多数用户是灾难(面对空白不知写啥,随手写句"友好一点"又太虚)。所以给框,但带脚手架:

```
┌─ 你的秘书 · 人设 ──────────────────────────────┐
│ 名字     [ 拂晓 ]                                  │
│ 性格基调  ◉资深幕僚  ○机灵搭档  ○温和陪伴  ○全自定义   │
│    └ "沉稳、有主见、护着你的时间和精力。" [可改]        │
│ 怎么称呼你  [ … ]                                  │
│ 关系设定   ◉右手幕僚  ○平级搭档  ○贴身助理            │
│ 习惯 / 雷区  [+别太正式] [+可以损我] [+我忙时别闲聊] … │
│ 自由补充  [ … ]                                    │
│         [ ▶ 试一句 ]  ← 立刻听它用这套人设说话          │
└────────────────────────────────────────────────────┘
   底层「不复读 / 有主见 / 简洁 / 看分寸」已内置,你只管调性格
```

- **预设 = 三个起手模板**(可继续加):
  - **A 资深幕僚 / 大管家**(沉稳、有主见、护着你)—— 推荐默认。
  - **B 机灵搭档 / 损友**(俏皮、平视、用幽默推你)。
  - **C 温和陪伴 / 教练**(柔、鼓励、陪你往前挪)。
  - 多数用户点一个、微调两下就走,不用从零写。也支持"A 为主掺点 B"。
- **「试一句」是灵魂**:填完立刻让它用这套人设说一句简报 + 一句催办,所见即所得,不满意当场改 —— 把"填框"从碰运气变成能调准。
- **锁死的"反机械"工程层**(不开放给用户改):替你拍板不甩选项 / 不复读不客套 / 开场措辞每次不同 / 会回扣过往(靠记忆层喂)/ 会示弱会表达不确定 / 简洁。用户拨"性格调味",拨不坏"职业素养"。

**一致性**:人设不写死在某个引擎里,而是 app 自持的一段**结构化人设模块**,每一轮、每一条主动消息生成时都注入 —— 换 Claude Code / Codex / API,换聊天 / 简报,出来都是**同一个性格、同一种腔调**。换脑不换魂。

**护栏**:人设只控"怎么说话"这层皮,盖在锁死的核心行为之上(它永远会简报、会帮你、会主动)。用户写出"高冷别主动"也不会真把秘书的活儿关掉,只是换张脸。

### 1.3 记忆层

**边界:记忆层不是再存一份待办。** 任务、目标、日程已在数据库里结构化躺着;记忆层管的是塞不进那些表的、软的、关于"你这个人"的知识,以及"每天发生了什么"。

**三层模型:**

| 层 | 是什么 | 存哪 | 怎么用 |
|---|---|---|---|
| ① 原始对话 | 每句聊天记录 | 已存 SQLite(`conversations` / `messages`) | 留着可搜,**不整篇重读**(贵、噪、爆上下文) |
| ② **每日纪要(情景记忆)** | 当天发生了什么:聊了啥/做了啥/推了啥/你提到的状态/留的尾巴 | 新增存储,一天一条 | "记住每天的对话和任务"**靠读最近几天的纪要** |
| ③ 关于你(语义/耐久) | 长期知识:你是谁、习惯、偏好雷区、重要的人 | 新增存储 + 面板 | 每轮全量注入,长期人格化 |

**关于"怎么记住每天的对话和任务"(② 的核心)**:
- 每天**日终**,大脑写一条当天纪要(搭车在主动引擎的日终扫描上跑)。
- **任务状态**实时查数据库(永远最新);任务的**"故事"**(今天完成 A、B 已第三次推)写进纪要。
- 纪要**会衰减**:最近 N 天逐日保留,更早的压缩成周/月摘要,或提炼成 ③ 的耐久事实。
- 晨间简报读〔昨日纪要 + 今日任务库 + 关于你〕→ 能"续接昨天"。

**写入路径:**
- **主力:`remember` 工具** —— 大脑聊着发现值得长期记的事,自己调工具写(配 `update` / `forget`)。engine-agnostic(CC/Codex 走 MCP,API 由 app 提供同一工具)。
- **兜底:日终扫描** —— 怕弱模型不主动记,app 侧扫一遍"今天有啥值得记的",写纪要 + 抽取耐久事实。
- **用户手动**:面板里直接加。

**读出路径:** v1 **全量注入**(近几天纪要 + 全部耐久事实)——一个好秘书对你的"了解"也就几十到上百条,**不用上向量检索**。大到撑爆上下文了,phase 2 再换按需检索。注入同时喂**反应式对话**和**每次主动扫描**。

**「关于你」面板(看得见可编辑):**
```
┌─ 关于你 · 它记住的 ──────────────────────────┐
│ 你是谁                                         │
│   • 做 AI 产品,管方向和风险,不爱抠细节   [改][删] │
│   • 不喜欢太正式的说话方式             〔你说的〕  │
│ 在忙什么 · 习惯/雷区 · 重要的人 · 偏好  …          │
│                                [ + 手动加一条 ]  │
└──────────────────────────────────────────────┘
 〔你说的〕= 你亲口讲的;〔学到〕= 它推断的,可改可删
```
"你说的 vs 学到"的标记是关键信任设计:它猜的东西会标明是猜的,你一眼看出哪条是脑补、顺手改删,化解"被偷偷建档"的别扭。

**记忆卫生(决定记忆越用越准还是变垃圾堆):**
- **会过期**:"这周很累"是临时的,标"耐久 vs 临时",临时的自动退场。
- **会打架**:先说"别太正式"后说"正式点",新覆旧,拿不准就问。
- **会去重/归并**:同一件事别攒五个版本,日终扫描合并精简。
- **猜的保持试探**:推断来的事语气留余地,不当铁律照干。

### 1.4 主动引擎

**核心:触发了 ≠ 会说。** 中间隔一层"分寸"。现有 `reminder.ts` 是"定时器到点发模板",这是"机械"的根源;秘书像人,是因为它会判断"现在到底要不要说、怎么说"。

```
触发                 闸门(分寸层,app 自管)            大脑              投递
────               ──────────────────────         ───              ───
⏰ 心跳 / 晨间   ┐                                ┌ 带人设+记忆+    ┐  聊天框冒一条
📅 会议快到     ┤   预算够吗? 在静默吗? 刚说过吗?    │ 今日上下文,判断  │ (可选:系统通知/
⏳ ddl 临近     ┼─  优先级过线吗? 几件事合并一条?  ─→│ "现在值不值得说  ┼→ 弹出悬浮条)
🧊 任务卡很久   ┤   今天忙不忙(抬高/放低门槛)      │  + 该怎么说"      │  你回一句,
✅ 刚完成一件   ┘                                └ 攒着的合成一句   ┘  就接成正常对话
```

**三个部件:**

1. **心跳 ——「每隔一段时间问我」的智能版**:工作时段内每隔一个**可配间隔**,大脑瞄一眼全局(记忆 + 今天任务/日程 + 刚才有啥变化 + 你今天忙不忙 + 上次说了啥)→ 决定**说,还是闭嘴**。平静的一天大多数心跳是"闭嘴"。**晨间简报 = 当天第一次心跳**,读昨日纪要做续接。

2. **打断 —— 急事插队**:高优先级事件(会议还有 10 分钟、今天 ddl 还没动、硬冲突)不等下次心跳,立刻发,但仍受静默和最小冷却约束。

3. **闸门 —— 分寸层(全是 app 侧廉价规则,确定性地板)**:
   - **打扰预算**:每半天最多 N 条,5 个触发也不发 5 条。
   - **静默**:工作时段外、开会中、专注时一律不主动。
   - **去重合并**:多件事合成一条说,说过的不复读。
   - **冷却**:刚说完歇一会儿,除非急事。

   关键:**廉价规则先滤噪音,大脑只对幸存的少数候选做判断** —— 背景模型调用很少(控成本),且**就算用户挂弱模型,闸门这层是确定性地板,再弱的脑子也 spam 不起来**。

**「懂你状态」的安全落地**:只看得见的信号(今天日程多满、计划完成几成、是不是加班、某任务被推几次)→ 合成"今天大概什么节奏"(忙/正常/闲、有势头/卡壳)→ 只做两件事:**调闸门门槛**(忙→只放急事、说短)和**调语气**(告诉大脑"他今天很满,简短别闲聊")。**推断的是负荷,不是心情**;心情那种等你自己说了再记。

**投递**:默认**在聊天框里冒一条**(悬浮条给轻提示),可选叠加系统通知 / 弹出悬浮窗(复用现有通知与 reminder 弹窗能力)。**主动消息是个话头,不是死通知** —— 你直接回它就无缝接进正常对话(同一个脑子、人设、记忆)。

**配置(还是"脚手架"哲学)**:懒人三档 **关 / 温和 / 积极**(一键设好节奏+预算+触发项),下面给高玩展开(心跳频率、晨报时间、静默时段、打扰预算、各类事件开关、渠道)。**默认出厂"温和"** —— 新秘书第一印象绝不能是个话痨,让用户往上调,而不是一上来就唠叨。

---

### 1.5 三块咬合成一个环(不是三个外挂)

- **记忆 → 人设**:让它"回扣过往";phase 2 还能让"你总嫌它正式"反过来把人设调软。
- **记忆 → 主动**:心跳读记忆决定说什么,日终写纪要/提炼事实。
- **主动 ⇄ 记忆 共用同一个心跳/日终扫描**:一套定时基建,干三件事(判断要不要开口 + 写纪要 + 记忆卫生)。

它们在 app 层互相加强,与用哪个大脑无关 —— 这是"秘书核心 app 自持"架构的真正回报。

## 2. 风险点

> 按"会不会真发生 × 发生了多严重"排序,最高在前。

**R1 主动消息变骚扰**(类型:产品)
- 触发条件:闸门阈值/预算没调好,或默认就激进。
- 影响:用户被烦,直接关掉主动甚至卸载 —— 这是整个秘书卖点的命门。
- 缓解:出厂默认"温和";心跳带判断(平静日沉默);预算+静默+冷却三重闸;"别烦我"快捷键;从用户忽略/dismiss 行为学习自动降频。

**R2 隐私与信任 / 云端大脑看到记忆**(类型:产品)
- 触发条件:记忆在给你建档,且用户选了云端 API 大脑,记忆随 prompt 外发给模型方。
- 影响:用户觉得被监视或数据外泄,信任崩;对要发出去的产品是口碑 + 合规风险。
- 缓解:看得见可编辑面板;记忆**默认只存本地**("你的记忆不出本机"是强信任牌);**如实披露**"云端大脑会看到你的记忆";提供"敏感信息不记 / 仅本地大脑"选项。

**R3 效果随大脑浮动,弱模型体验差**(类型:产品/实现)
- 触发条件:用户挂了个便宜/弱 API 模型。
- 影响:秘书显笨(判断差、对话生硬),口碑两极。
- 缓解:设"推荐档位"门槛与提示;闸门等确定性逻辑保下限;关键时刻(简报/主动判断)可强制走更强模型。

**R4 记忆腐烂**(类型:实现)
- 触发条件:不做卫生,记忆越积越多/旧/错。
- 影响:秘书越用越蠢,回扣错误信息,比没记忆更糟。
- 缓解:耐久 vs 临时 + 自动过期;新覆旧冲突解决;日终去重归并;猜的保持试探 + 面板一键纠正。

**R5 多引擎适配工程量与一致性**(类型:实现/项目)
- 触发条件:要同时抹平 API / CC / Codex 三种输出、工具调用、思考模式。
- 影响:工期拉长;某引擎下行为跑偏、人设腔调不一致。
- 缓解:先做 **API + Claude Code 两条**,Codex 随后;统一适配器接口;一致性回归测试(同人设同输入跨引擎对比)。

**R6 挑错时机打断心流**(类型:体验)
- 触发条件:专注/会议中被非急事打断。
- 影响:适得其反,觉得它不懂事,拟人感崩。
- 缓解:专注/会议检测进静默;冷却;预算;"懂状态"在忙时抬高门槛。

**R7 成本 / 后台常转**(类型:实现/项目)
- 触发条件:心跳频繁 + 云端大脑按量计费,乘以用户规模。
- 影响:token 成本失控。
- 缓解:廉价规则预过滤(大脑少跑);心跳频率可配;只在工作时段跑;CC/Codex 走订阅;省电模式。

**R8 app 没开就没主动**(类型:实现)
- 触发条件:用户关了 app 或只留悬浮条,调度不在跑。
- 影响:晨间简报/提醒不触发,秘书"失约"。
- 缓解:调度跑在单一常驻进程/窗口(注意现有**多窗口 store 隔离**,主动逻辑须读 DB/localStorage 真相源,不读内存态,且只在单一窗口跑以防重复发送);v1 接受"app 开着";后台常驻服务列为 phase 2。

> 次级风险(暂记不展开):人设与职责打架(已由"锁死核心行为"护栏覆盖);"懂状态"误判(已由"只推断负荷不读心情"降级覆盖)。

## 3. 方法(实施路径)

> 颗粒度到"做哪几件事、先后、依赖、怎么验收",不到函数级。

**Phase 0 —— 地基:引擎适配器 + 人设注入管线**
- 做:把现有 `cli_agent` + DeepSeek 直连收敛成**统一引擎适配器接口**,先支持 **API + Claude Code** 两条;搭好 app 自持的"结构化人设模块"和注入管线。
- 依赖:现有 MCP server、cli_agent。
- 验收:同一段人设,在 API 和 Claude Code 两个大脑下,输出同一种腔调;工具调用都能通过 MCP 跑通。

**Phase 1 —— 人设框 + 试一句**
- 做:人设配置 UI(预设 + 结构字段 + 自由补充 + **试一句**预览);人设 spec 注入每轮对话。
- 依赖:Phase 0 注入管线。
- 验收:用户能填框、点"试一句"听到对应声音、换大脑腔调不变;锁死的反机械规则生效。

**Phase 2 —— 记忆层**
- 做:三层落地(原始已存 / **每日纪要** / **关于你**);`remember` 工具 + 日终扫描(写纪要 + 抽取事实 + 卫生);「关于你」面板(看/改/删/钉,标"你说的 vs 学到");全量注入。
- 依赖:Phase 0(注入)、日终扫描基建(与 Phase 3 共用)。
- 验收:跨对话、跨天能回扣("昨天你说要做 X");面板可编辑;临时记忆会过期;冲突能解决。

**Phase 3 —— 主动引擎**
- 做:触发(心跳 + 事件)→ 闸门(预算/静默/冷却/去重)→ 大脑合成 → 投递(聊天 + 可选通知/弹窗);"懂状态"调制;配置三档;默认温和。扩自现有 `reminder.ts`。
- 依赖:Phase 1(人设)、Phase 2(记忆/纪要)。
- 验收:晨间简报带昨日续接;急事插队;平静日大多沉默;一键调档 / "别烦我"生效;主动消息可直接回复接成对话。

**Phase 4 —— 打磨 + 扩展**
- 做:Codex 适配器;跨大脑一致性回归;成本优化;隐私文案与"仅本地大脑"选项。
- 验收:三种大脑都能跑且腔调一致;成本在可接受区间;隐私披露到位。

**后续(phase 2+,非本期):** 后台常驻服务(app 关了也能主动)、记忆 drift 反向微调人设、记忆向量检索、接入更多飞书数据/外部渠道。
