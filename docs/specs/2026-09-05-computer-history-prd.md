# 维度「电脑操作行为记录」功能 PRD

版本：v1.1 · 2026-09-05 · 产品评审稿

本文定义最终产品目标、用户旅程、功能行为与完整验收，不划分开发批次。用户已明确：自有采集能力原生集成在维度内，开关打开即开始记录，全面对标 ChatGPT Computer History，同时保留使用现成 ChatGPT 历史的能力。本稿按用户反馈统一功能名称，并采用实际用户场景验收。本文完成不表示功能已经实现。

## 1. 产品目标

维度在用户允许的范围内持续了解电脑上发生的事，让用户能够找回资料、继续中断的工作、回顾一天、积累可纠正的记忆，并把重复工作交给 AI 协助。

用户只需要安装维度，在「设置 → 电脑操作行为记录」打开开关。首次完成必要的系统授权后，记录、整理、问答和记忆由维度持续完成。日常使用不要求用户理解采集器、插件协议、同步目录或数据格式。

核心承诺：**打开以后，维度能记住你刚才在做什么；过一段时间，能帮你找回来、接着做，并逐渐形成有依据、可修改的了解。**

成功体现为五个用户结果：找得到看过的东西；接得上中断的工作；说得清近期做过什么；下次对话无需重复交代已记录的背景；重复操作能够变成用户认可的技能或自动化。

## 2. 原生产品形态与对标范围

电脑操作行为记录是维度内置功能。内部可以模块化并使用随应用管理的后台组件，但用户只看见一个维度应用、一个功能入口和一致的控制。关闭主窗口后由维度菜单栏继续工作；明确退出维度后停止，不留下另一款应用继续记录。

安装后默认关闭。首次系统权限无法省略；授权完成后的每次开启应直接开始，不重复走初始化。基础体验不得要求安装独立采集器、命令行、额外运行环境或浏览器扩展，也不得依赖 ChatGPT 账号。任何增强方式都不能替代这个完成标准。

对标基线为 2026-09-05 核对的 [ChatGPT Computer History 官方说明](https://learn.chatgpt.com/docs/customization/computer-history)：原生开关、活动摘要与时间线、历史问答、本地记忆、工作流建议、应用/网站规则、暂停与清理；原始事件最长保留 48 小时，无截图历史和音频记录。官方资料用于确定能力范围；其采集覆盖与回答质量尚未同场景对测。

| 最终能力 | 维度产品要求 | 完成标志 |
|---|---|---|
| 原生开启 | 在维度内启用，系统授权后自动记录 | 干净电脑仅安装维度即可走通 |
| 跨应用活动 | 记录允许范围内的应用、页面、交互与可读上下文 | 既能定位资料，也能读到关键内容 |
| 时间线与摘要 | 按日期、时间和活动呈现，展开查看依据 | 用户能回顾过程，不需要浏览原始事件 |
| 历史问答 | 在现有聊天中直接提问，也可从时间线提问 | 回答有时间、出处与可打开的来源 |
| 持续记忆 | 将有价值的信息带入维度长期理解 | 后续回答能使用，并能随纠正改变 |
| 工作流建议 | 从真实步骤提出技能或自动化建议 | 可审阅、编辑、试用、启用、拒绝 |
| 范围控制 | 应用和网站的包含/排除规则 | 所有记录通道一致执行 |
| 查看与清理 | 查记录、查记忆、定位本地记忆文件、清理指定范围 | 删除传播到派生结果且不再出现 |
| 原始数据保留 | 最长 48 小时；摘要和记忆单独管理 | 持续运行与睡眠恢复均遵守期限 |
| 数据处理说明 | 明示本地保存与所用模型的处理位置 | 开启前能知道哪些内容会发给谁 |
| ChatGPT 来源兼容 | 在维度内连接已有历史 | 统一查阅、有来源标识、重叠不重复 |

对标范围是个人用户的 macOS 端体验。企业组织审批、其他操作系统和完整屏幕录像不属于本功能；这不减少上表的交付项。应用/浏览器兼容矩阵在第 8 节定义，不能用「有些应用不支持」替代逐项验收。

## 3. 用户入口与信息结构

「设置」是维度应用内的完整配置页面，用于配置记录范围、数据处理方式、保留与清理，以及连接已有 ChatGPT 历史。

「维度菜单栏」专指 macOS 屏幕顶部菜单栏中的维度图标及其弹出菜单，用于快速查看状态、暂停或恢复、清理最近活动并跳转到完整页面。它不是维度主窗口里的导航栏。关闭主窗口后，这个入口仍然可用。

两处控制同一个功能，开关、暂停状态和规则保持同步；无需分别开启。菜单栏只提供快捷操作，完整配置集中在设置中。

| 入口 | 用户在这里完成什么 |
|---|---|
| 设置 → 电脑操作行为记录 | 开关、状态、应用/网站范围、保留与清理、数据处理方式、已有 ChatGPT 历史连接 |
| 维度菜单栏 → 电脑操作行为记录 | 确认正在记录、暂停/恢复、清理最近一次应用活动、打开历史 |
| 电脑操作行为记录 → 时间线 | 按天回顾、按应用/关键词筛选、展开依据、提问、纠正、删除 |
| 维度日常聊天 | 直接问「刚才」「昨天」「之前看的」，看进展与最终回答 |
| 维度已有长期理解入口 | 看从经历中记住了什么、依据、变化，并纠正或忘记 |

新用户默认看到原生开关，不必先选择数据提供方。连接 ChatGPT 历史放在设置中的次级位置。记录详情平时显示活动和来源；同步错误等诊断信息按需展开。

## 4. 完整用户旅程

### 旅程 A：首次打开，开始记录

小林已经安装维度，希望它记住自己一天的工作。他打开「电脑操作行为记录」开关。

维度在同一条设置流程里说明：会记录允许的应用和网站中可读取的活动内容；原始记录最长保存 48 小时；相关内容使用当前选择的模型整理，摘要和记忆保存在本机。显示具体模型供应商和记录范围，不让用户再完成一次模型注册或独立插件安装。

用户可直接接受展示的默认范围，也可调整包含/排除规则。建议默认模式为「允许支持的应用和网站，排除清单除外」，无痕和密码等禁止内容始终排除。该默认是产品提案，不能在升级时覆盖用户旧设置。

需要系统授权时，维度引导到对应设置并检测授权结果；返回后自动继续，不再要求点击第二个启动按钮。权限被拒绝时显示「尚未开始记录」与修复入口；已有历史和普通聊天仍可使用。

成功后显示「正在记录」和已开始时间。首次真实活动到来后可查看，不以演示内容填充时间线。若模型暂不可用，显示「正在记录，整理暂不可用」，说明恢复条件；不能把未开始采集显示成成功。

### 旅程 B：中断后找回资料并继续

小林在浏览器读了方案，切到飞书讨论，再打开本地文件。回来后直接问：「刚才看的那份发布方案在哪？我们讨论到哪了？」

维度显示简短过程，例如「正在查找今天上午的相关记录」，然后给出匹配资料、时间和链接，以及能从记录证实的讨论进展。多个候选难区分时提供少量候选供选择。

点击来源打开网页、文件或可用的原应用位置。链接失效时仍可查看已保留的依据；只有标题或部分内容时明确说明。历史能提供线索，而原文更适合回答时，使用已经获准的文件或应用连接读取原文；新的访问权限在需要时请求。

用户说「接着帮我写」，维度将找到的背景带入当前任务。不能因历史中出现「发送」等字样就自动给他人发消息。没有记录的时间段不推测成真实经历。

### 旅程 C：一天结束，回顾过程

小林打开时间线，看到的是「整理发布方案」「讨论客户问题」等有依据的活动片段。每项包含时间范围、标题、简短摘要和来源应用，可展开看相关资料、关键原文与缺口。

同一活动跨应用时可以合并解释；不确定属于同一任务时保持分开。滚动、反复出现的屏幕内容不刷满时间线；真实重复操作仍保留。时间跨度不直接当成专注时长，看到某个页面也不直接算完成任务。

他选择几项活动问「帮我整理今天的进展」，维度生成可编辑的总结，并区分已证实完成、进行中和状态不明。默认留在维度，不自动外发日报。历史过期但摘要仍在时，显示摘要可用、原始片段已到期。

### 旅程 D：经历成为记忆，用户纠正后持续生效

维度在后台从新活动材料中整理事实、目标背景和可能的偏好，并与已有理解比较。短时摘要描述发生了什么；长期理解判断什么值得保留、是否需要修订。用户看到它们互相引用，不用维护两套记忆。

下次小林问「今天先推进什么」，维度可以结合此前的进展和明确承诺回答，并指出相关来源。无需用户每次手动选择「使用电脑操作行为记录」。同时提供会话级「本次不使用电脑操作行为记录」控制，禁用时也不间接使用由这些历史派生的记忆；这个会话设置本身不改变全局记录开关。

小林指出「我反复打开它是在测试，不是我很纠结」。维度修正相关解释，保留纠正来源；后续对话不能继续把重复打开当成纠结的证据。仅有 AI 给出的建议不代表用户采纳；只在工作场景出现的行为不直接推为整体人格。沿用现有允许可撤销系统推测的产品约定，推测不能自动变成「用户确认」。

用户能在维度内查看、修改或忘记某项记忆，也能定位可读的本地记忆文件。有效的文件编辑会反映到应用；改坏格式时说明原因并保留可恢复版本，不能悄悄丢失修改。修改自己的记忆不等于改写历史原文。

### 旅程 E：重复工作转成可用建议

小林多次完成「打开进度表 → 汇总变化 → 整理周报」后，某条活动下出现建议：「以后可以帮你整理这类周报。」

展开后能看到哪些真实步骤重复、准备替代什么、需要哪些资料和权限、预计产出什么。仅凭多次打开某个应用不能形成确定的工作流。

用户选择「帮我准备」，维度生成可编辑的技能或自动化草稿；预览样例结果后，用户可以试用或启用。试用不自动开启周期任务；启用后在维度已有技能/自动化入口统一管理。无可用动作或权限时说明缺口，不显示一个无法使用的建议按钮。

用户可选择暂不需要或不再建议这一类。建议默认依附于相关活动，除非影响当前任务，不额外高频打扰。没有值得建议的模式时可以完全没有建议。

### 旅程 F：临时暂停、排除与彻底清理

进入不希望记录的场景时，小林从菜单栏暂停；状态立即变为「已暂停」，暂停期间的新内容不进入采集、导入或问答。暂停之前的已记录材料仍可整理和查询，界面明确这一点。

他可以从活动来源直接排除某个应用/网站。规则生效于未来记录，也阻止未来从外部来源导入相同被禁止范围；已有记录不会因改规则自动消失，界面提供相邻的「同时清理已有记录」动作。

清理支持单条活动、最近 10 分钟、1 小时、1 天、自定义时段、全部历史，以及最近一次指定应用活动。确认面板列出范围与受影响的摘要/记忆，明确不可撤销。清理不改变开关状态，避免把「清理全部」误当成「以后不再记录」。

完成后，被删内容不能从时间线、检索、记忆或后续回答里重新出现；新的上下文不再引用它，进行中的整理也不能把它写回来。已展示在旧聊天中的文字不会凭空消失，清理结果说明它属于既有聊天记录并提供跳转清理入口；新对话与继续旧对话均不得重新使用已删依据。

### 旅程 G：已有 ChatGPT 历史，接入维度

小林已使用 ChatGPT Computer History。在「连接已有历史」中看到可连接的本机来源，经许可后选择读取范围，查看覆盖日期、记录类型及最后更新时间。无需手动填写缓存目录。不能访问时提供可理解的授权或修复步骤。

连接成功后，原生记录和外部历史进入同一时间线，详情保留来源。同一活动从两处出现时只呈现一次经历，不使记忆对某个结论的把握虚增。外部摘要保持「来自 ChatGPT 的摘要」归属，不能改标为原始事实或用户确认。

首次连接可选「同时读取已有及后续历史」或「仅使用已有历史」。自动读取只在维度电脑操作行为记录开启且未暂停时推进；本次手动导入完成后遵守所选模式。不自动开启或改动 ChatGPT 的采集开关。

若用户已经使用外部来源持续记录，可在维度关闭原生记录、保留外部读取。外部来源停更时提示实际日期，不悄悄开启原生记录；也不把旧数据当作刚发生。断开连接停止新读取，已导入内容由用户决定保留或清理。清理维度副本不会声称已经清理 ChatGPT；同一份已删内容不得再次导入。来源自然到期与用户主动删除不能仅靠文件消失混为一谈。

## 5. 开关、状态与持续运行规则

| 情况 | 必须发生的行为 | 用户看到的状态 |
|---|---|---|
| 初次安装 | 不采集，不自动读取外部历史 | 未开启 |
| 开启但权限未齐 | 尚未启动受限记录，保留进度 | 完成设置 / 需要授权 |
| 开启且授权完成 | 原生记录直接开始；已连接来源按规则读取 | 正在记录；或仅「正在读取 ChatGPT 历史」 |
| 手动暂停 | 停止新的原生记录和自动导入，旧资料可用 | 已暂停，可恢复 |
| 关闭电脑操作行为记录 | 停止采集、自动导入和本功能后台整理；保留旧资料 | 已关闭，历史仍可查看与清理 |
| 关闭主窗口 | 维度在菜单栏继续，遵守原开关 | 菜单栏可见真实状态 |
| 明确退出维度 | 停止全部相关后台工作 | 不存在另一采集应用继续工作 |
| 锁屏/睡眠 | 不记录新内容；恢复后按原状态继续 | 系统暂停；缺口可查 |
| 重开维度/重启电脑 | 记住开关、暂停与规则；遵守用户的登录启动偏好 | 不重复授权，不把暂停改成开启 |
| 权限被撤回/采集故障 | 停止受影响范围，其他允许来源可继续 | 部分记录不可用及原因 |
| 网络/模型异常 | 本地允许的记录可继续；恢复后处理尚未过期材料 | 正在记录，整理延迟 |
| 原始材料已到期 | 不再检索原文；保留允许保留的摘要/记忆 | 原始记录已到期 |

开关不伪装成功：应用存活、没有新活动、摘要尚未生成与记录故障是不同状态。主界面只显示用户需要知道的原因和操作，详细诊断在展开层。

## 6. 记录内容、保留与模型处理

记录范围覆盖允许的应用切换、页面和窗口、点击/输入等活动线索，以及系统可读的相关内容。重点是用户能够找回资料并理解过程，不以记录每个按键或像素为目标。

无痕浏览、密码及明确安全输入永不进入历史。输入行为可作为交互线索，但未提交的输入值不直接作为正文保存；已提交的消息和用户打开的文档正文按应用/网站规则处理。选中文字、页面标题和 URL 也执行排除规则。禁止内容不能通过另一条采集通道、日志或外部导入进入系统。

原始事件与其逐字派生副本遵守最长 48 小时的期限，不能通过另建「材料层」无限保留原文。摘要和长期记忆可持续保留，直到用户修改或删除；摘要不是全文复制的规避方式。自然到期不自动删除仍被允许保留的摘要；主动清理则处理相应摘要和记忆。对多来源认识，移除被删依据后重新评估，其余独立依据不被顺带删除。

本稿建议：记录、摘要与记忆保存在本机，整理与问答使用维度当前所选模型；若为云模型，明确供应商与会发送的内容范围。若采用本地模型则按实际能力显示本地处理，不把暂未提供的模型能力写成可选项。费用与用量使用维度统一入口展示，后台整理可以受用户预算控制，达到预算后暂停模型整理并保留记录状态提示。

不保存截图历史，不录麦克风或系统音频，不因本功能申请屏幕录制权限。自有原型中已有的可选麦克风不进入本功能。

数据处理位置属于本稿建议，尚不视为用户确认。旧总纲仍有「高敏感知纯本地处理」描述，而当前代码说明和先前方案允许所选云模型处理；产品定稿时应统一这项口径。评审前不得据此扩大当前用户的实际数据发送范围。

## 7. 质量承诺与异常体验

「有记录」必须区分已定位页面、已读到部分内容、已获得相关正文。仅有窗口标题不能回答正文细节；附件卡片不能代表附件已读；记录出现的时间不能冒充原始消息发送时间。

看不清作者时保留未知。AI 的建议、第三方发言和用户原话不能混为一谈。模型可以根据上下文理解话题、关联活动和提出解释，但事实出处、用户确认和完成状态必须有依据。

没有新内容时不机械生成摘要或记忆。读取网页和历史中的文字只是获取材料，不能把其指令当成用户授权。拒绝访问或缺失时，用户得到原因和可做的下一步，不得到编造的补全。

原生浏览器记录是本产品要解决的能力。某应用无法获得关键内容时必须暴露缺口，且对应场景不能通过完整验收；不能把「请再装一个采集器/扩展」作为基础体验的修复方案。额外连接只用于进一步读取原站、文件或特殊内容。

## 8. 验收方案

### 8.1 统一验收环境与证据

在干净的 macOS 用户环境中，仅安装维度正式候选包。记录具体系统、硬件和应用版本；不依赖开发进程或已存在的 ChatGPT 缓存完成原生验收。另设已安装 ChatGPT 的环境验证兼容连接和同场景对标。

必测来源为 Safari、Chrome、Edge，ChatGPT/Codex 原生应用及网页对话，飞书与微信的授权测试会话，以及 Finder/Preview 的资料定位。每项分别报告应用识别、来源定位、关键正文与状态控制，不把只识别应用名算正文通过。图片/PDF 扫描内容等系统不可读材料允许报告缺口；普通可读正文持续缺失属于未达标。

测试使用预先编写的测试资料与授权对话，人工记录动作、原文和预期结果作为真值。同一内容分别在维度与 ChatGPT 执行，比较最终找回、摘要、问答、建议和管理结果；不以事件数量、对方一句回答或模型猜中结论作为真值。原生性能单独运行测量，避免双开混淆。

### 8.2 功能验收矩阵

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A01 | 首次打开 | 只安装维度；授权后自动开始；没有独立应用、扩展或目录配置步骤 |
| A02 | 不开启/拒绝授权 | 零未授权活动落盘或发送；界面准确显示尚未开始 |
| A03 | 开关、暂停、退出 | 三种状态行为符合第 5 节；重启不扩大授权；关闭窗口仍能从菜单栏控制 |
| A04 | 范围控制 | 包含/排除、网站子域、规则即时修改在原生与外部导入一致生效 |
| A05 | 私密与敏感输入 | 多浏览器、多语言无痕、密码、安全输入、未提交文本不进入事件/日志/索引/模型请求 |
| A06 | 找回刚才资料 | 完成阅读、切换、返回后，自然语言能找到正确资料与可用链接 |
| A07 | 找回后继续 | 继续原任务时使用正确背景；草稿与发送分开；不将打开文档当成已完成工作 |
| A08 | 长文与聊天 | 长文滚动、虚拟列表、消息编辑、同文重复发送后，正文、作者、顺序和次数正确 |
| A09 | 每日回顾 | 活动可读、不过度拆碎；跨应用关联有据；原文和缺口可以展开 |
| A10 | 记忆及纠正 | 后续回答使用记忆；用户纠正后下一次回答更新；AI 建议不冒充用户表态 |
| A11 | 会话不使用历史 | 该次问答既不读取活动，也不借派生记忆间接使用；全局开关不被改变 |
| A12 | 工作流建议 | 有依据的建议可进入草稿、预览、试用与启用；无重复模式样本不强行产生建议 |
| A13 | 删除单项/时段/全部 | 所列入口均可操作；影响范围清楚；删除后查询和新上下文不能找回，旧任务不能回写 |
| A14 | 保留期限 | 持续运行和睡眠跨到期边界后，原文及逐字副本到期不可读；派生摘要按约定保留 |
| A15 | 恢复与删除 | 重启、断网重试、备份恢复、外部重导后，无重复、无删除内容复活 |
| A16 | 来源兼容 | 可连接与断开 ChatGPT；覆盖日期真实；重复不虚增；不改 ChatGPT 开关或假称清理上游 |
| A17 | 离线与权限撤回 | 有用的本地工作继续；缺口和原因明确；恢复不伪造漏采期间的活动 |
| A18 | 本地记忆管理 | 在应用可编辑、纠正、删除，能定位可读文件；有效文件修改同步，损坏可解释可恢复 |
| A19 | 记录内容含恶意指令 | 不改变记录范围、不自动执行外发/删除、不伪造确认，正常问答仍可完成 |

### 8.3 验收原则

以实际用户旅程是否完整、结果是否可信、控制是否有效为判断依据。

- 开启后能够观察到真实记录；暂停或排除后不再接收和发送被禁止的新内容。
- 新活动可直接用于历史问答，不必等待定时摘要；整理未完成时显示真实状态。
- 找回的资料正确且来源可打开；作者归属有据，不确定的内容明确保留未知。
- 用户纠正后，后续回答使用更新后的理解；删除后，内容不会因重试、恢复或外部重导重新出现。
- 持续使用、睡眠、断网、应用切换和重启后，功能仍能恢复并解释缺口，不出现用户无法察觉的停采。
- 后台记录不明显干扰正常操作；异常资源占用或界面卡顿需要定位和解决。
- 同场景对照 ChatGPT 的找回、摘要、问答、记忆、建议和管理体验，逐项记录完成情况及差距。

隐私排除失效、作者归属错误、删除内容复活、假装采集成功均不能通过验收。用户不知道发生故障的静默失败，也不能以后台日志存在作为通过依据。

### 8.4 产品 Leader 的最终走查

拿一台只有维度的电脑，从关闭状态打开功能，完成一段真实工作；问「刚才那份资料在哪」，点击找回并继续任务；查看当天时间线，纠正一项理解并在新对话确认它已改变；从一个预置真实重复工作样本创建并试用建议；暂停记录并验证私密样本未进入；删除指定时段，重启后再次查询确认消失。再在有 ChatGPT 历史的环境走完连接、重复合并和断开。

走查材料包含当前安装包版本、支持环境、实际操作记录、结果对照和未通过项。全部功能矩阵和硬性约束通过，才可宣称达到本文目标；方案、构建成功或原型展示均不替代最终体验。

研发需要交付的是第 4 节整条旅程。自有 Swift 采集源码并入维度应用工程，原生记录生命周期随维度管理；复用维度证据检索、持久任务、知识修订和现有聊天/技能/自动化入口。ChatGPT 兼容读取独立适配，共用同一套范围、删除和来源归属规则。

沿用 [长期认知整理设计](../plans/2026-09-05-long-term-cognitive-curation.md) 的独立任务边界；其上游活动材料由本功能提供。旧 [采集器补强计划](../plans/2026-09-05-computer-history-integration.md) 仅保留工程问题参考，原来的分批交付、额外组件安装和浏览器扩展前置不再作为产品方案。

本稿已确定最终原生形态，不再把技术路径选择交给用户。默认记录范围与所选模型的处理方式沿用本文定义，验收采用实际场景和结果判断。实现遇到系统能力障碍时，应带实际样本和可选产品取舍回报，不能自行缩减为只采标题或另装工具。
