## 0. 这份文档是什么

[前端定义 PRD](2026-08-19-dimension-desktop-frontend-prd.md) 回答「界面上有什么、长什么样」；本文档回答两个它不回答的问题：

1. **用户旅程**：一个真实的人从第 0 天到第 30 天，是怎么经历这个产品的——每个时刻他在做什么、系统在做什么、他应该有什么感受。
2. **功能背景**：每个功能为什么存在——它服务旅程的哪一步、背后压着哪条假设、没有它会发生什么。

用途：设计和开发做任何功能取舍时，先回到这里查「这个功能在旅程里的位置」。一个不服务任何旅程时刻的功能不该做；一个旅程时刻没有功能承接，就是缺口。

## 1. 用户是谁，带着什么来

**画像**（承接总纲 §1.1）：有明确自我提升需求，正处于学习迷茫、事业过载或生活瓶颈的个人。共同特征是一句话：**信息很多，判断却没有变清楚；日子过得很快，却说不出自己变了什么。**

他们带着三个未被满足的需求来：

| 需求 | 现有工具为什么满足不了 |
|---|---|
| 想被「接住」每天冒出来的想法和承诺 | 备忘录接得住但没有下文；记了等于埋了 |
| 想知道自己到底在怎么想、有没有变化 | 日记靠自律，回看靠毅力；没有人帮他看出模式 |
| 想让「想明白的事」真的变成「做出来的事」 | todo 工具只管执行，不管这件事为什么值得做 |

**他们不要什么**（同样是功能背景）：不要又一个信息流、不要打卡式自律工具、不要一个滔滔不绝显得很懂他的 AI。产品的克制（留白、宁缺、低频点亮）不是功能缺失，是对这三个「不要」的直接回应。

**维度在旅程里扮演什么**：一个**第二大脑**，加一双**逐渐被托付的手**。第二大脑替你记住并理解现实——核心靠速记与对话；录音胶囊与电脑使用轨迹（computer history）作为**感知插件**按需开启（默认关闭、显式开启、纯本地）。手是懂你之后替你把事办了——从「告诉你怎么跟 Codex 说」到「替你起草真正符合你意思的指令」再到「直接调度 Claude Code / Codex 代跑」，作为**执行插件**按你授予的权能逐级解锁（执行梯子与插件模型见总纲 §3.2 / §3.4）。**插件是维度的器官**——感知是眼睛耳朵、通道是嘴巴、执行是手：维度带感官出生，器官可替换、可增强、可关闭，但不是裸核之外的增值包。

## 2. 旅程总览：四个时间尺度

```text
第 0 天        一天之内             一周之内               一个月
────────      ──────────────      ──────────────────    ──────────────
20 分钟        早：早报 + 日程      候选逐条异步推进        回看养成时间线：
引导对话   →   午：速记 / 摸鱼   →  （回一句也算）→        哪些认识变了、
产出第一张     偶尔：候选来了       攒清楚 → 行动进日程     哪些实验做了、
桌面           回一句              （可选深聊加速）        桌面长成什么样
              大事办完：问一句      每周：check-in 兜底
                                   → 周日回顾
```

四个尺度各有一个核心问题：

- **第 0 天**：凭什么留下来？（First Useful Breakthrough 的起点）
- **每一天**：凭什么每天打开？（资讯 + 日程的保底价值）
- **每一周**：产品主张兑现了吗？（共创流产出真实的认知沉淀与行动）
- **每个月**：他变了吗，他知道自己变了吗？（成长可见性）

四个尺度之外还有一条贯穿线：**养成**——维度越来越懂你，你越来越放心它，桌面越来越像你的。见第 7 节。

---

## 3. 第 0 天：从一无所知到第一张桌面

系统对用户一无所知，用户对产品半信半疑。这是最容易流失的一天，设计目标是**在 30 分钟内给出一次不依赖历史数据的真实价值**。

| 步 | 用户在做什么 | 系统在做什么 | 触点 | 情绪目标 |
|---|---|---|---|---|
| 1 安装打开 | 装 mac 应用，首次打开 | 不弹教程；秘书打招呼，说明接下来会聊 20 分钟 | 桌面 | 「不是又一个要学的工具」 |
| 2 引导对话 | 聊最近在忙什么、卡在哪、typical 一天怎么过 | 追问具体事件而非观点；实时把听到的整理成条目给用户看 | 对话 | 「它在认真听，而且听得懂」 |
| 3 第一张桌面 | 看到桌面第一次被填上 | 从对话产出：首批日程、2-3 条资讯挂靠主题、（如果有）第一个候选观察 | 桌面 | 「这是我的，不是模板」 |
| 4 第一次裁决 | 对候选观察给反应（有点意思 / 不太对） | 记录反应；如果存活，邀请补全成第一张认知卡 | 对话 | 「我说了算」 |
| 5 收尾 | 被告知接下来几天会发生什么 | 说明：速记随手发（微信里就行）；偶尔会丢一个「我注意到的事」，回一句就行；大事办完会问你一句感觉如何，平时每周聊一次；想深聊随时可以 | 对话/微信 | 预期管理完成 |

**失败模式与防线**：引导对话问成问卷（防线：对话脚本按「事件优先」设计，禁止连续两个抽象问题）；第一张桌面稀疏难看（防线：留白格有正式设计，见前端 PRD 7.2）；用户当天没接 IM 窗口（防线：微信扫码接入放进引导流程，2 分钟内完成；桌面单独可用，飞书是备选）。

## 4. 日循环：凭什么每天打开

一天三个触达窗口，总投入 **≤10 分钟**。设计红线：任何一天，就算用户只做「扫一眼」，桌面也必须自洽——日循环不依赖用户勤奋。

**早（开场，~2 分钟）**：打开桌面。资讯区（首位）有今天的 1-3 条早报——不是热点，是挂着「为什么给你看」的异质视角；日程区（最大格）是今天的 3-5 件安排，其中来自实验或规划的条目带血缘标（「这件事是因为你上周想试 X」）。

**午（随手，零散）**：想到什么发给微信里的维度（或应用内速记、飞书）：一句抱怨、一个决定、一件答应了的事。系统只收不评，静默归档为证据。摸鱼时点开资讯条目细看，给个反馈（有新角度 / 已知道 / 没用）。

**晚（默认不打扰）**：没有每日打卡式的提问。维度只在两种情况开口：一件**大的日程或实验刚完结**——顺势问一句「那件事办完了？感觉如何」（事件完结是记忆最鲜活、最有话说的时点）；或到了**每周一次**的 check-in 兜底。回不回都行；沉默也是数据，不追问第二次。想每天被问一句的用户，由维度以形态提案的方式让他自己选择长出这个习惯。

**日循环里系统在攒什么**：速记、日程完成情况、资讯反馈、check-in 回答——全部进证据层，供每周的候选挖掘用。用户感知不到「被分析」，只感知到「被接住」。

## 5. 周循环：产品主张的兑现时刻

**共创不是必须出席的周会，是可暂停、跨触点续接的流**。候选是最小推进单元：

1. **候选出现**（单条）：「我注意到一件事——你周二说要 X，但周三周四都在做 Y，你怎么看？」（问句，不下结论；桌面或微信都可能收到）
2. **回一句就算参与**：有点意思 / 不太对，其实是…… / 先放着。今天只回这一句完全可以。
3. **跨天续接**：明天想起来再补两句证据、聊聊什么时候例外——在哪个触点续都行，维度记得聊到哪了。
4. **攒清楚了才成路**：**显性产出是下一步怎么走**——规划条目或一个 ≤30 分钟可逆的小尝试，进日程区、带血缘。聊出来的新认识由维度安静记下（内部仍是完整结构），只轻轻确认一句：「这次想清楚了一件事：……」——**认知沉淀不立卡、不打断，成长是结果不是任务**。
5. **不追问**：候选 3 天没人碰就静默收起；推进到一半停了 7 天，轻问一次「要不要先放着」，之后不再问。

**深聊模式（可选加速器）**：攒了 ≥2 个推进中的候选、或一个实验出了结果，维度邀请一次 ≤15 分钟的完整对话，一口气推进多个——「攒了几件事想跟你聊聊，有空吗？」。拒绝或没空，一切照常走异步流。**深聊是加速器，不是闭环的唯一入口。**

**结果回收**独立于深聊：验证动作到期时单独问一句（或并入最近一次 check-in），一起给旧的认识下结论（灵了 / 部分灵 / 不灵）。

**周日回顾（~5 分钟，被动阅读）**：一页「本周」——记了多少、想清楚了几件事（小角落的正循环提示，点开可溯源）、试了什么、下周桌面会因此有什么不同。

## 6. 月弧：成长可见性

从秘书栏底部「看看我们是怎么熟起来的」进入养成时间线。回答一个问题：**这一个月我到底变了什么？**

- 哪些旧认识被挑战了，结局如何（确认 / 修订 / 收窄了适用范围）
- 哪些实验做了，结果改变了什么后续安排
- 桌面形态怎么长的：哪些卡来了又走、哪个区被你钉住了、秘书提过什么形态建议、你接受了哪些
- 养成参数（熟悉 / 默契 / 权能）的每次变化都能点开看到具体事件（不能解释的增长不展示）

月弧同时是 harness 命题（H7/H8）的观察窗：用户在这里第一次「看见」自己的产品形态和别人不一样。

## 7. 养成线：和维度一起变熟（贯穿全程）

旅程不只有「用功能」，还有一条贯穿四个尺度的关系线。它有两股：

- **关系养成**（人 ⇄ 维度）：系统名称。可计算的参数只有三个——**熟悉**（它对你的覆盖度与新鲜度）、**默契**（它对你判断与取舍的校准度）、**权能**（你显式授予的行动范围）。**「关系」本身不做数值**——那会被理解为情感好感度；数值与阶段一律挂在三参数上。
- **形态养成**（你 ⇄ 桌面）：桌面被你们一起养成你的样子——形态提案、钉住一张卡、让一张卡走。harness 命题的日常体现。

**养成的物理规则**（不可让渡）：任何成长必须由具体事件驱动、可点开解释；权能只能显式授予，绝不随好感自动升级；沉默、拒绝、纠正同样是有效的关系数据；没有签到、没有连击、没有「今天还没和我说话哦」。

**养成的回报是行为变化，不是数值**。用户感知到的不是进度条在涨，而是维度做事的方式在变：

| 熟悉阶段（工作稿） | 维度的行为基线 | 用户的体感 |
|---|---|---|
| 初见（第 0-1 周） | 只问、只记、只整理，不下判断 | 「它在认真听」 |
| 看见模式（第 1-3 周） | 开始提候选观察；保守，证据充分才开口 | 「它注意到了我没注意的」 |
| 懂处境（第 3 周后） | 候选可以更私人；会主动引用几周前的速记 | 「它记得，而且连起来了」 |

（**受托**不是熟悉阶段，是权能状态——由显式授权解锁，与熟悉深浅无关。）

**候选的大胆程度由四因子共同决定，熟悉阶段只是其中的先验**：

> 大胆度 = 证据充分度 × 领域敏感度 × 用户偏好 × 当次许可

- **证据充分度**：基础门槛，证据不足的判断在任何阶段都不出口；
- **领域敏感度**（硬闸）：亲密关系、健康、心理等高敏领域，熟悉三个月也不擅自下判断——最多最轻的问句，或等用户先开口；
- **用户偏好**：直说还是委婉，可设置、可被形态提案调整；
- **当次许可**：即时生效——用户说「你直说」临时放开，说「这个别碰」立即归零并记住。

**各尺度的养成时刻**：

- **第 0 天**：引导对话结束，维度复述「今天我认识了你的 A、B、C」——熟悉的第一次可见增长。
- **每一天**：状态徽章（在岗 / 在想 / 有事说）维持在场感；速记有回执；纠正被当场复述修正版。
- **每一周**：回合尾声一句「这次之后我更清楚你——（具体内容，如：你不是拖延，是在等一个确定信号）」——增长用内容说，不用数字说。
- **每个月**：养成时间线回看每次变化对应的事件；阶段跃迁是月弧里的正式时刻。

**实验期裁剪**（与 harness 实验设计 5.5 一致）：种子产品**不做**参数外显与阶段系统，只做三件轻的——状态徽章在场感、纠正被复述、回合尾声的「懂你一句」。参数、阶段、数值时间线属于 P4 批次（工程实施计划 §3）；实验期用访谈验证「用户是否感到被越来越懂」，为 P4 的评分规则积累真实样本。

## 8. 关键时刻（Moments that Matter）

旅程中五个决定信任的时刻，每个都有明确设计要求：

| 时刻 | 大概发生在 | 设计要求 | 压着的假设 |
|---|---|---|---|
| **第一次「我没这么想过」** | 第 1-2 周 | 候选必须挂真实证据（用户自己的言行），问句呈现；宁可晚，不可假 | H1 |
| **第一次拒绝被尊重** | 第 1 周 | 用户说「不对」后，系统记录并当场复述修正版；同类候选下次明显收敛 | H2 |
| **第一次留白** | 任意 | 「今天没什么特别想说的」要说得体面、笃定，不带歉意；次日照常 | H6 |
| **第一次授权请求** | 第 2-4 周 | 说清楚要代做什么、会动什么、怎么撤销；被拒绝不再问同类第二次 | 权能物理规则 |
| **第一次形态提案** | 第 2-4 周 | 「我注意到你总是周五才看周回顾，要不要改成周五发？」——必须指向用户真实行为，可一键还原 | H7/H8 |
| **第一次被懂** | 第 2-3 周 | 维度主动引用几周前的速记解释今天的候选（「你三周前说过 X，今天这个像不像同一件事？」）；引用必须准确、可点开原文 | 养成线（熟悉/默契） |
| **第一次阶段跃迁**（正式版 P4） | P4 后 | 跃迁可解释（点开看事件清单）；伴随可感知的行为变化，而非仅数字变化 | 关系可解释性 |
| **第一次替你办成一件事**（正式版） | 授权后 | 维度把一件小事翻译成手（Claude Code / Codex）能执行的指令并跑完：事前确认单、事后全程账本；首次必须选低风险可逆任务 | 执行梯子（权能） |

## 9. 功能背景矩阵

每个功能的存在理由。**评审用法：砍需求时对照「没有它会怎样」列；加需求时先回答「它服务哪一步」。**

| 功能 | 一句话定义 | 服务旅程哪一步 | 存在理由（压着的假设） | 没有它会怎样 |
|---|---|---|---|---|
| 引导对话 | 第 0 天 20 分钟结构化聊天 | §3 全部 | 冷启动必须当天给价值（First Useful Breakthrough） | 第 0 天是空桌子或模板，用户次日不回来 |
| 速记 | 随时一句话丢给系统（app / 微信 / 飞书） | §4 午 | 证据层的主要来源（H5）；微信是摩擦最低的入口 | 候选挖掘无料，共创回合成空转 |
| check-in（事件 + 周度，非每日） | 大日程/实验完结时顺势问一句 + 每周一次兜底；频率可经形态提案自选上调 | §4 晚、§5 | 补齐速记漏掉的选择与结果；事件完结是记忆最鲜活的时点（AAR） | 证据层只剩碎片，结果回收（H4）断链 |
| 资讯策展 | 每日 ≤3 条挂靠认知张力的异质视角 | §4 早 | 认知发散入口；反茧房主张（H9）；开场价值 | 桌面失去每日新内容，打开动机只剩日程 |
| 日程 | 今日 3-5 件时间锚定安排，带血缘标 | §4 全天 | 最高频价值锚点；认知落地的承接面 | 产品退回「偶尔聊聊的 AI」，日活无从谈起 |
| 血缘标注 | 每条内容可回溯上游（来自哪个实验/认知） | §4-§6 | 「为什么这样排」的可解释性；图谱的用户可见形态 | 桌面变成不可解释的黑盒推荐 |
| 共创流 + 深聊模式 | 候选逐条异步推进（回一句也算、跨触点续接、不追问）；深聊是可选的 15 分钟加速器 | §5 | 产品主张的兑现机制（H1/H2）；协作经验主义；C 端不接受必须出席的周会 | 认知卡退化为系统单方面生成的鸡汤；或仪式太重没人来 |
| 认知沉淀（低调） | 共创中确认的新认识：对话一句轻确认 + 小角落正循环提示（「这周想清楚了 2 件事」），点开才见完整结构（判断/证据/例外/边界） | §5、§6 | 认知突破的可信载体（证据先于结论）；成长是结果不是任务 | 「懂我」没有可检验的实体；或反过来变成显眼的作业 |
| 行为实验 / 验证动作 | 小、可逆、有停止条件的尝试 | §5 → §4 | 认知必须被现实检验（H3/H4，CBT 行为实验） | 产品停在「漂亮洞察」，改变不发生 |
| 周回顾 | 周日一页被动阅读 | §5 尾 | 周循环的闭环感；30 天叙事的素材 | 一周的投入没有回响，仪式感断裂 |
| 养成时间线 | 月度成长与形态生长的可视回看 | §6 | 成长可见性；harness 命题的观察窗（H7/H8） | 用户说不出自己变了什么——产品价值不可见 |
| 形态提案 | AI 观察摩擦后提出的界面/节奏调整 | §6、§7、§8 | 生长语法（AI 园丁）；H7/H8 的机制载体 | harness 命题没有执行机制，人人形态相同 |
| 授权与行动账本 | 显式授予代办边界，每次代办留痕 | §7、§8 | 权能物理规则：不能自动升级、可撤销 | 一次越权毁掉全部信任积累 |
| 秘书在场（立绘/状态徽章） | 在岗 / 在想 / 有事说三态的角色区 | §4 全天、§7 | 养成线的日常载体；主动性有可见状态 | 维度沦为无形的后台脚本，关系无处附着 |
| 养成参数与阶段（P4，实验期不做） | 熟悉/默契/权能的外显、阶段与事件时间线 | §6、§7 | 养成必须可解释（反伪养成硬约束） | 「被懂」的感觉无法回看验证，或滑向游戏化 |
| 被动采集（**感知插件**，非必选：录音 / computer history） | 现实自动进入证据层，不依赖用户勤奋；默认关闭、显式开启、纯本地 | §4 全天（无感） | 第二大脑的感知段（采集愿景文档）；插件模型 | 证据层只有用户记得说的事，第二大脑近视 |
| 承诺检测 | 从任何证据源（速记 / 对话 / 微信 / computer history）抓「你答应了别人什么」，提案卡一键确认进日程，带原文血缘 | §4 全天 → 日程区 | 帮用户记住容易忘的承诺；「被接住」需求的直接兑现；写入必经确认（物理规则 2） | 顺口答应的事继续丢，第二大脑对承诺失明 |
| 指令代拟与调度（**执行插件**，非必选） | 措辞建议 → 代拟指令 → 调度 Claude Code / Codex 代跑，按权能逐级解锁 | §4、§8（授权后） | 第二大脑的执行段（CODE 的 Express）；权能四模式；插件模型 | 想清楚的事还是得用户自己动手，「懂你」停在嘴上 |
| 自由结构面板（布局即数据 + HTML 模块，渐进点亮） | 桌面是三层布局文档（背景样式 / 卡的大小与内容 / 排布规则），每层可被形态提案编辑，不是硬编码页面 | §6、§8（形态生长的上限） | harness 命题的能力底座；OS 与小组件市场的分界 | 「长出不同结构」无从发生，产品终局是小组件市场 |
| 留白 | 「今天没什么想说的」的正式形态 | §4、§5 | 判断力的证明（H6，Grice 量准则） | 系统被迫每天硬找话说，沦为废话生成器 |
| 导出 / 删除 | 一键导出全部数据、一键彻底删除 | 全程 | 隐私最高标准 + 开源承诺的可验证性 | 「本地优先」沦为口号，共建者不敢真用 |

## 10. 反旅程：不希望发生的使用模式

| 反模式 | 信号 | 防线 |
|---|---|---|
| 刷资讯成瘾 | 资讯反馈量远超其他交互；要求加量 | 日上限 ≤3 条写死在代码；不做无限滚动；「已经看完了」是正式状态 |
| 只当 todo 工具用 | 日程高频、回合连续跳过 | 允许（日程本身有价值），但秘书按月提示一次「聊聊？」；回合完成率进 H2 结账 |
| 认知卡当鸡汤读 | 卡被点赞但验证动作从不执行 | H3 放弃线触发：动作改轻量承诺；回合里回收环节优先于新候选 |
| 讨好式裁决 | 候选全被接受、从无纠正 | 秘书主动示弱邀请纠正（「这条我不太确定，你觉得哪里不对？」）；全盘接受连续 2 回合触发提醒 |
| 形态折腾癖 | 频繁要求改布局改节奏 | 生长语法限速：单次一个变更、可回滚、H8 监控收敛 |
| 情绪依赖 | 深夜高频倾诉、把秘书当唯一倾听者 | 秘书不承担心理治疗角色；识别到持续情绪危机信号时明确说出边界并建议真人求助 |

## 11. 旅程级验收

以下指标在 harness 实验（3-4 周）内测量，与 H 表对应：

| 旅程问题 | 指标 | 目标 |
|---|---|---|
| 第 0 天留下来了吗 | 引导对话完成率；次日打开率 | 共建者 100%（样本小，全数追访） |
| 每天打开吗 | 日打开天数占比；速记条数/天 | 打开 ≥70% 天数；速记 ≥1 条/天 |
| 主张兑现了吗 | 候选闭环率与时长（H2）；「没这么想过」频率（H1） | ≥50% 候选 7 天内闭环、每人每周 ≥1 次闭环；≥1 条有效认知沉淀/周/人 |
| 认知变成行动了吗 | Cognition-to-Action（H3）；结果回收（H4） | ≥50%；≥50% |
| 他知道自己变了吗 | 月末访谈：能否不看时间线说出 ≥1 个变化，再看时间线是否补出更多 | 定性通过 |
| 形态长出来了吗 | 形态差异可指认（H7）；变更频率收敛（H8） | 见 H 表 |
| 感到被越来越懂吗 | 周访谈定性题：「维度最近有没有哪句话让你觉得它记得你/懂你？」能否举出具体实例 | 第 3 周起每人 ≥1 例 |
