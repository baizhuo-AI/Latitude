# 知识准入、事项生命周期与成本设计

日期：2026-09-06。状态：研究与设计提案；未实现、未修改用户知识、未启用任务。文中的旅游是用户提出的假设案例，不是真实行程。

2026-09-07 修订：补充事项内部的结构化语义与子图示例。保留当次动机、认知表征和取舍不必等待长期人格证据；叙述用于保留上下文，不能代替可检索、可修订的节点与关系。

承接[知识形成、整理写入与检索使用设计](2026-09-06-knowledge-formation-maintenance-retrieval-design.md)和[认知—行为理解模块](2026-09-06-cognition-behavior-understanding-modules.md)。本次修订解决三个问题：什么值得留下、留下到什么程度、什么时候值得进一步分析。Computer History 的采集与材料预处理保持上游职责。

## 1. 设计判断

维度需要同时保有“正在发生的事”“过去的经历”和“可复用的认识”。短期事项可以留下有价值的历史；一段有价值的历史不必立即转化成人格或偏好。

将原先容易混在一起的三个决定分开：

| 决定 | 核心问题 | 旅游案例 |
|---|---|---|
| 保留 | 以后接着讨论、安排事情或回顾时，需要找回什么？ | 保留是否决定、实际理由及必要背景 |
| 分析 | 现在多做一层解释，能改善哪项帮助？ | 给出本次建议可能需要比较取舍；不必同时分析人格 |
| 使用 | 这次问题应该读哪些知识和依据？ | 下周安排需要当前状态；半年后复盘可能需要当时的选择理由 |

六个认知—行为模块属于分析能力，不是六种必填记忆，也不是六次固定调用。默认采用“发生时保住关键背景，并结构化已经可知的动机、判断和关系；问题需要时深入理解，值得复用时沉淀认识”。当次认知和动机也可以立即入图，scope 限定于这次事项；跨情境推广需要另行论证。对于正在发生的重要矛盾和变化，后台也能主动展开理解，不必一直等用户提问。

## 2. 研究依据及取舍

| 原始研究 | 可借用之处 | 本设计的取舍 |
|---|---|---|
| [LongMemEval，§5.2–5.3](https://arxiv.org/html/2410.10813v2) | 实验中，把交互进一步压成孤立用户事实会损失信息；提取信息用于增强检索键，同时保留较完整的阅读材料，有不同效果 | 简短目录帮助找到材料，经历及来源负责保留背景；粒度在维度回放中验证，不照搬其“轮次”最优结果 |
| [Hindsight，§3.2–4.2](https://aclanthology.org/2026.acl-demo.27.pdf) | 区分保留、召回和反思；使用带时间与实体的叙述型事实 | 借用操作分工和有上下文的记忆单元；保留过程本身也调用模型，不能算零成本；不照搬其意见分数或人格设定 |
| [TeleMem，§2.1、§3](https://arxiv.org/html/2601.06037v1) | 叙述型内容、事件记忆，以及批量检索、归组和合并 | 借用减少碎片写入的方向；其流程仍包含逐轮摘要，不能据此声称本方案只需一次调用。文中中文角色扮演问答实验也不能验证真实个人建议 |
| [Mem0，§2.1、§4.4–4.5](https://arxiv.org/html/2504.19413v1) | 新内容与旧记忆比较后再决定增改；分别讨论检索回答延迟和记忆构建开销 | 测算整条链路，不能把回答阶段的 token 降幅直接当作维度每月总成本降幅 |

这些工作支持分开处理记忆写入、表示与使用。下面的事项生命周期、准入判断和预算调度是针对维度的设计综合，尚未经过本产品真实模型验收。

## 3. 一件事只有一个身份，可以有不同使用状态

### 3.1 三种逻辑视图

| 视图 | 内容与用途 | 退出或变化条件 |
|---|---|---|
| 当前事项 | 尚在考虑的选择、已决定的安排、相关约束及未解问题；支持继续讨论与近期协助 | 决定取消、事项结束、已过讨论窗口或状态需要重新核实 |
| 经历记录 | 当时处境、真实考虑的选项、本人理由、实际选择与后续反馈；支持回顾及未来比较 | 可降低默认检索优先级、合并重复表达；保留与删除遵循来源和用户设置 |
| 可复用认识 | 明确背景、自述偏好、经证据支持的条件性模式与方法；支持跨事项帮助 | 新事实、纠正、条件变化或反例触发修订 |

这不是三个新数据库，也不是一条事项复制三遍。当前与历史是同一事项不同时间的视图；可复用认识通过引用连接有关经历，不再复制整段故事。上游证据保持原有归属与读取接口。

“事项”是组织和查询单位，不要求增加通用的第四套节点类型。明确的选择沿用 decision；确有规划/行动和结果时才连接 action、outcome；没有显式选择的经历可以用已有来源摘要与 observation 承载。项目、目标、claim 等对象只在需要独立使用和修订时创建。

现有 decision 的 question、options、selected、rationale 可承接选择内容。状态、分阶段来源引用及跨来源事项身份仍需补充统一契约，不能宣称已有完整实现。这里的“经历记录”也不等于模型在原图谱定义外随意写入一个新 kind。

### 3.2 保留背景的最小表达

保留一段可核对的事件叙述，同时把已经明确、值得独立检索或修订的状态、目标、动机、预期和选择建立为语义对象及关系。叙述提供上下文，子图提供结构化读取；二者指向同一批来源。可读到哪些内容，就表达哪些内容：当时在解决什么问题，已知约束是什么，实际考虑或选择了什么，本人怎么解释，后续结果如何。

未知动机、未记录的备选方案、未发生的结果可以缺省；不能为了“背景完整”补造。选择理由尽量保留能改变解释的原意和关键措辞，有权限且仍可用时可继续回读原文。

只基于用户的旅游假设，测试记录至多能写成：

> 正在考虑下周是否出游，尚未决定，希望维度结合已有了解提供建议。当前材料未给出目的地、可用时间、预算或本人出游理由，后续结果未知。

这足以承接下一轮讨论。此时没有必要增加“探索欲强”“逃离压力”“P 型倾向”等判断。

这个最小叙述只适用于来源确实只有一句未决问题、且有关背景尚未找到的情况。不能把它规定为所有事项的最终存储形式；一旦本人理由、认知或有关背景已经可读，就应该在本轮表达相应语义。这里缺的是材料时补查材料，缺的是结构时补结构。

同一事项聊了多轮，只更新有意义的变化，并保留阶段来源。长事项可以有分阶段摘要和可展开的原文引用，不能不断重写一篇越来越大的总传记。索引、概况和摘要允许派生缓存，但不成为独立证据或另一份权威版本。

### 3.3 把四种时间分清

- 发生或预计发生时间：事情在什么时候发生，或计划何时发生。
- 当前适用时间：它在什么时候约束当前安排；“下周可能出游”有有限窗口。
- 记录与修订时间：维度何时获知、何时改正理解。
- 保留与可读期限：来源及其派生内容允许保留、查询到何时。

事项不再影响当前安排，不代表过去的事实不再成立，也不等于所有记录都应删除。反过来，历史可读不代表仍可以按“当前计划”使用。过了预计日期，只能更新其时效，不能自动推断旅行已发生。

源材料自然到期与用户主动忘记分别处理。允许长期保留的简短经历摘要可以独立于短期原文存在，但要标记只能核对到摘要；主动删除/排除按已有治理规则传递给受影响的派生内容、索引与缓存。不得复制原文绕过到期限制。

### 3.4 旅游示例：结构化一份当次认知—行为子图

为了展示完整结构，假设材料进一步包含以下话语。这些仍然是设计测试材料，不是用户的真实自述：

> 最近工作很累，想出去换个环境恢复精力。我觉得这样能缓过来，但周五有个重要交付，担心回来之后更赶。

可以形成以下语义对象。这里不是要求每段对话产生七个节点；已经存在且身份、时间和含义相符的对象直接引用。

| ID | 语义内容 | 沿用的对象 | 认识依据与范围 |
|---|---|---|---|
| D1 | 是否下周出游；考虑去/不去，尚未选定 | decision | 由原问题支持；本次决策 |
| S1 | 本人报告最近工作疲惫 | claim，fact | 关于本人自报状态的事实；近期，不是长期人格或客观健康评估 |
| G1 | 本次希望恢复精力 | goal | 原话明确的目标；它影响出游选项的关系表达本次动机 |
| C1 | 本人预期出游换环境能帮助缓过来 | claim，assumption | 本人表达的积极预期；不是出游效果已得到验证 |
| B1 | 本人报告周五有一项重要交付 | claim，fact；已有交付事项则引用 | 本次选择的背景约束；未独立核对日程 |
| C2 | 本人担心出游后交付准备的时间会更紧 | claim，assumption | 本人表达的风险预期；没有宣称一定迟交 |
| T1 | 恢复需求与交付准备之间存在待解决的时间取舍 | tension，可选 | 模型对上述关系的综合；本次资源权衡，不等于两种认知互相反驳 |

动机不只是给用户加一个“恢复”标签：G1 表达想达到的结果，G1 对 D1 中出游选项的影响表达“为什么考虑这个行为”。C1、C2 则表达本人怎样预期行为的收益和代价，属于当次的认知表征。它们已经是有价值的图谱内容，即使从未推广为稳定偏好。

关系需要保留作用对象及依据，不能把所有边都写成“相关”：

| 关系 | 含义及承接方式 |
|---|---|
| G1 → D1 | 沿 influences 表达动机，指明受影响的是“出游”选项；目标作为起点的领域语义需要正式补齐 |
| C1 → D1 | influences：本人预期的收益，有利于考虑出游 |
| C2 → D1 | influences：本人预期的代价，使出游需要更审慎权衡；担忧不等于最终否决 |
| S1 与 G1、B1 与 C2 | 作为本次背景引用；需要 claim-to-claim 背景关系时应正式定义，不能冒用 about 或事实因果边 |
| C1、C2 → T1 | 参与同一选择的权衡；两项判断可以同时为真 |
| 原话片段 → 各内容与关键关系 | 正式来源引用，按片段区分自述、背景与模型综合；同一来源不能计作多个独立证据 |

当前代码包含 goal、claim、decision、tension 等节点类型，以及 influences、tension_of 等关系处理，但这不等于上述语义契约已经实现。尤其 `relationship_evidence_role` 将 tension_of 统一映射为 contradiction；本例需要区分资源权衡与事实矛盾，不能用反证强度代替目标取舍。后续需补关系的语义角色、受影响选项和依据，或采用经过明确约定的权衡关系；本轮不改运行时代码。

每个节点应能独立表达以下信息，而非全部塞进 statement。字段命名是拟议契约，需要对齐现有 scope、payload、authority 和证据关联接口后实现：

- 对象身份、内容类型、认知持有者/被描述者、具体命题。
- 所属事项、适用情境与时间；本次有效、跨事项可用等范围。
- 认识依据：本人明确表达、系统从材料推测、外部核对等；它与写入者的 origin/authority 分开，不因模型抽取而伪造用户裁决。
- 来源身份、内容版本及片段；属于人的预期时，另保留预期是否经过结果验证。
- 与目标、选项及其他命题的关系、作用和依据；模型综合须可单独修订。

例如 C2 的逻辑记录可读成“持有者：用户；类型：结果预期；内容：若出游，回来后准备交付可能更赶；范围：D1；依据：假设原话中的担忧；效果验证：未知；对选择的作用：预期成本”。不需要先产生一个长期的“风险厌恶”节点。

只有原始短句时，先找同一时期的相关背景；来自旧经历的解释不能自动成为本次动机。若模型推测“这次可能是想恢复精力”，可保存为本次有依据的暂定解释，保留替代解释和待补条件，不假装本人已经说过。没有支持时就保留缺口，不为展示图谱而填满六模块。

后续的价值体现为图查询：找“以前为恢复精力尝试过什么”可以沿目标和选项定位 D1；找“哪些安排让我担心影响交付”可以从认知内容定位 C2；收到实际结果后，检验 C1/C2，并保持“本人预期已明确”和“预期后来是否成立”的区分。T1 是同一来源的综合，不为人格推断额外增加一份证据。

## 4. 什么进入知识库：按保留目的决定表示程度

“进入知识库”不再只有“写成长期结论/什么都不留”两个答案。

| 情形 | 建议保留方式 | 判断理由 |
|---|---|---|
| 正在讨论具体选择，可能继续跟进或影响其他安排 | 当前事项，保留已知条件与未决状态 | 忘掉后会使后续建议脱节，或把候选误当既定安排 |
| 已发生有意义的取舍、承诺、结果或反馈 | 有上下文的经历；必要时关联已有决策和结果 | 以后可以回顾为什么这样选，不必先证明它代表人格 |
| 一次少见但有明显选择空间或代价的经历 | 保留关键背景和可比较信息；解释可暂缓 | 可能有区分价值，低频不是删除理由；高代价也不自动证明某种特质 |
| 明确表达长期偏好、稳定背景或作出纠正 | 相应事实/自述/认识及适用范围 | 可以一次保存，不要求重复三次；自述偏好不等于行为已经验证 |
| 多项材料支持能改善帮助的新模式或修订 | 有依据、条件、反例及依赖的可复用认识 | 例如帮助判断何种安排更符合本人实际体验；不以术语数量作为价值 |
| 普通知识询问、助手列出的备选建议、随口举例、语义重复 | 原会话/来源中保留即可；一般不新增个人语义记录 | 没有新增个人状态、经历或可复用认识；建议被实际采纳后另行更新 |
| 信息可能重要，但材料尚不充分 | 必要的经历线索或待补问题 | 标记缺什么与重看条件，不把未读完的材料判定为无价值 |

这里的准入判断同时考虑：未来帮助的具体用途、相对已有知识的新增量、失去背景的代价、证据支持范围，以及维护和误用成本。模型用一句具体理由说明为什么这样保留，不计算一个看似精确的“记忆价值分”。

“未来可能用于人格分析”单独不足以支持给所有日常动作建节点。普通细节可留在来源；有真实选择、本人理由或反馈的完整事件更值得维护。事件目录可帮助日后发现尚未预想到的用途，不要求现在就预测所有未来问题。

这仍是有损取舍。没有被摘要保留、且原文已经到期的细节，未来可能无法恢复；不能承诺“到时候再分析”就一定找得到。验收要专门查看后来的重要问题因哪些遗漏答不好，据此调整背景保留与准入。减少节点和 token 只有在这些能力仍可接受时才算收益。

例子也要分清：“这次想找个安静地方”先属于本次需求；“以后给我安排旅行，尽量留半天自由时间”可以直接成为自述偏好。“我下周会出游”即使明确说过，仍表示本人报告的计划，不能等同于实际完成。

## 5. 用旅游走完整个过程

下表各分支均为假设测试，不补写用户经历。

| 阶段 | 读取与回答 | 写入或更新 | 不必要的处理 |
|---|---|---|---|
| 询问要不要去 | 找与下周相关的真实承诺、当前目标和可用约束，再找有关出游体验与偏好；材料不足时保持条件化建议 | 若需要跨轮承接，建/更新“是否出游”的未决事项；本轮没有新事实也可以不写 | 为产生建议先重算完整人格画像 |
| 讨论多个选项 | 回读刚才的条件，比较新选项的取舍；助手建议与本人选择分开 | 在同一事项记录新增条件、实际考虑过的选项和理由 | 每轮再抽六套分析、每个目的地都建长期兴趣 |
| 本人决定去、改期或不去 | 根据真实决定检查与其他安排的联系 | 更新该决定及影响范围；只有实际关系成立才关联其他项目/承诺 | 因为写了知识，就自动订票、挪日程或发送消息 |
| 日期已过但没有后续 | 查询时说明原计划已过期、结果未知 | 退出默认近期窗口；有价值且有材料可追踪时保留待回收项 | 推断“已经去了”，或天天追问结果 |
| 本人报告过程与感受 | 对照事前理由和实际反馈，帮助复盘 | 补本次经历和结果；必要时关联原决定 | 一次旅游满意就推断长期外向或冒险偏好 |
| 以后再问类似安排 | 读本次相关经历、最新约束，以及仍有效的偏好 | 只有产生新信息或修订时才写 | 将同一经历因多次被检索而累计成多份证据 |
| 以后讨论人格/行为方式 | 重新阅读有选择空间的独立事件、当时情境与反例，再选适用模块 | 有复用价值时记录条件性理解；否则本轮解释即可 | 仅用旅游话题标签解释人格，或把未知维度补成确定类型 |

一次旅游也可能真正影响后续工作：例如已确认的出行时间与同周已有承诺冲突。记录真实日期和关系，即可在查询该承诺时召回；不必先写出“旅游影响事业”的宏大解释。单纯说想出游时不能假定冲突存在。

## 6. 按问题解释，避免标签把理解固定住

### 6.1 分清找材料的索引与关于人的结论

“旅行、某时间段、某个同行者、相关项目”可以帮助定位。原文确实讨论了工作冲突时，也可以增加“休息安排与工作取舍”的检索描述。索引是可重建的导航，不是新增心理事实。

“喜欢冒险、回避责任、外向”则是需要另行论证的判断，不能藏在标签中绕过证据要求。若只有话题标签，之后询问“我通常如何取舍”可能找不到这次经历；因此检索要能从问题、背景和已有对象关系找到事件，并回读其内容。

当次动机和认知预期有来源时直接结构化：例如“希望恢复精力”“担心影响本周交付”都是可关联的内容，不属于必须延迟的长期特质推断。延迟的是尚无必要或证据不足的深层解释，并非延迟一切认知—行为语义。

### 6.2 分析只展开能改变答案的部分

给旅游建议，可能只需要当前约束、既往体验和决策取舍；解释为何计划屡次落空，才可能用到行为实施模块；对照事前预期与事后感受，才进一步使用反馈与变化模块。模型可以组合方法，也可以直接按已知事实回答。

补查顺序由缺口决定。已有认识有用时直接复用；新事情、争议或人格问题需要展开到经历和来源。发现材料反驳旧认识时，从事件重新理解，不让缓存结论决定能看到哪些证据。

本轮解释可以只服务本轮，不自动进入长期库。将一次解释持久化，需要另外判断是否有新增、证据和后续用途。对于同一问题反复使用的理解，可缓存一份带输入版本、范围和依据的结果；相关源、状态、纠正或访问范围变化时失效。模型的分析输出与用户新经历分开，不重复提炼自己。

## 7. 成本放在哪里，怎样节制

### 7.1 采用混合方式

| 方案 | 优势 | 主要代价 | 取舍 |
|---|---|---|---|
| 写入时全面分析 | 常见问题回答时可以直接使用整理结果 | 大量材料从未被再次使用；前置解释可能固化误判，变化后还要维护 | 不作为默认 |
| 只保留来源，全部查询时分析 | 写入简单，未来问题不受早期标签限制 | 可能丢失短期来源；重复找背景，跨会话响应慢 | 作为可回源能力，不独自承担长期理解 |
| 及时保留关键事件与变化，按需深化，选择性维护可复用认识 | 同时支持连续帮助、历史回顾和复用 | 需要正确的事项归属、增量进度与失效机制 | 本方案采用；收益需回放测量 |

### 7.2 默认运行策略

1. **优先复用已经读过的内容。** 在线回答已充分理解的明确新事实，可通过同一写入契约提交小的变更；后台只接未处理部分或需更广背景的问题。提交仍有工具、校验和输出开销，不当作免费。
2. **按事项变化合并工作。** 同一事项新增材料归入同一待办，携带上次读到的位置和输入版本。新决定、结果或纠正及时处理；普通补充可以合并整理。不能每轮调用一个模型筛选器，再让另一个模型从头读取。
   本轮可以一次生成必要的节点、关系与证据引用；语义节点数不等于模型调用次数。复用已有对象，只提交新增或变化部分。不能为了减少节点而把有价值的动机、认知与关系全部压回无结构摘要。
3. **定时检查队列，模型只做有工作的一轮。** 没有新材料、依赖变化或到期待办时，不产生新模型调用。每天综合维护也只处理有理由重看的范围，不定时重读全库。时钟检查和权限过滤仍有程序开销。
4. **保留主动发现能力。** 近期重要选择、未解决矛盾和新结果优先；同时给积压材料、少见经历及尚未充分覆盖的场景轮转机会。不能只凭访问频次排序，形成“越被使用越被记住”的循环。
5. **限制重复阅读和表示膨胀。** 先查目录及有关变化，需要时展开来源。同一证据在多条关系下只读必要一次；概况增量维护。已有结果的输入版本未变且仍适用时直接复用，不反复生成同义洞察。
6. **按能力和实测成本选模型。** 只有经过回放验证的状态整理、范围明确的提取，才考虑交给成本较低的模型；重要歧义保留待理解或交给更适合的模型。较弱筛选器不应永久删除未来证据。

这些是调度和阅读策略，不给认知模块硬设“最多思考多少字”或“最多两轮”。用户显式配置后台预算时，优先保住当前协助和正确状态；预算不足的分析有进度、下次继续。明确纠正、忘记和失效标记先执行必要的程序更新，不能等待有预算重写画像才阻止误用。未配置预算时，不凭空引入隐藏产品限额。

### 7.3 旅游案例的开销应该怎样变化

首次提问的主要工作是相关知识检索与回答；是否保留未决事项可以随本轮处理。后续只补新增条件和决定，不每次重算人格。没有新消息的日子，不为这次旅游重复分析。事后有真实反馈时，才更新经历及受影响认识。未来问到类似事情，再支付必要的比较分析成本。

原文十轮对话不意味着十份记忆或六十次模块调用；合并也不承诺整件事永远只要一次调用。真实调用次数取决于背景缺口、重试、新材料及用户需要，必须记录。

对某项反复使用的理解，可以用下式判断预先整理的经济性：

`后续查询次数 × 每次少做的分析成本 > 首次整理成本 + 后续维护成本`

这是在帮助质量相当时的核算方式，不是自动准入公式。长期反复使用的决策偏好可能值得提前整理；一次普通旅游的深层解释通常可以推迟。低频但重要的事件仍能保留经历，在真正需要时分析。

### 7.4 费用必须覆盖完整链路

按每个实际计费请求归集到：材料整理、关系/认识维护、检索辅助与重排、在线回答；失败及重试也记入所属环节。另列索引、工具与存储开销。记录模型与价格版本、实际输入输出、缓存信息、耗时、事项/工作项、成功或失败，以及知识读取/提交版本。

`总成本 = 所有计费调用的实际费用之和 + 索引、工具和存储费用`

不同供应商的输入、缓存与推理 token 字段可能互相包含，按对应计费口径换算，不能把所有字段直接相加当成账单。未知费用与缺失 usage 标成未知，不能记为零。不要用一次成功回答的 usage 代表整个后台服务。

当前代码已存在 [RunUsage](../../services/agent/src/types.ts)，[dshRuntime.ts](../../services/agent/src/runtime/dshRuntime.ts) 汇总会话消息的 usage 并合并呈现阶段 usage；[HistoryService](../../services/agent/src/history/historyService.ts) 也已有活动记忆的轮询、批量挑选和五分钟节流。它们可以作为接入点。本轮没有核实所有失败/重试的计费覆盖，也没有运行真实流量成本评测，不能报告月费或节省比例。首版先把费用按事项和工作阶段串起来，再决定预算与模型分工。

## 8. 如何验证取舍是否正确

用相同授权材料与时间顺序，对比“逐条事实提取”“每件事全面六模块分析”“本方案的事件保留与按需理解”。完整报告各方案实际成本；再在相近预算下比较帮助质量，避免把模型或预算差异误算成架构收益。

| 验收问题 | 通过的表现 |
|---|---|
| 第二天继续问旅游 | 找到仍未决定的事项及讨论过的条件，无需用户重述 |
| 改期或取消后讨论工作 | 使用最新状态，不继续扣减已释放的时间 |
| 日期过了但没有结果 | 保持结果未知，不编造完成，也不把旧候选常驻当前概况 |
| 几个月后问当时为什么这样选 | 能找到当时背景、本人理由和可用依据，而不只剩抽象偏好 |
| 同一选择聊十轮、被读取多次 | 更新同一事项，不产生十份独立人格证据 |
| 询问行为模式 | 能找来自不同情境的独立事件和反例；不局限于已贴某标签的材料 |
| 本人明确新的长期偏好 | 一次即可保存为有范围的自述，且下次相关建议可以使用 |
| 大量普通问答夹着一次重要决定 | 重要事件仍可召回，不被高频闲聊或访问记录挤掉 |
| 无变化/预算暂停/中断恢复 | 无重复模型工作；未处理材料有明确进度，不假装完成 |
| 来源删除或本人纠正 | 相关视图、认识、索引与分析缓存遵循新状态 |

同时测关键背景召回、信息遗漏、错误泛化、时效错误、需要重复说明的次数、实际费用与延迟。能查出一条记录只是中间结果，还要看最终建议是否因这些背景而更有帮助。

后续问题从未用于写入提示词调优的材料中抽取，并加入临时状态、罕见事件和跨情境比较；历史测试不能提前读取未来反馈。自动评测用来源核查与典型样例复审约束，不让模型给自己打“像不像用户”的分数。

本方案的实施边界是知识治理：事项归属、准入与生命周期、按需解释、统一读写、增量调度及成本账目。用户界面可以呈现“正在考虑”“过去经历”“目前的理解”，不把模块编号、模型调用数和心理学标签变成每次正常对话的操作要求。
