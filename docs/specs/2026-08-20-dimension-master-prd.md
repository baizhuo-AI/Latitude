## 1. 产品定义

> **维度是一个 AI native 产品：以「认知突破 + 行为管理」为理论内核，提供有限的积木和生长语法，让每个用户在日常交互中长出属于自己形态的成长系统。**

这个定义包含三个互相咬合的身份，缺一不可：

| 身份 | 回答的问题 | 对应的系统能力 |
|---|---|---|
| **第二大脑** | 「谁替我记住并理解我的现实？」 | 感知 → 理解 → 执行的完整回路（§3.2） |
| **成长伙伴** | 「谁帮我把想明白的事变成做出来的事？」 | 认知—行为闭环与共创机制（§4、§5.3） |
| **可生长的个人 OS** | 「为什么它是我的，而不是又一个通用工具？」 | 布局即数据 + 生长语法（§3.1、§5.2） |

**核心差异**：不是「首页有几张卡」，而是**首页能随用户成长出不同结构**。固定形态的工具在第一天就决定了它永远是什么；维度在第一天只决定种子和物理规则，形态由使用长出来。

### 1.1 目标用户

**时代处境**：AI 飞速发展，环境动荡，旧的路径与判断以前所未有的速度失效——每个人都被迫频繁地重新想清楚「我该信什么、该做什么」。这个时代真正稀缺的，是**有一个人陪你一起理清思路、稳步成长**。维度要做的就是这个「一个人」。

落到具体画像：有明确自我提升需求，正处于学习迷茫、事业过载或生活瓶颈的个人。共同处境一句话：**信息很多，判断却没有变清楚；日子过得很快，却说不出自己变了什么。**

他们带着三个未被满足的需求来，也带着三个明确的「不要」：

| 需求 | 现有工具的缺口 | | 不要 |
|---|---|---|---|
| 被「接住」每天冒出的想法和承诺 | 备忘录记了等于埋了 | | 不要又一个信息流 |
| 知道自己在怎么想、有没有变化 | 日记靠自律，没人帮看模式 | | 不要打卡式自律工具 |
| 让想明白的事变成做出来的事 | todo 只管执行不管为什么 | | 不要滔滔不绝显得很懂他的 AI |

产品的一切克制设计（留白、宁缺、低频点亮、不追问）都是对三个「不要」的直接回应。

### 1.2 定位约束

- 不是心理陪伴产品，不做临床诊断，不承诺读心；识别到持续情绪危机时明确说出边界并建议真人求助。
- 伙伴关系是交互方式，不是产品目的；聊天时长、情绪依赖、关系数值不作为任何目标。
- 项目以**开源**形式公开；隐私采取最高标准（§6.2）。

**术语约定**：本文档及全部子文档中的「桌面」均指**维度应用内的主面板**（应用桌面 / OS 面板），与操作系统的电脑桌面无关；「桌面应用」指承载它的 mac 客户端程序。

## 2. 理论内核

理论的使用纪律：**每条理论必须落成一条可检查的设计约束；落不成约束的理论是装饰**。理论术语止于代码与文档，绝不出现在 UI（§4.6）。

| 理论 | 落成的约束 | 生效位置 |
|---|---|---|
| 协作经验主义（Beck, CBT） | 认知结论必须由用户参与得出；系统单方面生成的「洞察」不写入 | 共创流 §5.3 |
| 苏格拉底式提问（CBT） | 候选以问句呈现，不下结论 | 候选协议 §5.3 |
| CBT 行为实验 | 实验必备：假设 / 触发 / 成功信号 / 停止条件；结果三分类（证实/限制/证伪） | 行为实验 §4.1 |
| 双环学习（Argyris）+ Kolb 学习圈 | 「换了做法」与「改了看法」是两级成长，分开呈现 | 回顾与叙事 §5.4 |
| 双钻模型（发散—收束 × 2） | 内容按认知/行为各一次发散收束组织 = 四象限 | 内容体系 §4.1 |
| Toulmin 论证模型 | 认知沉淀的完整结构：判断/证据/推理链/适用边界/反证；字段可缺失但不硬填 | 认知结构 §4.4 |
| AGM 信念修订 | 修订区分收窄（contraction）与推翻（revision）；旧认识不硬删 | 图谱设计 §5 |
| Grice 合作原则 | 只在有信息量时发言；出场资格 = 对这个用户这个情境的特异性 | 出场资格 §4.3 |
| 事件边界效应 + AAR 传统 | 复盘邀请挂事件完结点，不挂固定日历 | 节奏 §5.4 |
| 混合主动性交互（Horvitz） | 不确定性 × 打扰成本决定自动/提案/共创三档 | 生产方式 §4.2 |
| CQRS + COPE | 领域事实一次生产，多投影消费；禁止读侧双真相源 | 数据架构 §3.3 |
| Pace layering（Brand） | 外壳（慢）/骨架（中）/内容（快）分速率变化 | 桌面治理 §5.2 |
| Second Brain（Forte, CODE） | 采集→组织→提炼→表达四段齐备；缺执行段则退化为第二仓库 | 回路 §3.2 |
| Papert 建构主义 + Alexander 模式语言 + HyperCard 传统 | 给生成语法不给成品蓝图；建筑师内置为 AI；结构可生长是 OS 与小组件市场的分界 | harness §3.1、布局 §5.2 |
| Wizard of Oz 原型法 | 引擎建成前由人扮演验证体验；跑通的协议即 spec | 实验 §7 |

## 3. 系统架构

### 3.1 Harness 四层

| 层 | 是什么 | 谁能动 |
|---|---|---|
| **物理规则** | 见 3.1.1，不可让渡的五条 | 谁都不能动 |
| **积木** | 有限原语集：速记、check-in、资讯条目、候选、认知沉淀、行为实验、日程、周回顾、提醒、留白规则，以及**渲染积木**（native / declarative / **自由 HTML** 三档渲染能力——HTML 是内部积木，不是插件）……各有输入输出契约 | 产品方定义与扩充（含插件 §3.4）；用户选用组合 |
| **生长语法** | AI 观察使用摩擦与用户表达 → 形态变更提案 → 用户裁决 → 配置变化，留痕可回滚 | AI 提案，用户裁决 |
| **种子形态** | 所有人从同一个最小默认配置开始（§8.1） | 产品方定义 |

关键机制：**用户从头到尾不「配置」，AI 当园丁**——可塑软件研究的结论是不到 10% 的用户会主动配置任何东西；维度把建筑师内置成 AI，用户只对生长提案点头摇头。生长语法的铁律：**只响应有记录的用户摩擦或原话，不发明形态创意**；每次变更可指回触发它的用户行为。

产品形态的生长和认知的生长共用同一套「提案—裁决」语法（底层同一套 Proposal / Change Set）。

#### 3.1.1 物理规则（不可让渡）

1. 一切认知结论可追溯到证据；无证据的推断必须标注为推断。
2. 写入长期记忆/认知模型前必须经用户确认（确认的**形式**可经显式授权降低，可追溯性不可）。
3. 所有形态与内容变更留痕、可回滚。
4. 拒绝与沉默是有效数据，不惩罚、不追问超过一次。
5. 用户数据可全量导出、可彻底删除。

用户请求突破 1/2 时，路由到权能授权流程，而非直接答应或拒绝。

### 3.2 第二大脑回路：感知 → 理解 → 执行

| 段 | 内容 | 形态 |
|---|---|---|
| **感知**（被动优先） | 主动最小集：速记、对话、check-in（内建）。被动通道：录音胶囊（AI Listener 项目）、电脑使用轨迹（computer history） | 被动通道为**感知插件**，非必选；默认关闭、显式开启、纯本地处理、可彻底删除 |
| **理解** | 认知—行为图谱：记住、连起来、看出模式 | 内建（§3.3） |
| **执行**（手的梯子） | 维度是大脑和秘书，Claude Code / Codex 等 agent 是手；维度把「你想要什么」翻译成「手能执行的指令」 | **执行插件**，按权能四档解锁（下表） |

执行的四档梯子（权能显式授予，逐级解锁）：

| 权能档 | 执行形态 |
|---|---|
| 只建议 | 告诉你怎么跟手说（措辞建议） |
| 代我准备 | 起草完整指令与上下文包，你过目后自己发 |
| 执行前确认 | 维度直接调度，dispatch 前给确认单 |
| 低风险自动执行 | 白名单任务自动跑，全程进行动账本，可查可撤 |

### 3.3 数据架构

- **写模型**：认知—行为图谱（本体、状态机、修订操作的唯一权威见[图谱设计](2026-08-20-dimension-cognitive-graph-design.md)）。
- **读模型**：桌面内容、周回顾、养成时间线是同一批领域事实的**投影**。投影只准读领域层，禁止投影间互读、禁止绕过领域层拼数据。
- **设计方法**：内容契约夹逼——每个内容单元定义 payload、来源实体、出场资格、生命周期；用契约反向验收领域模型，没有消费者的表推迟建。

### 3.4 插件模型

**插件是维度的器官**：感知是眼睛和耳朵，通道是嘴巴，执行是手。维度**带感官出生**——出厂自带默认器官（微信嘴巴、速记耳朵），完整体验依赖器官在位；器官可替换、可增强、可关闭，但它们不是「裸核之外的增值包」。三类器官插件共用同一套授权与行动账本：

| 器官 | 插件类型 | 例子 | 接入契约 |
|---|---|---|---|
| 眼睛和耳朵 | 感知插件（证据源） | 录音胶囊、computer history、速记通道 | 产出 evidence（带来源与隐私等级）；高敏感知需显式授权开启。首个高价值场景：**承诺检测**——从通信内容里抓「你答应了别人什么」，经提案档一键确认进日程（带原文血缘），帮用户记住容易忘的承诺；这也是 computer history 值得开启的直接理由 |
| 嘴巴 | 通道插件（对话窗口） | 微信、飞书 bot | channel adapter：共享会话与秘书核心 |
| 手 | 执行插件 | 调度 Claude Code / Codex | 消费权能授权，每次执行写行动账本 |

（自由 HTML 模块**不是插件**，是积木层的内部渲染积木——OS 生长的核心能力不能是可选件；其安全边界为 ModuleManifest + Capability API + 沙箱，工程规格见工程实施计划 §4。第三方积木包未来经插件机制分发，复用同一安全边界。）

插件是积木层的扩充机制，也是开源生态的接口面：核心保持小而稳，器官靠插件长。

## 4. 内容体系

### 4.1 四象限：认知—行为循环的外化

认知—行为是内核，外化到桌面是四类内容（双钻：认知、行为各一次发散—收束）：

排列按生活时序（不严格，取其顺）：先打开认知，把今天过掉，把经历理清，再定下一步——

| 象限 | 职能 | 内容 | 频率 |
|---|---|---|---|
| **资讯**（认知·发散） | 打开认知 | 挂靠当前认知张力/实验的异质视角、反例、新材料 | 每日 ≤3 条，宁缺 |
| **日程**（行为·收束） | 执行 | 今日 3-5 件时间锚定安排，实验/规划来源带血缘标 | 每天 |
| **复盘**（认知·收束） | 把经历梳理成清晰的规划和道路 | check-in + 共创流 + 深聊；显性产出是**下一步的规划与路径**，认知修订自然沉淀 | 事件触发 + 每周兜底 |
| **规划**（行为·发散） | 打开行为选项 | 从认知修订/目标推出候选动作与行为实验设计 | 每周 / 事件驱动 |

**血缘链路是四象限的灵魂**：资讯被引进复盘 → 复盘产出认知修订 → 修订触发规划 → 规划生成日程条目 → 执行结果喂回复盘。桌面上任何一张卡可回溯上游——这是认知—行为图谱的用户可见形态，也是「为什么这样排」解释层的数据来源。

**资讯象限的反茧房硬约束**（写进代码，不靠 prompt）：日上限 ≤3 条、无合格内容就空着；每条必须挂靠活跃张力并展示「为什么给你看」；异质性优先（与既有立场不同的来源加权）；反馈三键回灌策展，连续「没用」自动降频。

### 4.2 三档生产方式（与四象限正交）

| 档 | 生产方式 | 用户角色 | 典型内容 |
|---|---|---|---|
| 自动 | 系统独立生成，不需确认 | 扫一眼 | 资讯策展、节奏类、日程日常项 |
| 提案 | 系统生成，用户批准/拒绝 | 点头摇头 | 建待办、调触发器、记偏好、形态变更 |
| 共创 | 共创流中对话产出 | 共同作者 | 认知沉淀、行为实验 |

### 4.3 出场资格与留白

- 出场资格的可判定标准：内容必须对**这个用户、这个情境**有特异性——换任何人任何一天都成立的句子不配上桌面。
- **留白是正式内容**，不是空状态兜底：「今天没什么特别想说的」要说得体面、笃定、不带歉意。一个总在说话的系统等于没有判断力。

### 4.4 认知沉淀：低调外化

成长是结果，是交互间的认可，不是要完成的任务。认知沉淀（内部为完整 Toulmin 结构）的外化只有两种姿态：**对话里的一句轻确认**（「这次想清楚了一件事：……」）和**小角落的正循环提示**（「这周想清楚了 2 件事」，带数量、点开才见完整结构）。不做显眼大卡。

### 4.5 候选大胆度：四因子

> 大胆度 = 证据充分度 × 领域敏感度 × 用户偏好 × 当次许可

- 证据充分度是基础门槛；
- **领域敏感度是硬闸**：亲密关系、健康、心理等高敏领域，熟悉再深也不擅自下判断（最多最轻问句或等用户先开口）；
- 用户偏好（直说/委婉）可设置、可被形态提案调整；
- 当次许可即时生效：「你直说」临时放开，「这个别碰」立即归零并记住。

熟悉阶段只是用户偏好的先验之一，不是门。实施前置物料：领域敏感度分级表（进 P0 词汇冻结）。

### 4.6 外化语言原则（双层语言制）

理论术语止于代码与文档，UI 文案一律日常语言。默认语言的基准测试：**通俗易懂**——一个没读过任何文档的人能不能秒懂这句话；不追求风格化。文案评审逐条读出声，作为验收项。

**语言人格是可生长的**：有人想要朋友，有人想要秘书，有人想要教练——称呼、语气、亲疏是形态生长的一个维度，由用户的表达和形态提案逐渐长出来，不做统一人设。原生默认只保证中性、通俗、不装。以下对照表给的是默认中性版：

| 内部术语 | 用户看到的 |
|---|---|
| 认知卡 / 被挑战的判断 | 「你好像一直觉得……」 |
| 支持证据 / 反证 | 「这么想的理由」/「不过也有例外」 |
| 适用边界 | 「什么时候不是这样」 |
| 验证动作 / 行为实验 | 「要不试试」/「这周试个新做法」 |
| 共创回合 / 深聊 | 「聊聊最近」 |
| 裁决 | 「有点意思 / 不太对 / 先放着」 |
| 候选观察 | 「我注意到一件事」 |
| 形态变更提案 | 「要不要把这里改成……」 |
| 留白态 | 「今天没什么特别想说的」 |

## 5. 交互体系

### 5.1 载体与触点

| 载体 | 角色 | 承担 |
|---|---|---|
| **桌面应用**（Tauri，mac 先行） | 核心 | 四象限桌面、共创完整形态、血缘与展开态、周回顾、养成时间线 |
| **微信**（官方 iLink Bot API） | **主交互窗口** | 移动场景主入口：速记、check-in、候选推进、轻量裁决；搭建第 1 周 spike 验证，失败零成本回退飞书 |
| **飞书 bot** | 备用窗口 | 与微信同能力；管道现成 |
| 应用内对话条 / 悬浮条 | 常驻 | 随时说一句、发起深聊、用自然语言改桌面 |

所有窗口经 channel adapter 共享同一会话与秘书核心；新通道只加 adapter 不动核心。设置不在桌面上；桌面是唯一常驻界面，工具（Todo/Calendar/目标等）只能从卡片下钻进入并原位返回。

### 5.2 桌面：布局即数据

**渲染架构（冻结）**：桌面从第一天起是**布局文档 + 渲染器**——若先按固定 React 开发、后挂自由 HTML，终局只会是小组件市场。布局文档分三层，每层可编辑、编辑走生长语法，对话条「让她改动这张桌面」是三层的自然语言编辑入口：

| 层 | 内容 | 种子默认值 |
|---|---|---|
| 背景 | 画布样式（底色/纹理/密度/主题） | 纸张语言 token |
| 卡 | renderer（native/declarative/html 三档预留）、尺寸、数据绑定 | 九种卡型，native |
| 排布 | **规则而非坐标**：具名策略 + 参数 | 「占比跟随使用频率」 |

**种子布局**（占比跟随使用频率）：上排 `5`（资讯，首位，早报心智）+ `7`（日程，最大格，最高频交互）；下排 `4+4+4` = 复盘·规划（低频小区，平时安静、点亮时升起回合邀请/规划产出）+ 节奏（闸门/时长/锚点）+ 弹性格（提案优先 > 待抉择 > 留白）。

**治理规则**（与渲染能力分层）：骨架恒定、单次最多换一个格子、变化有理由可撤销——这是种子形态的行为约束，由生长语法管理，不是渲染器的能力上限。视觉规格（纸张色板、等宽标签、无阴影等）见前端 PRD §8。

### 5.3 共创流：异步状态机

**共创不是必须出席的周会。** 候选是最小推进单元，任一触点可推进一步，跨天续接：

```text
proposed（我注意到一件事……）
  → touched（回一句：有点意思 / 不太对 / 先放着）
  → shaping（跨天跨触点补证据、聊边界）
  → concluded（产出：下一步的路——规划条目/小实验进日程带血缘；
               认知沉淀轻确认；或一次被记录的纠正）
  → parked（先放着，到期自动收起）
超时：proposed 3 天无响应静默收起（算触达数据）；shaping 停 7 天轻问一次，之后不再问
```

**深聊模式**是可选加速器：攒了 ≥2 个推进中候选或实验出结果时邀请一次 ≤15 分钟完整对话；拒绝照常走异步。**结果回收**独立存在：验证动作到期时单独问一句（或并入最近一次 check-in），结论三分类回写认知。

### 5.4 节奏与打扰预算

- **check-in 不做每日打卡**：事件触发（大日程/实验完结时顺势问「那件事办完了？感觉如何」）+ 每周一次兜底。「大事」判定：带血缘条目完成或用户标星日程完成。想每天被问的用户，经形态提案自选长出——生长语法的第一个天然用例。
- 日循环 ≤10 分钟（早扫桌面 / 随手速记 / 晚默认不打扰）；周循环 = 候选异步推进 + 周日回顾一页；月弧 = 养成时间线回看（哪些认识变了、哪些实验做了、桌面长成什么样）。
- 周回顾区分双环：「换了做法」和「改了看法」分开呈现。
- 完整旅程（第 0 天冷启动 20 分钟引导对话、关键信任时刻、反旅程防线）见旅程 PRD。

### 5.5 养成系统（关系养成）

- **命名规范**：关系养成是系统名；可计算的只有三参数——**熟悉**（覆盖度与新鲜度）、**默契**（对判断与取舍的校准度）、**权能**（显式授予的行动范围）。「关系」本身不做数值。
- **回报是行为变化不是数值**：熟悉阶段（初见→看见模式→懂处境）决定行为基线（初见只问不判断；懂处境才引用几周前的速记）；受托是权能状态，与熟悉无关。
- 物理规则：任何成长由具体事件驱动、可点开解释；权能绝不随好感自动升级；无签到、无连击、无「今天还没和我说话哦」。
- 外显默认展示阶段名与证据，不展示裸数值；参数外显与阶段系统属 P4，实验期只做在场感、纠正复述、回合尾声「懂你一句」。

## 6. 边界与原则

### 6.1 反旅程防线（摘要，全表见旅程 PRD §10）

刷资讯成瘾（日上限写死、无无限滚动）；只当 todo 工具用（允许，按月轻提示一次）；认知当鸡汤读不行动（回收优先于新候选）；讨好式裁决（秘书主动示弱邀纠正）；形态折腾癖（单次一变更、可回滚）；情绪依赖（不承担治疗角色，危机时建议真人求助）。

### 6.2 隐私与开源

- 一切生成与存储纯本地，各自引擎 key，无遥测、无服务端；通道传输例外（IM 消息过服务商服务器）在知情同意中写明。
- 高敏感知插件（录音、computer history）默认关闭、显式开启、纯本地处理、可彻底删除。
- 项目开源；开源卫生审计为硬门禁（个人录音/转写/密钥绝不入库，含 git 历史扫描）。
- 数据一键导出（指标层 + 可删减的内容层）、一键彻底删除。

### 6.3 全量愿景，分批交付

**没有「不做」，只有「什么时候做」**（2026-08-20 拍板：不怕工期，都做）。认知图谱是底层，养成外显、权能系统、模块运行时、配置能力都是体验核心，全部在路线上：

| 能力 | 批次 | 说明 |
|---|---|---|
| 简化六表 → 认知图谱全量 | 种子实验用六表验证闭环；P0-P1 建全量图谱 | 图谱是一切上层体验的底层 |
| 自由 HTML 渲染积木 | 架构承诺第一天给足（布局即数据）；渲染能力 P5 点亮 | OS 生长的核心能力 |
| 养成参数外显与阶段 | P4 | 实验期先攒评分规则的真实样本 |
| 权能完整系统与执行调度 | P4 之后开「执行前确认 / 自动执行」两档 | 实验期先开「只建议 / 代我准备」 |
| 配置引擎（形态提案的自动落地） | 实验期人肉 YAML（WoZ）；正式版自动化 | 生长语法先验证再自动化 |
| 想法地图（图谱可视化） | P1-P2（图谱建成后） | 「看见自己认知结构」的直接体验；开源传播亮点；实验期导出图谱 JSON 先行 |
| 深色模式、更多通道、第三方积木分发 | 生态批次，按需 | 不阻塞核心 |
| 多租户账号体系 | 长期不做 | 个人产品，一人一份数据 |

**提示词与规则的修改不是禁区**：开源产品的提示词本来就可见、可改。约束只有一条——修改走生长语法（提案 → 裁决 → 留痕 → 回滚），**不允许的是模型静默自改**。schema 变更同理，走迁移与版本。

## 7. 验证计划

九条可证伪假设（指标与放弃线全表见 harness 实验设计 §4）：

| # | 假设 | 一句话 |
|---|---|---|
| H1 供给 | 真实数据能挖出「我没这么想过」的候选（≥1 条/周/人） |
| H2 协议 | 共创流有人持续参与（≥50% 候选 7 天内闭环） |
| H3 转化 | 认知变成真实行动（≥50% 产生被执行的验证动作） |
| H4 修订 | 行动结果反过来改认知（回收 ≥50%，每人 ≥1 次修订） |
| H5 证据层 | 纯对话+速记足以支撑候选挖掘 |
| H6 留白 | 「没什么可说」增加而非消耗信任 |
| H7 分化 | 不同用户长出有意义差异的形态（实验期测配置层） |
| H8 收敛 | 形态趋稳而非永远折腾 |
| H9 资讯 | 挂靠张力的异质资讯有真实价值（≥30%「有新角度」） |

**实验设计**：运营者 + 2-3 名共建者（全 mac、符合画像），搭建 3.5-4 周 → dogfood 1 周 → 冷启动 3 天 → 运行 3-4 周 → 按假设结账。数据回收 = 每周两层导出包（指标层 + 可删减内容层）+ 访谈，无遥测。WoZ 阀门：出场资格代码化 + 共建者标废话 + 周审计。北极星时刻：First Useful Breakthrough——第一次「我没这么想过，而且愿意试」。

## 8. 实施路线

### 8.1 种子产品范围

桌面 app（四象限种子布局 + 布局文档最小渲染器 + 共创流 + 周回顾）+ 微信主窗口（iLink，spike 先行）+ 飞书备用 + 简化 schema 六张表（evidence / candidates / cards / actions / outcomes / feed_items）。执行能力只开「只建议 / 代我准备」两档（对话自然能力）。

### 8.2 路径（详表见 harness 实验设计 §7）

开源卫生审计与知情同意（1 天）→ 布局文档 schema + 最小渲染器 + 种子桌面（6-7 天，微信 spike 2-3 天并行）→ 内容管道与出场资格代码化（5-6 天）→ 回合状态机 + 导出 + 周回顾（3 天）→ 打包分发（2 天）→ dogfood 1 周 → 共建者进入。

### 8.3 与工程批次的关系

本实验是 pre-P0 发现轨（批次全表见[工程实施计划](../plans/2026-08-20-dimension-implementation-plan.md) §3）。结账后回填：P0 契约（warrant、contraction、领域敏感度分级、内容契约）、内容架构定稿、PRD 修订；H7/H8 证伪则 harness 定义回退，产品退为固定形态。P4（权能）之后开执行插件的调度档；P5 做模块运行时与想法地图；P6 接感知插件。
