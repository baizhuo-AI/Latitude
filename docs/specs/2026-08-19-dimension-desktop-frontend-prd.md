>
> **v3.1 → v3.2 的变更**：认知卡**低调化**（成长是结果，不是要完成的任务）——认知沉淀不做显眼大卡，外化为对话里的轻确认 + 复盘·规划格的小角落正循环提示（「这周想清楚了 2 件事」），点开才进展开态；复盘·规划格的点亮内容改为「回合邀请 / 新规划产出」。
>
> **v3.2 → v3.3 的变更**：共创**异步化**——候选单条出现、回一句即算推进、跨触点续接；深聊是可选加速器。秘书栏阶段标签挂在具体参数（熟悉/默契/权能）上、默认展示阶段名而非裸数值（设计稿的「默契 · 74」为占位示意）。
>
> **v3.3 → v3.4 的变更**：渲染架构冻结为**布局即数据**——本文档描述的桌面五区与四象限格子是**种子布局文档的默认值**，由渲染器解释执行，不是硬编码页面结构；自由 HTML 模块是 OS 面板成长的核心能力（安全边界沿用重构计划 §6.1），实验期渲染器做最小版。
>
> **v3.4 → v3.5 的变更**：布局文档定为**三层结构**——背景（样式）/ 卡（大小与内容）/ 排布（规则而非坐标），每层可编辑、编辑走生长语法；对话条「让她改动这张桌面」即三层的自然语言编辑入口。
>
> **v4.0 → v4.1 的变更**：秘书立绘资源项关闭——同一角色提供 `READY / THINKING / PRESENTING` 三张透明姿态；生长不做字面年龄变化，也不合成「关系分」，而由熟悉 / 默契 / 权能分别控制体量 / 微动 / 已授权工具。
>
> **v4.1 → v4.2 的变更**：三个运行状态各扩展为三个有明确语义的动作，共九张同身份立绘。动作由当前运行语义确定，禁止为求“灵动”而随机切换；非法或缺失动作回退到该状态的默认动作。熟悉 / 默契 / 权能的正交生长映射不变。首批资源中四张为真实透明 PNG，五张为暖纸底 PNG；固定浅色秘书栏可直接使用，离开纸张主题前再统一为 alpha。

## 0. 这份文档是什么

> **术语**：本文档中「桌面」均指**维度应用内的主面板**（应用桌面），与操作系统的电脑桌面无关。

定义维度桌面化之后，前端**完整需要哪些界面、它们之间怎么连、哪些边缘状态必须设计**。

**不是**：后端设计、认知模型算法、卡片内容的生成逻辑。「今天该出现哪几张卡」由 [harness 实验设计](2026-08-19-dimension-harness-experiment-design.md) 的内容架构回答（四象限职能 + 三档生产方式 + 出场资格）。

**范围**：一次外壳级替换。现有左侧功能导航（早安 / 待办 / 日历 / 记录 / 对话 / 目标 / 秘书 / 连接）全部不出现。新代码从零写。

## 1. 用户在这个产品里的十种状态

前端的完整性不由「画了几个页面」决定，由「用户可能处于的状态是否都有落点」决定。

| 状态 | 用户在干什么 | 落点 |
|---|---|---|
| 日常 | 打开看今天摆了什么 | **桌面**（主界面） |
| 追问 | 这张卡凭什么出现？证据呢？ | **展开态** |
| 回顾 | 这一个月我到底变了什么 | **养成时间线** |
| 处理具体事 | 改个待办、看日历排期 | **工具下钻** |
| 调整 | 这张卡我不要 / 换个排法 | **调整桌面** |
| 首次打开 | 系统还什么都不知道 | **第 0 天** |
| 无事可说 | 今天确实没有值得重看的判断 | **留白态** |
| 被请求授权 | 秘书想代我做一件事 | **授权请求 + 权能清单** |
| 配置 | 换模型、改隐私、连微信 | **设置**（不在桌面上） |
| 共创 | 对一个候选回一句、改天再续两句；偶尔接受一次深聊 | **共创流**（异步，桌面/微信任一触点可续接；深聊为可选对话态） |

十个状态，五个界面 + 一个对话态 + 四个边缘状态。设计稿只画了第一个。

## 2. 导航模型：桌面是唯一入口

设计稿拿掉左侧导航，拿掉的不是「所有导航」，而是**按数据类型分的功能入口**。那种导航要求用户先回答「我现在该看哪一页」—— 把系统的内部结构推给用户。

替代它的不是另一根导航栏，而是：**一切从桌面上的元素点进去。**

```text
                    ┌─── 桌面（唯一常驻界面）───┐
                    │                          │
        点卡片 ─────┤  卡片网格                 ├───── 点「为什么这样排」
          │         │  秘书栏                   │            │
          │         │  对话条                   │            ▼
          │         └────────┬─────────────────┘      ┌──────────┐
          │                  │                        │ 解释层    │
     ┌────┴────┐        点秘书栏底部                    │ 出现理由  │
     │         │             │                        │ 证据链    │
     ▼         ▼             ▼                        └──────────┘
┌────────┐ ┌────────┐  ┌──────────┐
│ 展开态  │ │ 工具    │  │ 养成时间线 │  ← 早期规划的「30 天」和「我们」，
│ 单卡全宽│ │ 下钻    │  │ 变了什么   │     不需要一级入口
└────────┘ └────────┘  └──────────┘
```

**三条推论：**

1. **「30 天」和「我们」不需要一级导航。** 秘书栏底部的「看看我们是怎么熟起来的」（稿里已画）就是入口 —— 关系本来就是随时间长出来的，时间视图和关系视图是同一个东西。
2. **工具页不该有一级入口，它是卡片的下钻目标。** 用户永远从「今天的某个具体东西」进入待办，不是从导航栏进入待办模块。
3. **设置不出现在桌面上。** 走应用头右侧（现在放 `LOCAL CORE · SECRETARY ON DUTY` 那个位置）。

## 3. 主界面：桌面

去掉两个注释层后，设计稿剩下五个区：

```text
┌─────────────────────────────────────────────────────────┐
│  ◇ 维度  PERSONAL REALITY OS        状态指示 · 设置入口   │  A 应用头
├──────────┬──────────────────────────────────────────────┤
│          │  HOME / TEMPORARY CONTEXT                    │
│  秘书栏   │  今天，我们先一起把这件事做成    [为什么][调整]  │  C 标题区
│    B     ├──────────────────────────────────────────────┤
│          │  ┌─────────────┬──────────────────┐          │
│  立绘     │  │  资讯 (5)    │  今日日程 (7)     │          │
│  状态徽章 │  ├───────┬─────┴───┬──────────────┤          │  D 卡片网格
│  人格文案 │  │复盘规划4│ 节奏(4) │  弹性格 (4)   │          │
│  养成参数 │  └───────┴─────────┴──────────────┘          │
│  回顾入口 ├──────────────────────────────────────────────┤
│          │  说点什么，或者让秘书改动这张桌面…  ⌘K  [↗]    │  E 对话条
└──────────┴──────────────────────────────────────────────┘
```

### 3.1 A — 应用头（48px）

- 左：◇ 菱形描边 logo + 「维度」+ `PERSONAL REALITY OS`（等宽 9px）
- 右：状态指示 `LOCAL CORE · SECRETARY ON DUTY`（**接真实状态**，本地内核是否在跑、秘书是否在岗）+ 设置入口
- 下边框 1px

### 3.2 B — 秘书栏（固定 176px，不可折叠）

| 元素 | 规格 |
|---|---|
| 小标签 | `YOUR SECRETARY`，等宽 9px（**不预设秘书专名**，见总纲 §1.3） |
| 立绘框 | 撑满宽度，比例 1:1.12，圆角 2px，内嵌虚线圆环 |
| 状态徽章 | 压在立绘左下，黄绿底 `#c6d830`，格式 `THINKING / 在想` |
| 人格文案 | 13px / 600，两行以内 |
| 补充说明 | 11px，次级墨，三行以内 |
| 阶段行 | 左「我们走到哪里了？」+ 右阶段标签——挂在具体参数上、默认显示**阶段名**（如「默契 · 合拍」）；裸数值仅内部使用，设计稿的「74」为占位示意 |
| 阶段进度条 | 高 3px，橄榄绿 |
| 三条参数 | **熟悉 / 默契 / 权能**（总纲 §5.5；「关系」不做数值，设计稿的第四条「节奏」已退役）。标签 + 3px 细条；色序 橄榄 / 蓝 / 暗红 |
| 底部按钮 | 「看看我们是怎么熟起来的」→ **通往养成时间线** |

三个状态徽章：`READY / 在岗`、`THINKING / 在想`、`PRESENTING / 有事说`（中文取通俗易懂，见总纲 §4.6）。语义沿用 AI Listener 角色状态机：安静陪伴 / 正在形成判断 / 有提案待确认。

**立绘、动作与生长规则（v4.2 定案）**：资源位于 `src/assets/secretary/`。三个运行状态各有三个同身份动作，共九张；状态徽章仍由 UI 独立渲染，不烘焙进图片。角色始终是同一个无年龄化的成年秘书；「长大」指她在固定画框里逐渐站稳、微动更自然、工具更完整，不画成儿童随数值成年。

当前制品状态：`idle / listening / pondering / offering` 四张通过真实 alpha 验收；`organizing / writing / comparing / reminding / acknowledging` 五张为无棋盘格的暖纸底，由固定立绘窗做融合。本文第 8 节明确没有深色模式，因此不阻塞 v4.2；若将角色复用到独立浮层、深色主题或其他背景，需先把五张暖纸底资源重导出为真实 alpha。逐文件状态以 `src/assets/secretary/README.md` 为准。

| 运行状态 | 动作键 | 运行语义 | 默认动作 |
|---|---|---|---|
| `READY / 在岗` | `idle` | 无待处理信号，合上本子安静待机 | 是 |
| `READY / 在岗` | `listening` | 正在接收用户输入或聆听口述 | 否 |
| `READY / 在岗` | `organizing` | 已接收信息，正在归拢但尚未形成判断 | 否 |
| `THINKING / 在想` | `pondering` | 正在形成单一判断或寻找下一步 | 是 |
| `THINKING / 在想` | `writing` | 正在记录、整理或生成可呈现内容 | 否 |
| `THINKING / 在想` | `comparing` | 正在对照两个候选、证据或方案 | 否 |
| `PRESENTING / 有事说` | `offering` | 有一项提案、结果或纸卡待用户查看 | 是 |
| `PRESENTING / 有事说` | `reminding` | 有时间敏感事项或轻提醒待确认 | 否 |
| `PRESENTING / 有事说` | `acknowledging` | 用户刚确认、完成或采纳，给出克制反馈 | 否 |

动作选择必须由**明确的运行语义**驱动，不能按定时器、页面重渲染或随机数轮换。同一运行信号在输入不变时必须得到同一动作；动作键缺失、与状态不匹配或资源不可用时，回退到该状态的默认动作：`READY → idle`、`THINKING → pondering`、`PRESENTING → offering`。

| 参数 | 视觉映射 | 约束 |
|---|---|---|
| **熟悉** | 立绘体量连续从 `0.76` 生长到 `1.04`，虚线圆环同步舒展 | 内部值驱动，UI 仍只显示阶段名；不得突然跳档 |
| **默契** | 呼吸 / 轻摆等微动幅度从约 `0.45px` 增至 `1.8px` | 只增加自然度，不负责选择动作，不变成活泼打扰；遵守 `prefers-reduced-motion` |
| **权能** | 以 0—3 个工具页签表示已显式授予的能力层级 | 不改变人物年龄或亲密感；只能随真实授权变化，绝不自动升级 |

运行状态、动作与生长状态**正交**：运行状态限定动作集合，运行语义选择具体动作，养成参数只调整该动作的呈现。三条参数不得平均成一个「关系总分」来驱动立绘。

### 3.3 C — 标题区

- 面包屑：等宽 9.5px。三张稿分别是 `TEMPORARY CONTEXT`、`LEARNING MODE`、`PERSONAL PATTERN 07` —— **它标注的是「这张桌面此刻按什么逻辑组织」，不是路径**
- 主标题 22px / 600，副标题 12px
- 右上：`为什么这样排?` → 解释层；`调整桌面` → 卡片生命周期管理

### 3.4 D — 卡片网格

12 栅格，间距 12px。骨架固定：上排 `7 + 5`，下排 `4 + 4 + 4`。

五个格子承载**四象限**（v3.1；映射为纸面推导，dogfood 周后定稿）：

| 格子 | 区 | 内容 |
|---|---|---|
| 上排 `5`（左，**首位**） | 资讯（认知发散） | 每日 ≤3 条策展条目，早报心智：开场轻读、摸鱼小关注；每条带「为什么给你看」 |
| 上排 `7`（右，**最大格**） | 日程（行为收束） | 今日 3-5 件时间锚定安排，实验/规划来源带血缘标；每天最高频交互 |
| 下排 `4` | 复盘·规划（合并低频区） | 平时安静：实验状态（进行中 / 待回收）+ 小角落正循环提示（「这周想清楚了 2 件事」）；信息量充足或到周期时**点亮**：回合邀请 / 新规划产出 |
| 下排 `4` | 节奏 | 专注闸门 / 可深度工作时长 / 下班锚点（轮换） |
| 下排 `4` | 弹性格 | 提案卡优先 > 待抉择 / 谁在等你 > 留白 |

注：上排列序由 v3 的 `7 + 5` 调整为 `5 + 7`（栅格总数不变），让资讯占据阅读首位、日程占据最大面积。

**渲染架构（v3.5）**：以上骨架是**种子布局文档的默认值**（layout as data），渲染器解释执行。布局文档分三层，每层都是可编辑对象：

| 层 | 内容 | 种子默认值 | 实验期支持 |
|---|---|---|---|
| 背景 | 画布样式（底色、纹理、密度、主题） | 纸张语言（`--dim-canvas` 等 token） | token 级替换 |
| 卡 | renderer（`native / declarative / html` 三档预留）、尺寸 span、数据绑定、格内配置 | 九种卡片类型，native | 尺寸可调、绑定可换 |
| 排布 | **规则而非坐标**：具名策略 + 参数 | 「占比跟随使用频率」（5+7 / 4+4+4） | 仅此一种策略，参数可调 |

「骨架恒定、单次最多换一个格子」是种子形态的**治理规则**（由生长语法的提案—裁决管理），不是渲染器的能力上限；对话条「让她改动这张桌面」是三层的自然语言编辑入口。「为什么这样排」解释层直接读当前生效的排布策略与参数。HTML 沙箱不进实验期。

**卡片内容会变，格子不变。** 这是「主页变化过度」风险的答案：一次最多换掉一个格子的内容，不重排格子。

### 3.5 E — 对话条（40px）

placeholder：「说点什么，或者让秘书改动这张桌面……」右侧 `⌘K` + 26px 深橄榄发送键。**不出现秘书专名**（总纲 §1.3）。

「让她改动这张桌面」是产品主张：桌面可以用自然语言改，不是只能看。

## 4. 占比跟随使用频率（v3.1）

v2 争论「`7` 放认知卡还是节奏卡」；v3 把复盘放上主位——但这和「认知类内容低频」的结论自相矛盾：把最大的格子留给最低频的内容，主位常态会是留白。v3.1 按**占比跟随使用频率**重排：

- **资讯居首位**（上排左 `5`）：每天的早报，开场轻读，也是摸鱼时的小关注点。轻，但每天都新——桌面的「每日必有新内容」由它开场。
- **日程占最大格**（上排右 `7`）：用户每天最高频查看与操作的内容，桌面日常价值的主体。
- **复盘·规划合并为低频小区**（下排 `4`）：定期或信息量充足（攒够候选、实验出结果）时才点亮回合邀请与新认知卡入口；平时安静显示实验状态。**低频不等于次要**——它是产品主张所在，靠点亮时刻和展开态获得注意力，不靠常驻面积。

产品主张（认知突破）与空间占比解耦：主张由共创回合的对话、小角落的正循环提示和点开后的展开态承载——**认知沉淀不做显眼大卡**（成长是结果与交互间的认可，不是要完成的任务）。血缘（资讯 → 复盘 → 规划 → 日程 → 结果回到复盘）仍是「为什么这样排」解释层的数据来源。

## 5. 卡片系统

所有卡片共享外壳：纸张底 / 1px 边框 / 2px 圆角 / 右上角 `····` 四点 / 顶部等宽英文标签 / 中文标题。部分卡片有类别色条（左缘 3px 或顶边 2px）。

| 类型 | 形态 | 用在哪 |
|---|---|---|
| **cognition** 认知沉淀 | 小角落正循环提示（「这周想清楚了 2 件事」）+ 点开原地展开完整结构（判断 / 证据 / 例外 / 边界，含密度信号） | 复盘·规划区次要位置，**不做大卡**（共创产物） |
| **feed** 资讯卡 | 标题 + 「为什么给你看」+ 来源 + 反馈三键（有新角度 / 已知道 / 没用） | 资讯区，每日 ≤3 条 |
| **anchors** 锚点列表 | ◇ 菱形 + 文字，右对齐时间或状态标（`NOW` / `NEXT` / `16:00` / `2D`） | 日程区、谁在等你 |
| **count** 大数字 | 32px 数字 + 单位 + 说明句 | 待抉择数、待确认数 |
| **note** 便签 | 米黄底 + 左缘竖条 + 重点句 | 专注闸门、习惯提示 |
| **chart** 柱状图 | 青绿柱列，可带下方链接 | 可深度工作时长 |
| **text** 纯文字 | 标题 + 说明，可带链接 | 下班锚点、今晚留白 |
| **proposal** 提案 | 米黄底 + 引述句 + 接受 / 拒绝两键 | 等待回应的建议 |
| **progress** 进度 | 说明 + 进度条 + 左右角标 | 项目脉搏 |

**两条硬约束：**

1. **提案卡是唯一需要用户回应的卡片**，对应总纲 §3.1 的 Proposal / Change Set。必须视觉上明确区别，不能让用户误以为是普通信息卡。
2. **认知沉淀的小角落提示必须带数量**（「2 件事」而非无数字的图标），点开才进展开态；展开态内保留密度信号（支持 3 条 / 反证 2 条）。理由见第 6.1 节。

## 6. 五个下钻层

### 6.1 展开态 —— 原地撑满，不用模态

认知沉淀的完整信息量（判断 + 支持证据 + 反证 + 适用边界 + 不确定性 + 修订历史）不常驻桌面——入口只是复盘·规划格的小角落提示（v3.2）。

**方案：点开后原地展开成全宽，其他卡片下移。**

不用模态的理由：用户正在判断「这条对我成立吗」，需要同时看得见桌面上今天的其他情境。模态会切断这个上下文。

展开态内容顺序：

1. 被挑战的那条判断（原话 + 类型 + 记录时间）
2. 为什么是今天（触发原因）
3. 支持证据 / 反证 **两栏视觉平权**
4. 适用边界
5. 系统的不确定性
6. 替代视角（来源 + 什么时候别用它）
7. 验证动作（耗时 + 可逆性 + 什么算成立）
8. 纠正入口（结构化选项，不是自由文本框）

**入口态与展开态的信息落差是最大的实现风险**，所以小角落提示必须带数量（「2 件事」），让用户预判展开后有多少东西；展开动画从小角落生长出来，而不是整页替换。

### 6.2 养成时间线 —— 「30 天」的落点

从秘书栏底部进入。展示：

- 哪些旧认识被挑战、结果如何
- 哪些行为实验执行了、修订了什么
- 养成三参数（熟悉 / 默契 / 权能）的变化，**每次变化能点开看到具体事件**
- 卡片的出现 / 常驻 / 休眠 / 退出记录

**硬约束**：养成参数变化必须能追溯到具体事件。不能解释的数值增长就是伪养成系统（总纲 §5.5 反伪养成约束）。

### 6.3 工具下钻 —— 现有页面的归宿

Todo / Calendar / Activity / Telos / Connections 全部保留，但**只能从卡片进入**。

- 点日程区条目 → 日程下钻（Todo 与 Calendar 的合并完整视图）
- 点「可深度工作时长」→ 日历
- 点「项目脉搏」→ 目标
- 点复盘·规划区实验 → 实验详情（假设 / 触发 / 结束条件 / 待回收结果）

**硬约束**：下钻视图必须保留来源上下文（面包屑带那张卡的标识），返回时回到桌面的**原滚动位置**，不是顶部。否则桌面作为唯一入口的模型会退化成页面跳转。

### 6.4 想法地图（图谱可视化）

认知—行为图谱的可视化下钻——「看见自己认知结构」是产品主张最直接的展示，也是开源项目的传播亮点。页面名「想法地图」为工作稿（外化语言，不叫图谱）。

**入口**（两个，都是下钻不是一级导航）：养成时间线内「看看你的想法地图」；认知沉淀展开态底部「看它在你想法里的位置」（直接定位到该节点的 ego 视图）。

**三层视图**：

1. **宏观星座**：社区聚类分组（≈生活领域），节点大小 = 枢纽度（牵动多少决策），颜色 = 领域，张力热点标记（用珊瑚色）；力导向布局跑在纸张色板上，无阴影语言不变。
2. **ego 局部**：点击任一节点 → 一跳邻域：这条认知的证据（带强弱）、反证、影响了哪些决策与行动、修订历史链。节点标签一律用户原话。
3. **时间回放**：滑块回到任意日期看当时的结构——新社区出现、枢纽转移、张力消解。**这是成长可见性的杀手镜头**：「结构变了」比「数量涨了」更有说服力。

**硬约束**：generic 节点不显示；高敏领域默认折叠簇（展开需确认）；observation 层永不显示；默认落点是「本周变化了什么」的局部高亮，**不是全图轰炸**。

**防炫技化**：地图必须可行动——点开张力热点或枢纽节点可直接发起「聊聊这个」（进共创流）；纯浏览超过一屏深度仍无行动入口即视为设计失败。供数契约见图谱设计 §8.4。批次：正式版 P1-P2（图谱建成后）；实验期不做界面，但导出包含图谱 JSON，共建者可用外部工具查看。

### 6.5 调整桌面

从标题区右上进入。至少要能：

- 看到每张卡为什么在这里
- 让某张卡走（记录拒绝原因）
- 把某张卡钉住（不参与自动休眠）

## 7. 三个必须设计的边缘状态

这三个是真实产品和 demo 的分界线 —— demo 永远画的是「一切正常且有内容」的状态。

### 7.1 第 0 天

设计稿最早画的是「第 3 天」，那时系统已有内容。真实的第一次打开：系统什么都不知道。

**要求**：不能是空桌子，也不能是引导教程。第 0 天必须有一个**不依赖历史数据也能提供的真实价值** —— 比如从一次 5 分钟对话里就能产出第一张有内容的认知卡。

这是 `First Useful Breakthrough` 指标的起点，也是最容易劝退用户的地方。

**v3 定案**：第 0 天做一次 20 分钟引导对话，第一张认知卡候选、首批日程与资讯挂靠主题都从这次对话产出——与 harness 实验的冷启动协议一致。

### 7.2 留白态

今天确实没有值得重看的判断怎么办？

物理规则写明「沉默、纠正和拒绝同样是有效数据」（总纲 §3.1.1）。那系统就得有一个**体面的「今天没什么要跟你说的」形态**，而不是为了填格子生成一张正确的废话卡。

**这个状态做得好不好，直接决定用户信不信这个产品的判断力。** 一个总在说话的系统等于没有判断力。

要求：它是一个正式的设计交付物，和主状态同等对待，不是 `else` 分支。

### 7.3 授权请求与权能清单

秘书要代做事时怎么问、已授哪些权在哪看、怎么撤。设计稿完全没有，但这是 P4 批次的核心（工程实施计划 §3）。

**硬约束**：权能不能自动升级，只能用户显式授予。每次代办都要有授权来源、输入、输出和撤销路径。

## 11. 风险

**布局映射未经验证。** 类型：产品。触发：第 3.4 节的映射是纸面推导，dogfood 后发现资讯 `5` 格装不下 3 条带理由的条目、日程 `7` 格内容不足显空旷、或复盘·规划 `4` 格点亮时信息挤不下。影响：布局返工。缓解：映射标注为待验证项，dogfood 周结束后定稿；栅格骨架不动，只调区归属与格内密度。

**认知卡的内容供给。** 类型：产品。触发：`7` 格做好了，但每天生成的判断是正确的废话（「你可能在推迟做取舍」这种对任何人任何一天都成立的句子）。影响：管道全绿、指标可算，但产品没价值 —— 而且现有验收门禁发现不了。缓解（v3）：由共创机制与 harness 实验承接——候选经用户裁决后才成卡上桌面，废话进不了主位；供给频率由实验 H1/H2 实测，主位的留白态是常态设计而非失败态。

**留白态被做成 else 分支。** 类型：产品。触发：开发压力下实现成灰色空状态，或干脆总是硬生成一张卡。影响：这是产品可信度的试金石。缓解：当成正式设计交付物，与主状态同等对待。

**格子态与展开态的信息落差。** 类型：实现。触发：格子里一句话，展开后信息量是它的 20 倍，两态之间无过渡。影响：点开有「跳到另一个页面」的断裂感，失去桌面的空间记忆。缓解：格子态必须露密度信号。

**下钻回不来。** 类型：体验。触发：从卡片进入 Todo 完整视图后失去来源线索。影响：唯一入口模型崩塌，退化成页面跳转。缓解：面包屑带来源卡标识，返回回到原滚动位置。

**想法地图炫技化。** 类型：产品。触发：地图做成漂亮但不可行动的 dashboard，用户看一次截图发朋友圈后不再打开。影响：开发投入换不来留存，还挤占核心闭环工期。缓解：6.4 的防炫技约束——默认「本周变化」局部视图、节点可直接发起共创、纯浏览深度限制；上线后跟踪二次打开率。

**纸张色 + 无阴影的可读性。** 类型：体验。触发：低亮度屏或强光下，`#fcf6ea` 与 `#efece0` 对比只有约 3%，层次会糊。影响：看不清卡片边界。缓解：真机多亮度验证，要补对比就加深边框，不加阴影（加阴影破坏设计语言）。

**第 0 天设计不足导致首日流失。** 类型：产品。触发：新用户第一天看到的是引导文案而不是真实价值。影响：`First Useful Breakthrough` 被拉长到「用几天之后」，而那时人已经走了。缓解：第 0 天 20 分钟引导对话产出首批内容（见 7.1 v3 定案）。

## 13. 验收

- 桌面五区与设计稿的对应部分无肉眼差异（顶部分段与底部三栏不实现）。
