> **前端体验命题**：维度把你说过、做过和正在犹豫的事放回同一张会生长的工作面；秘书陪你看清它们为何相连，挑一个小行动去验证，再让结果改变下一次判断。

> **核心心智模型**：一份现实，三种距离，一个秘书，一条闭环。

## 0. 文档职责

本文定义维度前端如何在用户面前成立：

- 用户能看见哪些认识状态，以及如何分辨原始记录、秘书推测和自己的确认；
- 用户如何在行动、推理和演化三种体验中处理同一份现实；
- 秘书如何参与而不替用户下结论；
- 一个线索如何经过裁决、行动和结果，成为可追溯的成长；
- 前端如何落实用户主权、沉默、权限、回滚和数据权利。

本文**不定义**配色、字体、尺寸、具体构图、固定卡位、动效参数、立绘文件、组件 schema、算法和工程排期。这些属于实现与视觉验证，当前制品说明见 [`src/dimension/README.md`](../../src/dimension/README.md)、[`src/assets/secretary/README.md`](../../src/assets/secretary/README.md) 和组件 Stories。

本文中的行动、推理和演化是三种**并列的体验职责**，不是三张固定页面，也不是用户从低到高解锁的成长等级。当前纸面、线索板和星图只是非规范性的视觉探针，不能反过来决定产品信息架构。用户最终采用哪一种表达、怎样组合，仍由真实使用和生长语法决定。

本文所称「桌面」均指维度应用内的工作表面，与操作系统桌面无关。

### 0.1 文档权威边界

| 文档 | 回答什么 |
|---|---|
| 产品总纲 | 维度是什么、不可让渡的物理规则是什么 |
| 认知—行为图谱 | 领域对象、认识状态、血缘和读写权限是什么 |
| 本前端 PRD | 用户看到什么、能做什么、状态如何转换、如何建立信任 |
| 用户旅程 | 这些能力在第 0 天、日、周、月如何发生 |
| 工程与制品说明 | 当前做到哪、如何实现和验收具体表现 |

若本文与总纲或领域设计冲突，以上位文档为准。前端不另造一套产品真相。

## 1. 产品命题

> **上位产品定义**：维度是一个 AI native 产品，以「认知突破 + 行为管理」为理论内核，提供有限的积木和生长语法，让每个用户在日常交互中长出属于自己形态的成长系统。它同时是第二大脑、成长伙伴和可生长的个人 OS。

目标用户面对的不是信息不足，而是三种断裂：

1. 日常信息被记录了，却没有下文；
2. 判断不断形成，却说不清依据，也看不见它怎样变化；
3. 想明白的事没有进入行动，行动结果也没有反过来修正理解。

因此，维度前端不是信息仪表盘，也不是漂亮的任务管理器。它是用户、秘书与系统共同处理现实的工作表面：现实留下的痕迹被保存为带来源的原始记录，值得讨论的部分成为线索，线索被共同塑造成可验证的假设，行动结果再反过来改变认知、行为与产品形态。

前端必须持续帮助用户回答四个问题：

- **现在**：此刻最值得注意或行动的是什么？
- **为什么**：它为什么出现，依据与不确定性是什么？
- **变了什么**：我的理解、行为和产品形态发生了什么变化？
- **然后呢**：这次理解能否变成一个小行动，并由结果检验？

### 1.1 产品不是

- 不是又一个无限信息流；没有合格内容时允许沉默。
- 不是打卡式自律工具；不以连续使用、聊天时长或完成数量制造压力。
- 不是替用户生成一份权威人格画像；系统推测永远不等于用户确认。
- 不是一个滔滔不绝、擅自替用户解释人生的 AI。
- 不是虚拟陪伴或关系养成游戏；伙伴关系服务于认知—行动闭环。
- 不是三套换肤模板；表达方式的变化必须服务于不同的用户问题。
- 不是要求用户从空白开始配置的通用 OS；系统可以提议，用户保有裁决权。

## 2. 用户说了算，秘书来协作，系统守边界

用户提供现实并做最后判断；秘书负责接住、整理和提出可以被推翻的猜想；系统负责保存原始记录、守住权限，让每次变化可追溯。三者并不平权：产品的最终确认权、解释权、授权权和删除权始终属于用户。

### 2.1 角色与权力边界

| 角色 | 负责什么 | 绝不能做什么 |
|---|---|---|
| **用户** | 提供现实、补充语境、裁决假设、确认行动、授予权能、纠正与删除 | 不应被迫维护系统内部结构；不因拒绝或沉默受惩罚 |
| **秘书** | 接住信息、整理线索、提出可证伪的猜想、解释来源、设计小实验、陪同复盘 | 不把推断冒充事实；不直接改写长期认知；不替自己升级权能；不反复追问 |
| **系统** | 保存原始记录、执行状态机、检查权限、维护血缘与变更记录、生成不同投影 | 不把模型信心当作用户确认；不隐藏来源；不把沉默解释为同意 |

秘书是用户可感知的协作角色，系统是保证规则成立的基础设施。两者不能混为一谈：秘书可以说「我有一个猜想」，但只有系统在用户裁决后才允许完成状态转换。

### 2.2 用户必须能分辨的认识来源

前端不向用户暴露内部术语，但必须清楚区分：

| 用户理解 | 前端承诺 |
|---|---|
| **记录显示** | 这是带来源的原始记录，不保证记录中的说法本身已经被证实；能回到时间和语境 |
| **秘书注意到 / 猜测** | 明确表示可能不对，允许纠正或不回应 |
| **你已经确认** | 能看到确认发生在何时、基于什么 |
| **要不要这样做** | 说明影响，接受前不生效 |
| **刚才实际发生了什么** | 留下结果、权限和后续处理记录 |

任何界面都不能用视觉确定感抹平这些差异。

## 3. 五条物理规则与前端不变量

前端不另造一套「物理规则」，而是把总纲的五条底线变成用户能感知、能检查的体验：

1. **一切认知结论可追溯到证据；无证据的推断必须标明是推断。**
2. **写入长期记忆或认知模型必须处于用户授予的可追溯权限内。** 当前 standing grant 允许模型自动写入、修订或撤回，无需逐次确认；前端必须显示模型来源并提供历史与回滚，且模型写入永远不能冒充用户确认。沉默不能产生新的用户权威。
3. **所有形态与内容变化留痕、可回滚。**
4. **拒绝与沉默是有效数据。** 不惩罚，不换一种说法追问超过一次。
5. **用户数据可完整导出、可彻底删除。**

由此派生四条前端不变量：

- **原始记录不等于事实。** 前端始终区分「记录显示」「秘书推测」「用户确认」。
- **关系不能由画面需要生成。** 节点、连线、强弱和因果必须有来源；缺少依据时宁可没有线。
- **权能新增只能来自用户显式授予。** 熟悉和默契不会自动扩大执行权限，用户可随时撤回。
- **可回滚不等于伪造现实。** 领域状态和产品形态可以回滚；已经改变外部世界的动作只能提供事前确认、审计与补偿，不能假装从未发生。

## 4. 一条从现实回到现实的闭环

```text
现实发生 / 用户表达
        ↓
保存原始记录与来源
        ↓
系统观察（大多数不必出场）
        ↓ 满足出场资格
线索：值得一起看一眼的东西
        ↓ 共同澄清
可证伪的假设
        ↓ 用户裁决
拒绝 / 纠正 / 先放着 / 进入验证
                         ↓
                     小行动或实验
                         ↓
                       真实结果
                         ↓
               修正认知、行为或产品形态
                         ↓
                    成为新的现实证据
```

### 4.1 各阶段的体验责任

| 阶段 | 用户看到什么 | 用户可以做什么 | 前端留下什么 |
|---|---|---|---|
| 现实记录 | 原话、日程、完成结果、反馈等 | 查看、补充、纠正、删除 | 来源、时间、隐私等级 |
| 系统观察 | 默认不外显；达到资格才以线索出现 | — | 提取版本、证据血缘、有效期 |
| 线索 | 「我注意到一件事」及其依据 | 查看来源、说不对、补语境、先放着 | 用户回应与后续打扰边界 |
| 假设 | 一个明确、有限、可能被证伪的解释 | 继续澄清、确认成立、修改、拒绝、转成实验 | 支持、反证、边界与不确定性 |
| 行动 / 实验 | 为什么做、做什么、何时停止、什么算结果 | 确认、调整、执行、终止 | 所需权限、行动账本与血缘 |
| 结果 / 复盘 | 证实、限制、证伪或放弃 | 补充感受、修正原判断 | 结果如何更新旧理解 |
| 生长 | 什么变了、为什么变、谁确认的 | 接受、修改、回滚、继续观察 | 前后差异与变化历史 |

不是所有观察都要成为线索，不是所有线索都要变成认知，也不是所有假设都值得实验。拒绝、纠正、搁置、超时和「没有结论」都是合法终点。

接受一个假设也不等于把它确认为永久真理。证据不足时，它只能成为待验证的工作假设。

### 4.2 裁决不能被一个「接受」按钮抹平

| 用户表达 | 合法结果 |
|---|---|
| **有点意思** | 继续共同澄清，仍是未确认线索 |
| **这对我成立** | 有可追溯依据时才进入用户已确认的理解 |
| **要不试试** | 建立小行动或实验；原假设仍可保持未确认，等待结果检验 |
| **不太对** | 记录纠正或拒绝，不静默生成新的偏好判断 |
| **先放着** | 暂存并降低打扰；到期不响应不产生任何确认写入 |

### 4.3 三种生产方式

不是所有内容都由 AI 用同一种方式生成：

| 方式 | 何时使用 | 用户角色 |
|---|---|---|
| **自动** | 低风险、只读、可追溯的整理与提醒 | 扫一眼、反馈或忽略 |
| **提案** | 会改变记忆、计划、产品形态或外部行动的内容 | 接受、拒绝或修改；接受前不生效 |
| **共创** | 认知假设、行为实验与需要用户语境的判断 | 与秘书共同形成，不由系统单方面落结论 |

系统主动到什么程度，由证据充分度、领域敏感度、用户偏好和当次许可共同决定。高敏内容不主动策展；结果回收优先于不断制造新候选；复盘跟随真实事件，而不是变成每日打卡。

## 5. 四类内容职能，而非四块固定区域

维度用四类内容完成认知—行为循环。它们是投影职能，不是永久布局，也不要求每次同时出现。

| 内容职能 | 回答的问题 | 典型内容 |
|---|---|---|
| **换一个角度** | 有没有一个值得我重新看的东西？ | 异质资讯、反例、新材料、开放张力 |
| **把事情做出来** | 今天具体要做什么？ | 日程、承诺、实验动作、待确认执行 |
| **看看结果说明什么** | 刚才发生的事让下一步怎么走？ | 结果回收、复盘邀请、下一步的规划与路径；认知修订自然沉淀 |
| **决定下一步怎么试** | 已经明确的方向还能怎样落地？ | 备选动作、可逆试验、执行方案 |

四类职能的价值来自血缘，而不是数量：新材料进入讨论，讨论形成假设，假设产生行动，行动结果再回到理解。任何值得出场的内容都应能回答「为什么现在给你看」以及「它从哪里来」。

## 6. 三种体验职责

**同一件事，放近看是下一步，摊开看是来龙去脉，拉远看是变化。** 行动、推理和演化读取同一份现实，但回答不同问题；它们可以成为页面、模式或局部下钻，PRD 不预设唯一表现形式。

| 体验职责 | 核心问题 | 关注对象 | 秘书角色 |
|---|---|---|---|
| **行动** | 现在有什么，先做什么？ | 当前事项、承诺、提案、实验和结果待回收 | 编辑与守门人 |
| **推理** | 为什么会这样，依据是什么，哪里还不确定？ | 原始记录、线索、支持、反证、假设、关系与张力 | 共同调查者 |
| **演化** | 什么改变了，为什么改变，现在还成立吗？ | 认知修订、行为结果、产品形态、关系校准与权能历史 | 见证者与回顾伙伴 |

三种职责不是成熟度层级，也不要求用户依次进入。临时切换观察方式不会写入用户模型；如果系统建议改变长期默认表达，必须走生长提案。

### 6.1 行动：把复杂现实收敛成可开始的当下

行动体验优先呈现已确认方向、时间锚点、等待裁决的提案和需要回收的结果。每个行动对象至少说明：它从哪里来、当前处于什么状态、下一步是什么、是否需要授权、完成后怎样回收结果。

行动层只执行已经确认的方向。它可以邀请用户查看原因，但不能在执行流里静默生成新的长期认知结论。

### 6.2 推理：让判断过程可以被检查

推理体验呈现一件事为什么值得注意、有哪些支持和反证、哪些关系已经成立、哪些只是待验证的猜想。「线索」只是达到出场资格的系统观察与原始记录在前端的表达，不另建一套真相源。

每条关系都必须带着起点、终点、关系含义、确认状态和来源。产品不能为了完整或好看自行造边。推理的核心动作是追溯、纠正、补充、裁决和转成小实验；资料不足时直接说「还没聊清楚」。

### 6.3 演化：让成长表现为真实变化

演化体验不是积分页，而是一条可以追问的变化历史：哪条理解被确认、收窄或推翻；哪个行动产生了什么结果；哪种协作方式或产品形态因此改变；谁在何时确认；现在是否仍成立。

认知变化、行为变化和产品形态变化必须各自可追溯，不能被合成一个抽象成长分。演化中的任何事件都能回到原始记录和当时的语境，也能继续发起纠正、回顾或下一次实验。

### 6.4 与正式「想法地图」的边界

正式想法地图是推理与演化的图谱下钻，不是第四种体验职责。它以当前有效理解为中心，同时读取相关的原始证据、反证、决策、行动与修订历史，并明确区分 `user_*` 与 `system_inferred`；模型观察可以显示，但不能被视觉上伪装成用户确认。

地图投影本身不绕过领域写入口。用户直接纠正自己的理解应立即生效并留下修订记录；在 standing grant 下，系统的新解释可经统一 Domain Change Set 自动写入为 `system_inferred`，保留证据、before/after、逆操作和回滚。高敏内容默认折叠，用户确认展开后才显示；支持与反证必须成对取得，节点使用用户能理解的原话。领域供数以图谱设计为准。

### 6.5 当前视觉探针不是产品本体

当前三种预设只用来探索表达可能性：

- **纸面**主要试验行动职责如何收束当下；
- **线索板**主要试验推理职责如何显露来源与关系；
- **星图**目前试验当前事项之间的结构感，属于推理职责的一种表达。只有接入真实历史切片和修订事件后，它才可能承担部分演化职责。

三者可以继续发展，也可以被新的表达替代。当前固定连线和前端合成关系只属于样机，不得被描述为用户的真实认知关系。

## 7. 秘书：一个持续在场的协作角色

秘书不是信息卡的拟人装饰，也不是替用户做判断的全能 Agent。她的稳定职责只有五件事：

1. **接住**：保存用户说过的事和现实发生过的事；
2. **整理**：把相关材料放在一起，不急着得出结论；
3. **共同调查**：提出有限、可纠正、可证伪的猜想；
4. **递交**：把提案、权限请求和行动结果清楚交给用户裁决；
5. **见证**：记住判断、行为和产品形态为何改变。

同一个秘书在三种体验中承担不同侧重：在行动中帮助收束，在推理中陪用户查证，在演化中见证和解释变化。她不能因为表现形式切换就变成三个互相矛盾的人格。

### 7.1 运行状态

秘书的外显状态表达的是她此刻在做什么，而不是为了显得生动随机播放动作：

- **在岗**：安静接收，当前没有需要用户处理的信号；
- **在想**：正在整理材料、比较依据或形成一个候选；
- **有事说**：有一项提案、提醒、结果或确认反馈等待呈现。

同一运行语义必须得到稳定、可解释的表现；缺失时回到该状态的默认表达。动作与资源细节不属于本文。

### 7.2 关系生长

秘书的成长不等于年龄变化，也不由一个「关系总分」代表。三条维度彼此独立：

| 维度 | 真正增长的是什么 | 用户应感受到什么 |
|---|---|---|
| **熟悉** | 对用户确认的信息、语境和边界的持续记忆 | 更少重复解释，引用更准确 |
| **默契** | 对时机、表达和建议方式的校准 | 更少打扰，提议更贴近当下 |
| **权能** | 用户明确交付的行动范围 | 能做的事更多，但边界始终可见可撤 |

角色呈现可以随着熟悉和默契变得更从容、更有表达力，已授权的工具也可以变得可见；这些只是成长反馈，不是成长本身。权能绝不随熟悉或默契自动增加。

秘书默认没有预设专名。称呼、语气和协作距离可以逐渐长出来，但每次有意义的变化都应有现实依据，并允许用户纠正。

---

## 8. 生长：认知、行为与产品形态共同变化

维度中的生长有三种对象：

- **认知生长**：一条理解被确认、收窄、推翻或重新确认；
- **行为生长**：一个试验产生结果，策略因现实反馈而修订；
- **产品形态生长**：默认体验、信息组织、语言人格、工具与规则更适合这个用户。

它们共用同一套生长语法：

```text
有记录的摩擦或用户表达
→ 秘书提出一个变化
→ 说明理由与影响
→ 用户接受、拒绝或修改
→ 生效并留下记录
→ 可回滚或提供补偿
→ 观察后续效果
```

生长的硬约束：

- 不根据模型灵感主动折腾形态；变化必须指回真实摩擦或用户原话。
- 一次只提出一个可理解的变化，不把多个决定打包诱导接受。
- 用户不需要从空白手工配置，但始终可以查看、主动调整、纠正和撤销。
- 语言人格、信息组织和工具彼此独立变化；权能遵循单独的显式授权规则，不能被普通形态回滚恢复。
- 成长由事件和结果证明，不由积分、连续天数或立绘大小代替。

前端应让用户回答：「什么变了、为什么变、谁确认的、现在是否仍成立、能不能撤回？」

---

## 9. 交互与导航原则

维度不以内部数据类型组织一级导航。用户从一个有意义的对象或一句对话进入下一步：

| 用户意图 | 去哪里 |
|---|---|
| 我现在要做什么 | 行动体验 |
| 为什么它会出现 | 推理体验 |
| 我与产品发生了什么变化 | 演化体验 |
| 这些当下事项如何互相牵动 | 推理体验中的关系视角 |
| 这条长期理解在我的结构里是什么位置 | 正式想法地图下钻 |
| 处理具体任务或日程 | 从当前对象进入对应工具 |
| 看自己发生了什么变化 | 变化历史 / 回顾 |
| 让产品换一种组织方式 | 与秘书对话，形成形态提案 |

### 9.1 对象优先

任何可交互对象都应回答：

- 它是什么、现在是什么状态；
- 为什么此刻出现；
- 来源和相关关系在哪里；
- 用户现在能做什么；
- 操作会改变什么、是否需要权限；
- 之后如何查看结果、纠正或撤销。

同一对象跨体验必须保持相同身份、状态、血缘和业务动作。表达可以改变，事实不能改变。

### 9.2 渐进下钻

下钻要保留发起上下文。用户从某条事项进入工具、从某条线索进入证据、从某个节点进入想法地图后，都应能回到原对象和原观察位置，而不是被送到一个无来源的新页面。

### 9.3 对话是通用入口

用户可以随时补充语境、纠正判断、要求解释、发起行动或请求改变产品形态。自然语言降低配置成本，但不能绕过证据、权威归属、统一 Change Set、权限边界和回滚契约。提案或逐次确认是可选授权模式；当前 standing grant 下的安全写入可自动应用并留痕。

跨触点的对话共享同一会话、对象身份和裁决状态；不允许在不同窗口重复追问或产生互相矛盾的结果。

---

## 10. 必须成立的产品状态

边缘状态不是实现末尾的 `else`，而是产品可信度的主体。

| 状态 | 产品应如何成立 |
|---|---|
| **第 0 天** | 不假装了解用户；通过一段具体事件对话给出第一份真实价值，并允许用户立即纠正 |
| **没有合格内容** | 体面留白，不生成正确的废话，不用空洞鼓励填满界面 |
| **证据不足** | 允许只有材料、没有关系；明确还没聊清楚 |
| **证据冲突** | 支持与反证同时出现，不替用户提前收束 |
| **用户拒绝或纠正** | 即时生效，保留修订来源，不换个说法重复追问 |
| **用户沉默** | 到期静默收起，不产生确认写入，不自动授予权限 |
| **实验未开始、中止或无结果** | 如实显示，不包装成成功；允许放弃成为合法结果 |
| **权限缺失或撤回** | 在行动前说明边界；撤回后立即阻止后续执行，历史账本保留 |
| **高敏内容** | 默认不主动策展或推理；用户主动进入后再按权限展开 |
| **数据源离线或投影过期** | 明确显示未知、过期或降级，不把空数据冒充「一切正常」 |
| **原始证据被删除** | 所有体验和导出同步更新；仍有其他支持时更新血缘与证据密度，失去全部支持时才把相关判断标为依据不足 |

## 11. 信任与用户主权

### 11.1 可追溯

可追溯不是让模型现场生成一段听起来合理的解释，而是结构化血缘：任何判断能回到支持与反证，任何行动能回到用户原话或假设，任何变化能回到结果、纠正或形态提案。无来源对象不得以确定口吻进入用户视野。

### 11.2 可逆

前端必须区分三件事：

- **尚未生效的提案**：可拒绝，不产生改变；
- **可回滚的领域或配置变化**：能恢复先前状态并保留历史；
- **已造成外部副作用的行动**：不能伪装成可撤销，只能提供事前确认、行动账本和事后补偿。

### 11.3 沉默与拒绝

拒绝、纠正、忽略和暂停都是有效交互。它们可以降低同类建议的频率，但不能被静默推导为新的长期偏好。产品不通过红点、连续记录或情感压力逼用户回应。

### 11.4 权能与数据权利

维度负责理解与协调，外部 Agent 是执行的「手」。行动能力按用户授权逐步增加：

| 权能 | 产品行为 |
|---|---|
| **只建议** | 告诉用户可以怎样做，不替用户准备或执行 |
| **代我准备** | 起草完整内容或执行上下文，由用户自行发送或使用 |
| **执行前确认** | 系统可以调度，但每次执行前给出清楚确认单 |
| **低风险自动执行** | 只在用户建立的白名单内运行，并持续写入行动账本 |

当前授权范围必须随时可查、可撤。新增或扩大权能必须显式授予；撤权由用户直接发起并立即生效；恢复已撤能力视为一次新的显式授权，不能通过普通「回滚」偷偷恢复。权限保留审计历史，但不承诺像界面配置一样回滚。

导出、删除、纠正和撤权是用户直接拥有的权利，不需要秘书批准，也不应被包装成秘书提案。

### 11.5 隐私与安全边界

- 产品持久化纯本地、无产品遥测，也不建立保存用户内容的自有业务服务端。
- 云模型、外部 IM 或执行工具只作为用户显式选择后的数据出端例外；前端必须在数据离开设备前说明接收方、用途和范围。
- 录音、电脑使用轨迹等高敏感知默认关闭，显式开启，可单独撤销并彻底删除。
- 产品不做临床诊断，也不承诺读心；识别到持续情绪危机时明确能力边界，并建议寻求真人或专业帮助。

## 12. 语言与沟通原则

- 内部可以使用 Evidence、Observation、Claim、Proposal 等精确术语，界面一律使用日常语言。
- 先说发生了什么，再说秘书怎样理解；推测使用有限、可纠正的表达。
- 解释要能指向来源，不用长篇人格化话术掩盖证据不足。
- 用户说「不对」时先接受纠正，不辩护模型为什么会这样想。
- 没有信息增量时少说；安静陪伴是正式能力。
- 不把关系、成长或认知成熟度做成竞争性分数。
- 默认语气中性、通俗、不装；朋友、秘书或教练式距离可以经用户表达和提案逐渐形成。

---

## 13. 一份现实，跨体验不变

行动、推理和演化不是三份数据，而是同一份现实的三种处理方式。用户在任一处做出的纠正、裁决或行动都会回到共同历史，成为下一次理解的依据。

- 换一种体验只改变看法，不改变事实。
- 同一件事无论出现在哪里，都保留相同来源、状态和可做的事。
- 临时查看不会偷偷修改用户偏好；长期默认变化必须先征得用户同意。
- 关系、重要性和确认状态不能为表现效果随机变化。
- 数据未知、权限不足或内容过期时如实说明，不硬编码在线、已连接或已理解。
- 在同样的信息和用户选择下，产品可以换一种表达，但不能换一种事实含义。

### 13.1 非规范性的当前实现说明

当前纸面、线索板和星图共用演示内容，属于**视觉与交互探针**，不是行动、推理和演化三种体验已经完成。现有固定连线和前端合成关系不能视为真实认知关系。

从探针升级为产品能力，必须先有真实对象身份、关系含义、来源、认识状态、生命周期和权限状态。接入之前，界面明确标注演示数据，不能声称已理解用户现实或连接真实图谱。

## 14. 成功如何判断

维度开始成立的时刻，不是用户觉得界面漂亮，而是他说：「我原来没这样想过，但我愿意试一下。」几天后，尝试产生的结果真的改变了秘书下一次给出的判断。

前端成功不以「做了多少页面」判断，而看以下结果是否发生：

| 目标 | 应观察的信号 |
|---|---|
| **第一次有用的突破** | 新用户能从一段真实经历得到一个具体、可纠正、可行动的反馈 |
| **从理解到行动** | 被用户认可的假设能形成小行动，且行动结果被回收 |
| **从结果到修订** | 结果真正收窄、推翻或强化了旧理解，而不是只完成待办 |
| **可追溯的信任** | 用户能查看来源、反证和修改历史，纠正后全端一致 |
| **克制的打扰** | 无价值内容和重复追问减少；沉默不造成隐性写入 |
| **有意义的形态分化** | 不同用户因真实摩擦长出不同默认体验、语言或工具组合，而非随机换肤 |
| **可控的代理能力** | 用户知道秘书能做什么、为何能做，并能撤回权能 |

具体指标与放弃线由 Harness 实验设计定义，本文不重复数值口径。

## 15. 概念验收

新版前端至少通过以下端到端验收：

1. 同一对象在行动、推理和演化体验中保持同一身份、状态、血缘和动作语义。
2. 三种体验分别清楚回答「现在做什么」「为什么如此」「什么改变了」，而不是同一批内容换皮。
3. 任一重要对象都能回到来源，并说明为什么现在出现。
4. 推理体验同时容纳支持与反证；证据不足时允许没有结论、没有连线。
5. 任何关系视角只展示有真实来源的关系，不把临时信号冒充用户长期认知。
6. 正式想法地图以用户已确认的理解为中心读取证据、反证、决策、行动与修订史；未确认观察不进入，高敏内容再次确认后才展开。
7. 一条用户原话可以经过线索、裁决、小实验、结果，最终收窄或推翻原判断，完整血缘可查。
8. 用户拒绝后系统不换文案重复追问；用户沉默后没有确认写入。
9. 任何长期记忆、认知或默认形态变化都经过可理解的确认，并有历史与回滚路径。
10. 新增或扩大权能必须显式授予；撤权后后续执行立即被阻止，恢复需要重新授权；已经发生的外部动作保留真实审计，不伪装成已撤销。
11. 第 0 天、留白、证据冲突、离线、权限不足和删除后的状态都能独立成立。
12. 秘书状态由运行语义确定，不随机表演；熟悉、默契、权能彼此独立且变化可解释。
13. 界面不泄露内部理论术语，用户仍能分辨现实记录、秘书推测和自己的确认。
14. 核心语义能通过文字和辅助技术理解，不只依赖颜色、位置、形状或动画。
15. 当前仅有演示数据时，产品明确承认边界，不冒充已经接入真实日程、认知图谱或运行时。

这些验收在任何视觉方向下都应成立。视觉可以继续探索，产品概念与用户权力边界不能随皮肤变化。
