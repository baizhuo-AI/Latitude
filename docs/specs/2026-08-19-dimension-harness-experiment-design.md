## 0. 一页结论

这轮讨论从「补 PRD 缺的内容架构文档」出发，经历三次递进，最后落在一个新的产品命题上：

1. **内容架构讨论**：内容是投影不是存储；认知类内容是低频的，留白是正式内容。
2. **共创即形态**：认知卡不是「系统生成、用户消费」，而是「系统提候选、用户裁决、对话补全」——共创回合是产品的核心仪式。
3. **Harness 命题**：维度不是一个固定形态的产品，而是一个 harness——提供理论内核（物理规则）+ 有限积木 + 生长语法 + 种子形态，每个用户在日常交互中长出自己的产品形态。

本文档冻结三个判断、挂起一个命题：

| 结论 | 状态 |
|---|---|
| 桌面内容按**四象限职能**组织：资讯（认知发散）/ 复盘（认知收束）/ 规划（行为发散）/ 日程（行为收束） | 冻结 |
| 内容按「自动 / 提案 / 共创」三档生产方式划分，与四象限正交 | 冻结 |
| 认知类内容低频，留白是正式内容形态；桌面日常价值由资讯与日程象限保底 | 冻结 |
| 认知卡是复盘象限的**产物**，由「提案—裁决—共创」产出，不由系统单方面生成 | 冻结 |
| 核心载体是桌面应用；飞书 bot 降为交互窗口（速记、触达、回合的移动端） | 冻结 |
| Harness 命题（用户长出自己的产品形态） | **已采纳进产品定义**（2026-08-19 拍板，重构计划第 1 节已修订）；H7/H8 仍作为实验验证项，证伪则回退 |
| **外化语言原则**：理论术语止于代码与文档，UI 文案用日常语言（见 2.6） | 冻结 |
| 项目将先作为**开源项目**公开；隐私采取最高标准（纯本地、无遥测） | 冻结 |

五项已全部拍板（第 9 节）。下一步：开源卫生审计与知情同意（1 天）→ 约 3 周建种子产品（桌面 app + 飞书窗口）→ 运营者 dogfood 1 周 → 共建者 2-3 人跑 3-4 周实验 → 按第 4 节假设清单结账，结论回填 P0 契约与内容架构定稿。

## 1. 产品命题（当前版本）

> 维度是一个 AI native 产品：给出理论基础和乐高积木，用户在日常生活工作的交互中，逐渐长出属于自己形态的「产品」。（harness 保留为架构机制词，指四层结构本身）

「每个用户决定自己的产品形态」不等于给用户白板。命题拆成四层：

| 层 | 是什么 | 谁能动 |
|---|---|---|
| **理论内核（物理规则）** | 认知—行为闭环、证据先于结论、候选先于写入、可追溯可撤销 | 谁都不能动。用户长不出「不要证据直接下结论」的形态 |
| **积木（有限原语集）** | 速记、认知卡、行为实验、共创回合、提醒、周摘要、留白规则等，各有输入输出契约 | 产品方定义与扩充；用户选用与组合 |
| **生长语法** | AI 观察使用摩擦与用户表达 → 提出形态变更提案 → 用户裁决 → 配置变化，留痕可回滚 | AI 提案，用户裁决 |
| **种子形态** | 所有人从同一个最小默认配置开始（见第 5 节） | 产品方定义 |

**关键机制**：用户从头到尾不「配置」，是 AI 当园丁。可塑软件几十年的研究结论是不到 10% 的用户会主动配置任何东西——这个设计的新变量是把建筑师内置成 AI，用户只对生长提案点头摇头。

**对称性**：产品形态的生长和认知的生长使用同一套「提案—裁决」语法，底层共用一套 Proposal / Change Set 机制（总纲 §3.1）。搭建自己的反思系统这件事本身就是认知干预——产品形态生长与认知成长不是两件事。

### 1.1 第二大脑的完整回路：感知 → 理解 → 执行

维度是用户的**第二大脑**，回路有三段，缺一段都不成立：

| 段 | 是什么 | 通道 |
|---|---|---|
| **感知（被动优先）** | 现实进入第二大脑不依赖用户勤奋 | 主动最小集：速记、对话、check-in（核心，内建）。被动通道以**插件**形式提供、非必选：录音胶囊（AI Listener 项目提供）+ **电脑使用轨迹**（computer history：前台应用、浏览历史等屏幕活动）——隐私最高敏感级：默认关闭、显式开启、纯本地处理、可随时关闭并彻底删除 |
| **理解** | 认知—行为图谱：记住、连起来、看出模式 | 本文档第 2 节的内容架构 |
| **执行（手的梯子）** | 维度是大脑和秘书，**Claude Code / Codex 等 agent 是手**。维度懂用户的偏好和真实意图，把「你想要什么」翻译成「手能执行的指令」 | 按权能四模式（P4 批次，见工程实施计划 §3）分档，见下表 |

执行的四档梯子（权能显式授予，逐级解锁）：

| 权能档 | 执行形态 | 例子 |
|---|---|---|
| 只建议 | 告诉你怎么跟手说：「你可以这样跟 Codex 描述这个需求……」 | 措辞建议 |
| 代我准备 | 起草完整指令与上下文包（符合你的偏好、说清你的真实意思），你过目后自己发 | 指令代拟 |
| 执行前确认 | 维度直接调度 Claude Code / Codex，dispatch 前给你确认单 | 受控调度 |
| 低风险自动执行 | 白名单任务自动跑，全程进行动账本，事后可查可撤 | 自动代跑 |

实验期范围：「只建议 / 代我准备」作为对话的自然能力存在（零新模块）；「调度」类留到 P4 权能系统之后，本期只写入愿景不实现。

### 1.2 插件模型：积木的扩充机制

**插件是维度的器官**：感知是眼睛和耳朵，通道是嘴巴，执行是手。维度**带感官出生**——出厂自带默认器官（微信嘴巴、速记耳朵），完整体验依赖器官在位；器官可替换、可增强、可关闭，但不是「裸核之外的增值包」。三类器官插件共用同一套授权与行动账本：

| 器官 | 插件类型 | 例子 | 接入契约 |
|---|---|---|---|
| 眼睛和耳朵 | 感知插件（证据源） | 录音胶囊、computer history、速记通道 | 产出 `evidence_items`（带 source 与隐私等级）；高敏感知需显式授权开启 |
| 嘴巴 | 通道插件（对话窗口） | 微信（主）、飞书 bot（备） | channel adapter：共享会话与秘书核心 |
| 手 | 执行插件 | 调度 Claude Code / Codex | 消费权能授权，每次执行写行动账本 |

自由 HTML 模块**不是插件**，是积木层的内部渲染积木（renderer 三档之一）；安全边界为 ModuleManifest + Capability API + 沙箱（工程实施计划 §4）。第三方积木包未来经插件机制分发，复用同一安全边界。核心保持小而稳，器官靠插件长。

## 2. 内容架构结论

### 2.1 内容是投影，不是存储

写模型 = 认知—行为图谱（[图谱设计](2026-08-20-dimension-cognitive-graph-design.md)）；读模型 = 内容投影。桌面卡片、30 天叙事、关系时间线是**同一批领域事实的三个读侧投影**，领域事实只生产一次（CQRS + COPE）。投影只准读领域实体/事件，禁止投影间互读、禁止绕过领域层拼数据。

设计顺序采用**契约夹逼**：给每个内容单元写「内容契约」（payload 结构、来源实体与边、出场资格、生命周期事件），用契约反向验收领域模型——没有消费者的表推迟建，契约需要但缺的字段补进去。

### 2.2 四象限：认知—行为循环的外化（职能维度）

认知—行为是内核；外化到桌面上是四类内容，对应循环的四个相位（双钻模型：认知、行为各一次发散—收束）：

| 象限 | 内容 | 职能 | 频率 | 主生产方式 |
|---|---|---|---|---|
| **资讯**（认知·发散） | 与当前认知张力/实验相关的异质视角、反例、新材料 | 打开认知 | 每日 ≤3 条，宁缺 | 自动（策展） |
| **日程**（行为·收束） | 今日安排：3-5 件时间锚定的日程与待办，标注哪件来自实验/规划（带认知血缘） | 执行 | 每天 | 自动 + 提案 |
| **复盘**（认知·收束） | 轻量 check-in（**事件触发**：大日程/实验完结时顺势问一句，**每周一次兜底**，不做每日打卡）+ **共创流**（候选逐条异步推进：今天回一句「有点意思」、明天补两句证据、攒清楚了才成行动，跨触点续接）+ **深聊模式**（可选的 15 分钟完整对话，攒了多个候选或实验出结果时邀请）。**显性产出是下一步的规划与路径**；认知修订在对话中自然沉淀，不外显为大卡 | 把经历梳理成清晰的规划和道路 | 事件触发 + 每周兜底 | 共创 |
| **规划**（行为·发散） | 行动规划：从认知修订/目标推出候选动作与行为实验设计 | 打开行为选项 | 每周 / 事件驱动 | 提案 + 共创 |

（行序按生活时序：打开认知 → 把今天过掉 → 把经历理清 → 定下一步；不严格，取其顺。）

**血缘链路是四象限的灵魂**：资讯被引用进复盘 → 复盘产出认知修订 → 修订触发规划 → 规划生成日程条目 → 执行结果喂回下次复盘。桌面上每张卡可显示上游（这条日程来自实验 X，实验 X 来自认知修订 Y）——这就是认知—行为图谱的用户可见形态。

**资讯象限的反茧房硬约束**（防止产品变成它要反对的信息流）：

1. 每天 ≤3 条，无合格内容就空着；
2. 每条必须挂靠一个活跃的认知张力、主题或实验，展示「为什么给你看这个」；
3. 异质性优先：与用户既有立场不同的来源/视角加权；
4. 用户反馈（有新角度 / 已知道 / 没用）回灌策展，连续「没用」自动降频。

### 2.3 三档内容生产方式（与四象限正交）

| 档 | 生产方式 | 用户角色 | 典型内容 |
|---|---|---|---|
| 自动 | 系统独立生成，不需确认 | 扫一眼 | 资讯策展、节奏类（闸门、时长、锚点）、日程日常项 |
| 提案 | 系统生成，用户批准/拒绝 | 点头摇头 | 建待办、调触发器、记偏好、**形态变更** |
| 共创 | 共创回合里对话产出 | 共同作者 | 认知卡、行为实验 |

### 2.4 认知类内容是低频的

首个实证数据点：用户本人（拥有全部上下文）自评无法日更「被挑战的判断」。由此冻结：

- **留白是正式内容**，不是空状态兜底。系统「今天没什么可说」发生在回合层。
- 出场资格的可操作标准（Grice 量准则）：判断必须对**这个用户、这个情境**有特异性——换任何人任何一天都成立的句子不配上桌面。
- 桌面日常价值由资讯与日程象限保底（每日必有），复盘按节律，实验低频——四象限结构消解了「认知卡撑不起每日桌面」的矛盾，谁也不用硬造。**PRD 待拍板项 ⓵ 的答案**：主位不再是「认知卡 vs 节奏卡」二选一，而是四象限布局问题，进 PRD 修订。
- **认知卡不显眼（v4）**：成长是结果，是交互间的认可，不是要完成的任务。认知沉淀的外化形态是**对话里的一句轻确认**（「这次想清楚了一件事：……」）和**小角落的正循环提示**（「这周想清楚了 2 件事」），点开才见完整结构（判断/证据/例外/边界）。图谱内部结构不变，变的只是外显姿态。
- **候选的大胆度由四因子共同决定（v5）**：`证据充分度 × 领域敏感度 × 用户偏好 × 当次许可`。证据充分度是基础门槛；**领域敏感度是硬闸**——亲密关系、健康、心理等高敏领域，无论熟悉多深都不主动下判断，最多以最轻的问句触碰或等用户先开口（熟悉三个月不等于可以擅自判断用户的亲密关系）；用户偏好（直说 / 委婉）可设置、可被形态提案调整；当次许可即时生效（用户说「你直说」临时放开，说「这个别碰」立即归零并记住）。熟悉阶段只作为用户偏好的先验之一，不再是唯一门。

### 2.5 外化语言原则（双层语言制）

理论基础保证设计有依据；**外化的一切以用户体验为准**。理论术语（Toulmin、warrant、认知节点、共创回合、裁决、行为实验……）止于代码、schema 和文档，一个都不允许泄漏到 UI 文案。默认语言的基准测试：**通俗易懂**——没读过文档的人能不能秒懂；不过分风格化。**语言人格（朋友/秘书/教练）是可生长的形态维度**，由用户表达与形态提案长出，默认中性通俗。文案评审时逐条读出声。

| 内部术语（代码/文档） | 用户看到的 |
|---|---|
| 认知卡 / 被挑战的判断 | 「你好像一直觉得……」 |
| 支持证据 / 反证 | 「这么想的理由」/「不过也有例外」 |
| warrant（推理链） | 不单独外显，融进「为什么这么说」 |
| 适用边界 | 「什么时候不是这样」 |
| 验证动作 | 「要不试试」 |
| 行为实验 | 「这周试个新做法」 |
| 共创回合 | 「花 10 分钟聊聊最近」 |
| 裁决（有意思/废话/纠正） | 「有点意思 / 不太对 / 先放着」 |
| 留白态 | 「今天没什么特别想说的」 |
| 候选观察 | 「我注意到一件事」 |
| 形态变更提案 | 「要不要把这里改成……」 |

这与 CBT 的实践一致：治疗师从不对来访者说「我们来做认知重构」。专业性属于系统内部，亲切感属于界面。

### 2.6 对领域模型的两个修正输入（进 P0）

- 认知卡结构缺 **warrant**（为什么这些证据支持这个判断的推理链）——用户问「凭什么」时只给证据不够。
- 信念修订需区分 **contraction**（适用边界收窄）与 **revision**（推翻替换），不能都塞进 `superseded` 状态。

## 3. 理论底座

| 架构决定 | 理论 | 落成的具体约束 |
|---|---|---|
| 共创回合 | **协作经验主义**（Beck，CBT 方法论核心） | 结论必须由本人参与得出才会被接受；系统单方面生成认知卡注定失败 |
| 候选以问句呈现 | **苏格拉底式提问 / 引导式发现**（CBT） | 「我注意到 X 与 Y 矛盾，你怎么看」而非「你的信念有盲点」 |
| 认知卡内容结构 | **Toulmin 论证模型** | claim / grounds / warrant / qualifier / rebuttal → 判断 / 证据 / 推理链 / 适用边界 / 反证 |
| 信念修订语义 | **AGM 信念修订** | supersede 而非硬删；contraction 与 revision 是不同操作 |
| 行为实验结构 | **CBT 行为实验** | hypothesis / trigger / success_signal / stop_condition；结果三分类（证实/限制/证伪） |
| 核心飞轮 | **Argyris 双环学习**、Kolb 经验学习圈 | 30 天页显式区分「换了做法」（单环）与「改了看法」（双环） |
| 四象限内容职能 | **双钻模型**（发散—收束 × 认知/行为）、Kolb 四相位 | 资讯=认知发散、复盘=认知收束、规划=行为发散、日程=行为收束；桌面即循环的外化 |
| 资讯象限反茧房 | Pariser 过滤气泡批判、Grice 相关性准则 | 异质性加权 + 必须挂靠认知张力 + 日上限 ≤3 条 |
| 三档生产方式 | **混合主动性交互**（Horvitz） | 不确定性 × 打扰成本决定自动/提案/共创的分档 |
| 内容/数据分离 | **CQRS + 事件投影**、NPR COPE | 领域事实一次生产，多投影消费；禁止读侧双真相源 |
| 桌面稳定与变化 | **Pace layering**（Brand） | 外壳（慢）/ 格子骨架（中）/ 卡片内容（快）分速率变化 |
| 留白与出场门槛 | **Grice 合作原则** | 只在有信息量时发言；特异性作为可判定资格标准 |
| 复盘的触发时机 | **事件边界效应**（episodic memory）、**AAR**（After Action Review）传统 | 复盘邀请挂在事件完结点（大日程/实验收尾），不挂固定日历；每周兜底是下限不是节拍器 |
| 双时态 | **Bitemporal 建模**（Snodgrass） | valid time / recorded time 分离（计划已采用） |
| 用户长出自己的形态 | **Papert 建构主义**、**Alexander 模式语言**、可塑软件研究 | 生成语法而非成品蓝图；建筑师必须内置（AI 园丁），否则重蹈模式语言在建筑界的失败 |
| 布局即数据 | **HyperCard / end-user programming 传统** | 结构可生长是个人 OS 与小组件市场的分界；结构硬编码 + 后挂 HTML = widget 市场天花板，长不成 OS |
| 引擎可换、harness 为产品 | Agent harness 传统 | 记忆、权限、人格、安全边界属于 harness，不属于任何模型（计划已有，升为产品定义） |
| 第二大脑回路 | **Building a Second Brain**（Forte，CODE：Capture-Organize-Distill-Express） | 采集（速记/录音/使用轨迹）→ 图谱（组织）→ 复盘（提炼）→ 执行与表达（调度手）；Express 缺位则第二大脑退化为第二仓库 |
| 大脑—手分工 | Orchestrator-Worker 模式（agent 编排） | 维度持有意图、偏好与权限，Claude Code / Codex 持有执行力；指令翻译质量是大脑的核心能力 |
| 实验方法 | **Wizard of Oz 原型法** | 引擎与配置系统建成前，由人扮演验证体验；跑通的协议即 spec |

使用纪律：理论只用于完整性检查与命名，不强制字段全填——缺 warrant 的卡降级或不出场，而不是硬填。

## 4. 假设清单

每条可证伪，带通过线与放弃线：

| # | 假设 | 指标 | 通过线 | 放弃线（触发后动作） |
|---|---|---|---|---|
| H1 供给 | 从用户 7-14 天真实数据能挖出「我没这么想过」的候选 | 有效候选频率（用户自评 ≥4/5） | ≥1 条/周/人 | <1 条/两周 → 认知卡降为月度内容或先修采集，定位重议 |
| H2 协议 | 共创流（异步候选推进 + 可选深聊）用户愿意持续参与 | 候选闭环率（提出 → 结论：行动/纠正/明确搁置）、闭环中位时长、深聊接受率 | ≥50% 候选 7 天内闭环、每人每周 ≥1 次闭环、坚持 2 周 | 候选大量无响应（>50% 碰都没碰）→ 触点或候选质量问题，回访谈定位；深聊长期 0 接受 → 取消深聊只留异步 |
| H3 转化 | 存活认知卡能变成真实行动 | Cognition-to-Action 率 | ≥50% 的卡产生被执行的验证动作 | <30% → 验证动作设计过重，改轻量承诺 |
| H4 修订 | 行动结果会反过来改认知 | 结果回收率、修订发生数 | ≥50% 动作被回收；每人 ≥1 次修订 | 回收但从不修订 → 双环学习不成立，价值主张重议 |
| H5 证据层 | 纯对话+速记（无录音硬件）足以支撑候选挖掘 | 候选的证据来源分布 | 纯软件数据支撑 H1 达标 | 不够 → Listener 优先级提前 |
| H6 留白 | 「今天没什么可说」增加而非消耗信任 | 留白后次日留存、用户反馈 | 留白不导致停用 | 留白后流失 → 节奏类内容保底，桌面双态坐实 |
| H7 分化 | 不同用户长出有意义差异的形态 | 配置差异可指认，用户能说出为什么 | 3-4 周后成立 | 形态趋同 → harness 命题不成立，做固定形态产品 |
| H8 收敛 | 形态趋稳而非永远折腾 | 每用户形态变更频率 | 频率递减，后两周 ≤1 次/周 | 持续高频变 → 积木粒度或提案节奏要改 |
| H9 资讯 | 挂靠认知张力的异质资讯有真实价值 | 「有新角度」评价率；「又一个信息流」负反馈 | ≥30% 条目获「有新角度」，无信息流化抱怨 | <15% → 资讯象限降为复盘的内部素材，不上桌面 |

H1 是根，H2 是形态，H3/H4 是价值闭环，H5/H6 是架构参数，H7/H8 是 harness 命题本身，H9 是四象限中唯一全新品类的单独验证。

## 5. 种子产品（实验载体）

### 5.1 载体：桌面应用为核心，飞书 bot 为交互窗口

四象限内容需要空间化界面——资讯要浏览、日程要扫视勾选、复盘要看血缘和时间线，纯对话流承载不了「桌面作为循环外化」这个核心主张。分工：

| 载体 | 承担什么 |
|---|---|
| **桌面应用**（核心） | 四象限桌面、共创回合的完整形态、卡片血缘、周回顾。复用现有 Tauri 基座 + `src/dimension/` 视觉与 PRD 卡片骨架 |
| **微信**（主交互窗口，实验期就做） | 移动场景的主入口：速记、check-in（事件/周度）、候选推进与轻量裁决（「有点意思/不太对」在手机上回）。走官方 **iLink Bot API**（`@tencent-weixin/openclaw-weixin`），交互频度预期高于飞书——共建者日常泡在微信里，「回一句」摩擦最低 |
| **飞书 bot**（备用窗口） | 与微信同能力，作为 iLink 不可用时的回退。管道现成（「入站 → 秘书核心 → 回发」） |

代价（相对 bot 方案）：搭建期约 1 周 → 约 3 周；测试者需安装 mac 应用；实验数据散在各测试者本地，回收方式成为新决策点（见第 9 节）。

**对话窗口可插拔（channel adapter）**：应用内对话条与外部 IM 窗口共享同一会话与秘书核心，窗口只是通道插件（见 1.2）。**微信为实验期主窗口**（2026-08-20 拍板）：走官方 **iLink Bot API**（官方包 `@tencent-weixin/openclaw-weixin`：扫码登录、`getUpdates` 长轮询增量拉取、`sendMessage` 等 5 个核心接口，Node ≥ 22，约 300 行可跑通；[参考实现](https://cloud.tencent.com/developer/article/2651968)）。**搭建第 1 周先做 spike**——验证配额、消息类型、稳定性与合规条款；spike 失败即回退飞书为主窗口，channel adapter 保证切换零成本、不阻塞主线。已接：应用内对话、飞书 bot（备用）。企业微信 / 公众号为再备选；非官方协议方案（封号风险）仍不做。新通道接入只新增 adapter，不改会话与秘书核心。

### 5.2 种子配置（四象限 + 两条采集入口）

**渲染架构（v6 冻结）：布局即数据，第一天就是。** 维度的核心差异不是「首页有几张卡」，而是**首页能随用户成长出不同结构**。若底层先按固定 React 页面开发、之后再外挂自由 HTML，终局只会是小组件市场，长不成个人 OS。因此：桌面从第一天起就是**布局文档（layout as data）+ 渲染器**——种子四象限只是布局文档的默认值，不是硬编码 JSX；布局 schema 预留 `renderer: native / declarative / html` 三档。实验期渲染器只做最小版（「区 → 卡」两层结构 + 注册组件表），HTML 沙箱按工程实施计划 §4 的安全边界（CSP、Capability API、资源配额）后续点亮——**架构承诺第一天给足，能力渐进点亮**。「结构自由」与「变化节奏」分层：自由是渲染层能力，骨架恒定是种子形态的治理规则（由生长语法管提案与回滚），两者不冲突。

**布局文档的三层结构（v7）**——每一层都是可编辑对象，编辑一律走生长语法（提案 → 裁决 → 留痕 → 回滚），对话条的「让她改动这张桌面」就是三层的自然语言编辑入口：

| 层 | 内容 | 可编辑什么 | 实验期支持 |
|---|---|---|---|
| **背景** | 画布样式：底色、纹理、密度、（未来）主题 | 背景的样式 | schema 就位；仅内置纸张主题，支持 token 级替换 |
| **卡** | 每张卡的 renderer、尺寸（span）、数据绑定、格内配置 | 卡的大小和内容 | 尺寸可调、绑定可换；renderer 仅 native |
| **排布** | **规则而非坐标**：具名策略 + 参数（如「占比跟随使用频率」「时间轴优先」「单焦点」） | 按什么规则排布——换策略、调参数 | 仅内置「频率定占比」一种策略，参数可调 |

排布存规则不存像素：AI 园丁修改的是「按什么逻辑排」，渲染器把规则解释成具体格子。副产品：「为什么这样排」解释层不需要另行生成——当前生效的策略与参数本身就是答案。

桌面三个固定区承载四象限（种子布局文档的默认值），布局原则是**占比跟随使用频率**（资讯居首位、日程占比最大、复盘与规划合并为低频小区；格子映射见 PRD）：

1. **资讯区（认知发散，首位）**：每天的早报，也是摸鱼时的小关注点。每日 ≤3 条策展条目，每条带「为什么给你看」；反馈三键（有新角度 / 已知道 / 没用）。实验期来源用引擎 web search + 用户自述的信息源。
2. **日程区（行为收束，最大格）**：用户每天最高频查看与操作的内容。今日 3-5 件时间锚定的安排（日程 + 待办），来自实验/规划的条目带血缘标注。复用现有 Todo 与 Calendar 功能裁剪接入。
3. **复盘·规划区（认知收束 + 行为发散，低频小区）**：平时安静显示实验状态（进行中 / 待回收）与推进中的候选；有新候选或实验出结果时**点亮**。共创以**异步流**为主：候选单条出现，用户回一句就算推进（有点意思 / 不太对 / 先放着），可跨天、跨触点（桌面/飞书）续接，攒清楚了才聊成下一步的路（规划条目/小实验，进日程带血缘）；**深聊模式**（15 分钟完整对话）在攒了 ≥2 个推进中候选或实验出结果时邀请一次，是加速器不是唯一入口。没挖到就明说（H6 测试点）。认知沉淀不立大卡：小角落正循环提示 + 点开溯源。

三条采集入口（同一 evidence 流）：app 内随手记 + **微信速记（主）** + 飞书速记（备用回退）。**check-in 不做每日打卡**——默认**每周一次兜底** + **事件触发**：一件大的日程或实验完结时顺势问一句（「那件事办完了？感觉如何」）；实验期「大事」判定规则 = 带血缘条目完成，或用户标星的日程完成。若证据层过薄影响候选挖掘，「提高 check-in 频率」作为**形态提案**让用户自选长出（生长语法的第一个天然用例），不默认强加。被动采集通道——录音胶囊（AI Listener）与电脑使用轨迹（computer history）——以感知插件写入愿景与领域模型（`evidence_items.source` 预留 `recording` / `computer_history`），实验期不做。

数据：简化 schema 六张表（evidence / candidates / cards / actions / outcomes / feed_items），不建图谱全模型。每周日生成「本周回顾」（30 天叙事的最小前身）。

**质量阀门（已按拍板 ③ 调整为纯本地方案）**：候选与资讯在各测试者本地生成，**没有投递前的人工审核**。质量控制改为三层：① 出场资格写成确定性代码（日上限、挂靠检查、字段完整度门槛），不靠 prompt 自觉；② 测试者是共建者，废话候选由他们直接标记——这本身就是 H1 数据，不构成信任事故；③ 运营者拿到每周导出包后做**事后审计**，废话率高的挖掘 prompt 下周迭代。

### 5.3 生长语法（WoZ，不写配置引擎）

- 每用户一份配置文件（节奏、积木开关、称呼偏好），初期人肉改 YAML。
- 用户任何关于产品本身的表达（「别每天问我」「想要个每周复盘」）记录为形态反馈 → 拟提案发给他 → 同意即改配置。
- 铁律：**只响应有记录的用户摩擦或原话，不主动发明形态创意**；每次变更可指回触发它的用户行为（防 H7 假阳性）。
- 备 6-8 块扩充积木清单（晨间意图、决策日志、主题追踪等），用户表达需求时一周内可点亮；点亮也是形态提案。

### 5.4 物理规则清单（不可让渡）

1. 一切认知结论可追溯到证据；无证据的推断必须标注为推断。
2. 写入长期记忆/认知模型前必须经用户确认（确认摩擦的**形式**可经显式授权降低，可追溯性不可）。
3. 所有形态与内容变更留痕、可回滚。
4. 拒绝与沉默是有效数据，不惩罚、不追问超过一次。
5. 用户数据可全量导出、可彻底删除。

用户请求突破 1/2 时，路由到权能授权流程（P4 雏形），而非直接答应或拒绝。

### 5.5 明确不做

**实验期不做 ≠ 不做**（总纲 §6.3：全量愿景分批交付）。本期（种子实验）不做：认知图谱 15 张表（用六表）、养成参数外显、权能后两档、HTML 渲染点亮、配置引擎自动化（人肉 YAML）、深色模式、PRD 完整下钻层级（展开态最简版）。桌面 UI 只做四象限种子布局。以上全部在正式版路线上，批次见总纲 §6.3。

## 6. 实验运行设计

- **人**（已拍板）：运营者本人 + 2-3 名**共建者**，全部 macOS，符合目标画像（有自我提升需求、正处迷茫/过载）。共建者身份意味着：他们知道产品在实验期、会遇到废话候选、他们的标记和吐槽都是共建输入。
- **周期**：搭建约 3 周 → 运营者 dogfood 1 周 → 冷启动 3 天 → 运行 3-4 周。
- **冷启动**：每人第 0 天做 20 分钟引导对话，第一轮候选从这次对话挖（同时验证 PRD「第 0 天」问题的解法）。
- **双环复盘**：内环 = 真实共创回合（产出真实认知卡）；外环 = 每周一次数据复盘 + **共建者访谈**（替代遥测的主观数据源），按第 4 节假设打分，协议修订留痕。
- **数据回收**（已拍板：导出 + 访谈，无遥测）：app 内置一键导出，产出两层包——**指标层**（回合完成率、裁决分布、各象限使用计数，不含内容原文）与**内容层**（速记、卡、候选原文）。共建者导出前可 review 并删减内容层任意条目，每周发给运营者。
- **隐私（最高标准，已拍板）**：一切生成与存储纯本地，各自引擎 key，无遥测、无服务端；候选与卡一对一投递不进群；提供「删除我全部数据」指令；知情同意页公开在仓库里。**通道传输例外需在知情同意中写明**：经微信/飞书收发的消息内容会过 IM 服务商的服务器（这是所有 IM 通道的固有属性），长期存储仍只在本地。
- **开源前提**：项目将先作为开源项目公开。实验代码按「可公开」标准写（无硬编码 key、无个人数据进仓库），但仍是档位 2 原型质量。

## 8. 风险

按「会不会发生 × 多严重」排序：

**1. 分化是运营者演出来的。** 产品｜触发：WoZ 形态提案全由运营者拟，差异是其想象力的投影｜影响：H7 假阳性，拿假分化去建配置引擎｜缓解：5.3 铁律——只响应有记录的用户摩擦，每次变更可指回触发行为。

**2. 无事前阀门导致废话率失控。** 产品｜触发：纯本地生成 + 无人工预审，挖掘 prompt 初期质量差｜影响：共建者被废话淹没，H1 数据噪声大｜缓解：出场资格代码化（字段完整度不够不投递）；dogfood 周先在运营者自己身上调 prompt；共建者标废话是协议内动作；周审计迭代。

**3. 测试者不匹配画像。** 产品｜触发：找的是朋友而非有真实成长需求的人｜影响：H1/H3 假阴性｜缓解：按画像筛，宁缺勿滥。

**4. 用户想长掉物理规则。** 产品｜触发：「别老问我确认，直接记就行」｜影响：答应则信任架构溶解，硬拒则承诺变谎言｜缓解：路由到权能授权（5.4），确认形式可降、可追溯性不可让渡。

**5. 专业术语泄漏进 UI。** 体验｜触发：开发时图省事直接把 schema 字段名/理论词做成界面文案｜影响：用户沟通难受，产品像论文不像伙伴，共建者用不下去｜缓解：2.5 语言对照表进代码评审清单；每个新文案过「朋友说话」基准测试。

**6. 回合仪式坚持不下来。** 产品｜触发：忙碌周连续跳过｜影响：共创档断供｜缓解：跳过本身是 H2 数据；触发放弃线则改机会式。

**7. 隐私事故。** 项目｜触发：速记涉及第三方/职场敏感信息｜影响：信任事故，实验中断｜缓解：第 6 节隐私设计 + 知情同意。

**8. 积木太少撑不起分化。** 产品｜触发：4 块积木无从分化｜影响：H7 假阴性｜缓解：备 6-8 块扩充清单，按需点亮；实验期 H7 只测配置层分化（积木开关/节奏/布局参数），结构层分化（自由模块）留正式版验证。

**8b. 布局引擎过度设计。** 实现｜触发：实验期把最小渲染器做成通用框架（拖拽、嵌套容器、完整 DSL）｜影响：3 周搭建变 8 周，实验节奏崩｜缓解：最小版只支持「区 → 卡」两层 + 注册组件表；HTML 沙箱明确不进实验期；schema 预留字段但不实现。

**9. 资讯象限信息流化。** 产品｜触发：策展质量不稳时用凑数条目填格子，或用户把它当资讯 app 刷｜影响：产品变成自己要反对的东西，H9 失败连带信任受损｜缓解：2.2 的四条硬约束写进代码而非 prompt；日上限与挂靠检查由确定性逻辑执行。

**10. 手动导出无人执行。** 项目｜触发：共建者忙，周导出被拖延遗忘｜影响：外环复盘没数据，假设无法结账｜缓解：导出做成一键 + 周日 bot 提醒；访谈开场第一件事就是收包；连续两周没包视为 H2 参与度信号处理。

**10c. iLink API 新且未经实测。** 实现｜触发：配额限制、消息类型缺失、稳定性或合规条款在接入后才暴露｜影响：主窗口不可用，实验触达受阻｜缓解：搭建第 1 周先 spike（登录/收发/长轮询跑 48 小时）；channel adapter 使飞书回退零成本；spike 结论进周复盘记录。

**10b. 开源仓库泄漏个人数据。** 项目｜触发：`pipeline/audio` 真实录音、`pipeline/out` 转写、密钥或测试者数据在开源时进了公开仓库｜影响：不可逆隐私事故，直接违背项目最高原则｜缓解：步 0 的开源卫生审计为硬门禁——个人数据目录分仓或彻底 ignore，公开前跑一次全库扫描（含 git 历史）。

**11. 原型数据迁不进正式产品。** 实现｜触发：六张简化表与 P1 图谱对不上｜影响：测试者积累作废｜缓解：接受作废（发现轨数据即实验材料），卡保留 markdown 导出，人工可迁。

## 附录 A：认知卡完整模板（Toulmin 结构）

```markdown
## 认知卡 ·（日期）

**被挑战的判断**：用户目前相信/默认的一条原话（从真实言行反推）
**为什么是今天**：触发它的近期数据
**支持证据**：历史里支持这条判断的 1-3 件具体事
**反证**：历史里与它矛盾的 1-3 件具体事
**推理依据（warrant）**：为什么反证足以动摇这条判断
**适用边界**：这条判断在什么情境下仍然成立
**替代视角**：还可以怎么理解（标来源：个人历史 / 外部信息 / 换框架）
**验证动作**：≤30 分钟、可逆、结果可观察
**自评**：「没这么想过」还是「正确的废话」（1-5 分）
```

字段允许缺失：缺 warrant 或反证的卡降级展示或不出场，不硬填。

起笔技巧：先找「重复出现的行为模式」或「说了要做但没做的事」，再问「什么信念在支撑这个模式」。

## 附录 B：共创流协议（异步状态机）

候选是最小推进单元，任一触点（桌面 / 飞书）都可以推进一步，跨天续接：

```text
proposed（我注意到一件事……）
   │ 用户回一句
   ├─→ touched（有点意思 / 不太对，其实是…… / 先放着）
   │        │ 继续补证据、聊边界（可跨多天多触点）
   │        ├─→ shaping → concluded（形成：一条认知沉淀 + 一个进日程的行动；
   │        │                        或一次被记录的纠正）
   │        └─→ parked（先放着；不追问，到期自动收起）
   └─（3 天无响应）→ 静默收起（不算失败，算触达数据）

超时规则：shaping 7 天无进展 → 轻问一次「要不要先放着」，之后不再问。
结果回收：验证动作到期时作为独立轻触点单独问一句（或并入最近一次 check-in），
不等深聊才回收。
```

**深聊模式（可选加速器）**：攒了 ≥2 个 shaping 候选或实验出结果时，邀请一次 ≤15 分钟完整对话，一口气推进多个候选；被拒绝或忽略照常走异步流。深聊不是闭环的唯一入口。

记录字段：候选状态流转（含每步触点与时间）、裁决结果、闭环时长、深聊接受率（对应 H2 与默契的原始形态）。
