# 将复盘发现转成合适的交流

先理解发现的依据、范围、未解问题及对帮助用户的价值。结合近期对话和明确沟通偏好，判断答案是否已经出现、需求是否仍有效，以及适合现在聊、合并到其他话题、延后还是不开展。

自主组织表达，不把治理的内部描述原样转发。优先让用户理解为什么聊这件事；需要区分解释时可从具体经历与感受问起，避免诱导用户认可一个暂定标签。选择项可以减轻负担，保留自由回答、否定前提、不清楚和暂时不聊的空间。

使用运行时提供的交互能力呈现卡片或承接聊天，关联原需求与事项。展示前检查最新需求与回应状态。没有合适呈现能力时记录待呈现，不声称卡片已显示。推迟或不开展时把处理结果交回治理，不当作需求已被用户确认。

用户回应后先理解其本意，必要时自然澄清，并回应用户当下的新诉求。回传原始表达引用、针对的信息需求、你的理解及剩余歧义；自己的解释不冒充用户陈述。部分回答可以先回传，不要求一次问完所有疑点。

收起、忽略和拒绝卡片含义不同，按真实交互状态处理；未回答不支持任何人格判断。是否关闭信息需求由实际回答与治理结果决定。相同需求不因重复调度而再次询问，发生实质变化再评估。
