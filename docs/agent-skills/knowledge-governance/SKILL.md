# 完成一项知识治理工作

目标是让值得保留的新信息进入正确位置，让已有误解和过时状态得到修订，并确认实际结果。使用运行时已提供的查询、来源读取、知识变更和任务回执能力；没有写入能力时只能交付待提交产物，不能声称已入库。

## 处理一个事项

读取工作项中的触发原因、事项身份、输入版本和上次进度。根据新材料辨明主体、作者与时间；核对是否属于已有事项、在线是否已处理相同增量。已有节点可以复用，身份不能仅凭词义相似合并。

比较已有认识与本次变化。背景缺失、检索无进展或存在解释分歧时，可读 [检索调查方法](../knowledge-investigation/SKILL.md) 调整路径；需要理解动机、认知、归因或变化时，可读 [认知—行为方法](../cognition-behavior-analysis/SKILL.md)。不要求每次加载两份方法；当次明确表达的目标和预期可直接结构化。

围绕后续用途选择变更：新增、补依据、合并重复、收窄范围、修订替换、保留并存解释、调整事项状态，或不变。保持用户的原意；当次知识与跨情境认识分开。少见的重要选择也可保留，不以次数替代价值判断。

形成一份可提交的增量：目标身份和预期版本、节点与关系的变化、对应来源、适用范围，以及必要的依赖更新。系统推测保持推测身份，不把分析报告、方法资料或自己的概括当作新的独立个人证据。决定去旅行与授权订票、改日程分别处理。

通过统一知识写入能力提交，核对回执中的实际身份、版本和变更结果。版本冲突时读新版本重新比较；提交结果未知时先查原请求回执，不换新身份盲目重提。沿用既有授权，不默认增加逐条人工确认。

处理有关依赖：提交时标记需要复查的认识、概况或索引，后续按受影响范围继续。不要为补写一个事实重算整份画像；也不要让尚未复查的旧推断无标记地继续使用。

## 结束与承接

完成记录区分实际已提交、不变、待补材料与未完成。只登记真正检查过的输入版本；同批未读部分仍保留待办。缺口无法解决时写明缺什么、什么新材料或状态变化值得重看；无新增材料就不重复调查同一缺口。

工具失败、提交结果未知和预算暂停属于可恢复进度，不是“没有知识可写”。分别保留失败位置、原请求身份及已知回执。后台正常完成安静记录；重要变化或关键缺口是否向用户呈现，由既有通知策略和实际帮助价值决定。

复盘需要用户信息时，通过运行时交互委托能力向主 Agent 提供发现、来源、疑点、所需信息、询问价值和有关事项版本。主 Agent 自主判断沟通方式和时机；治理不直接挂卡片，也不要求对方照读拟好的问句。可先提交有依据的部分，将未解需求记为待补，结束本次执行等待回应事件。

回应到达后，读取用户原话与主 Agent 的解释，分别判断；关联原需求继续修订。忽略、收起或拒绝卡片不等于认可判断；已经通过其他对话得到答案时，通知主 Agent 更新或关闭冗余需求，避免重复询问。

普通在线分析得到的候选也可进入同一变更协议；已经提交的结果只需复用回执，后台不重复写一份。skill 提供处理方法，唤醒、队列、持久化与重试由运行机制承接。
